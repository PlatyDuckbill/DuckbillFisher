# 설정 백업·전용 WAV 개발본

2026-10-24. 공개0.5.3.0 뒤 개발본이며 공개 ZIP/태그/설치 JSON은 변경하지 않았다. 현재 동작/형식 계약은 [설정 백업](../../product/SETTINGS-BACKUP.md)을 따른다.

## 구현과 검사

- 기본 설정만 백업하는 사용자 선택을 반영했다. WAV는 전용 영구 복사본과 ZIP 동봉을 기본으로 하며, JSON만 내보내는 선택도 제공한다. 용도별 영어 고정 파일명을 사용해 재지정 때 영구 파일이 늘어나지 않는다.
- CommonSettingsBackup은 공통 설정만 명시적으로 복사한다. 일반 설정 로딩의 정규화는 PreferencesNormalization으로 옮겨 가져오기와 공유한다. 기존 순수 PreferencesMigration과 테스트 소스 링크는 유지했다.
- SettingsBackupFile은 형식/설정 버전·필수 필드/값·크기·ZIP 엔트리·WAV SHA-256을 검사한다. 관리 작업자에서 전부 읽고 검증한 다음 사용자 확인을 받아 Framework 설정 큐로 적용한다. 캐릭터 데이터/발송 기록은 내보내거나 덮어쓰지 않는다.
- ManagedSoundLibrary는 용도별 최대1개 요청과 취소/이전 파일 복구를 관리한다. 기존 외부 경로를 이전하고 같은 고정 경로를 다시 썼을 때 재생기를 강제로 갱신한다. 백업 내보내기/복원 중에는 음원 가져오기를 멈추고 종료 시 작업을 정리한다.
- 별도 `.cache/settings-backup-build/` → 정규 Debug 직접 빌드 모두 경고0/오류0. 설치된 wasdcxz15.0.3.9 참조를 사용했으며 SDK/의존성/lock·네이티브 계약은 변경하지 않았다.
- 한영933키/형식 인자·문서110개/로컬 링크544개·diff 검사 통과. 테스트는 요청되지 않아 추가/실행하지 않았다. 에이전트는 실제 백업 생성/복원·음원 재생·인게임 로드·패키징·원격 게시를 실행하지 않았다. 사용자의 ZIP 포함 보고는 하단에 구분한다. 빌드 성공은 아래 실기 확인을 대신하지 않는다.

## 인게임 대표 확인 대기

로드할 DLL은 `DUCKBILL_ROOT/src/DuckbillFisher.Plugin/bin/Debug/DuckbillFisher.dll`이며 이 PC의 루트는 [HANDOFF](../../SESSION-HANDOFF.md#환경과-경로)를 따른다.

1. 현재 ‘커스텀 WAV’인 기존 외부 경로로 로드하면 원본이 있는 용도만 `sounds/spawn-alert.wav`, `bite.wav`, `big-fish.wav`, `legendary-fish.wav`로 이전되어야 한다. ‘없음’/SE의 예전 경로와 없는 원본의 경로는 유지되어야 한다.
2. 같은 용도에 서로 다른 짧은 WAV를 두 번 선택한다. 전용 파일은 용도별1개만 남고 두 번째 내용이 미리 듣기에서 나와야 한다. 사용자 원본을 옮긴 뒤 재로드해도 전용 복사본이 재생되어야 한다. 원본을 수정했다면 다시 선택해서 반영한다.
3. 설정 → 설정 백업에서 기본 ZIP을 내보낸다. `settings.json`과 현재 ‘커스텀 WAV’를 선택한 용도의 영어 WAV만 포함되어야 한다. ‘없음’/SE의 과거 경로는 내보낸 설정 사본에서만 비워지고 기존 설정/음원은 보존되어야 한다. 같은 파일명을 다시 고르면 실패 안내가 나오고 기존 백업이 유지되어야 한다. WAV 포함을 끄면 JSON 하나만 생성되어야 한다.
4. 즐겨찾기·UI/필터·프리셋·알림·타이머 설정을 바꾼 다음 백업을 가져온다. 미리 보기만으로는 설정이 바뀌지 않고 취소도 보존되어야 한다. 복원 확인 후 원래 설정과 소리가 돌아오며 캐릭터 수집·기록·발송 기록은 유지되어야 한다.
5. ZIP 복원은 원본/기존 경로가 없는 환경에서도 전용 경로로 연결되어야 한다. JSON만 복원한 경우 외부 WAV는 따로 지정해야 함을 확인한다. 한영 전환·좁은 폭·언로드/재로드 후 설정 유지를 확인한다.

## 별도 미확인

- 이전 버전에서 만든 실제 백업 → 이후 버전의 새 선택 필드 기본값/설정 변환, 미래 형식 거절. 최초 백업 구현이므로 과거 배포판에서 만든 같은 형식의 파일은 아직 없다.
- 손상/누락 WAV·해시 불일치·중복/임의 ZIP 경로·크기/시간 초과·지원 인코딩, 권한/디스크/설정 저장 실패와 파일 되돌리기 실패.
- 가져오기/복원 중 로그아웃·캐릭터 전환·긴 IO·종료, 다른 PC와 전 용도/설정 조합. 사용자 설정/원본을 손상시키는 장애 실험은 실행하지 않았다.

기존 공개판·구조/네이티브/글로벌의 확인 대기는 [STATUS](../../STATUS.md)대로 유지한다.

## SE 선택에 남은 WAV의 잘못된 포함 수정

2026-10-24 사용자 보고: 커스텀 WAV를 지정하지 않은 출현 알림의 파일이 ZIP에 포함되며 길이가0초로 보였다. 필요한 소리 필드와 해당 WAV만 읽기 전용으로 확인한 결과 현재 출현 알림은 SE.1이고 예전 `spawn-alert.wav` 경로가 남아 있었다. 파일은35,324바이트·PCM16/모노44,100Hz이며 오디오35,280바이트/88,200바이트초로 실제 길이0.4초다. 빈 음원이라고 확정하지 않는다.

- 원인은 경로가 비어 있지 않다는 조건만으로 WAV를 동봉/자동 이전한 것이다. 현재 ‘커스텀 WAV’ 선택 여부를 공통 판정으로 사용하도록 수정했다. 내보내는 사본만 비활성 용도의 경로를 비우며 기존 사용자 설정/파일은 변경하거나 삭제하지 않았다.
- 읽기 형식은 바꾸지 않아 이전 형식1 ZIP에 비활성 용도의 WAV가 포함된 경우에도 계속 가져올 수 있다. 이번 변경의 새 ZIP 생성과 인게임 대표 확인은 대기이며 테스트는 추가/실행하지 않았다.
- 수정본도 별도→정규 Debug 경고0/오류0, 한영933키·문서110개/로컬 링크544개 검사 통과. 재확인은 현재 SE.1 상태에서 새 ZIP에 `spawn-alert.wav`가 빠지고, 커스텀 WAV 선택 시에만 포함되는지를 우선한다.
