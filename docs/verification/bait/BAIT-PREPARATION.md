# 미끼 준비 · 0.3.0.0 개발 확인

기록: 2026-10-18. 사용자 요청은 미끼 준비·찾기 구현과 이번 배포까지다. 수량/v3 복사/기본 찾기 확인 뒤 후속 피드백을 반영했고, 사용자 ‘Release 확인 완료’로0.3.0.0 추출본의 준비/찾기 대표 확인을 받았다. 동일 ZIP으로Release/저장소 게시와 익명 다운로드 검증을 완료했다. 아래 각 구현 당시의 대기 기록은 이력이며 모든 테마/캐릭터/친구 새 기능 확인을 뜻하지 않는다. [최종 산출물/실제 확인/게시](../releases/RELEASE-0.3.0.0.md).

## 0.3.0.0 · 명시적 미끼 찾기 후보

### 후속 피드백 · 준비 목록 단순화와 강조 가시성

- 사용자 피드백으로 준비 화면의 ‘다음 중 하나로 대체 가능’ 문장과 그 아래 반복되는 대체 미끼 목록을 제거했다. 더 이상 쓰지 않는 대체 집계 모델/생성 코드도 제거했다. 첫 미끼별 대상 집계/수량/링크/없는 미끼 필터/미확인 목록과 상세 미끼 선택지는 유지한다.
- 집계 바로 아래에 ‘같은 어종이 여러 미끼에 포함될 수 있습니다.’를 한 번 표시한다. 영어는‘The same fish may appear under multiple baits.’다. 한 어종을 다른 미끼별로 준비할 수 있다는 의미이며, 같은 미끼 행을 중복 생성한다는 뜻이 아니다. 전체 대상 수는 기존대로 어종 기준이다.
- 찾기 테두리는 기본 배율에서 대비 선4→7px/주 선2→4px로 강화하고 바깥에2.4초 주기로 alpha0.25~0.65/간격2~3px의 강조선을 더했다. 주 선은 고정해 효과 중에도 사라지지 않는다. 페이지 표식도 대비 반지름3.5→5px/주 반지름2.3→3.5px와 강조 링으로 키웠다. 테마 글자 색상/흑백 대비와 UI 배율 반영을 유지한다. 애니메이션은 단조 시계로 계산하며 게임 자료 재조회/쓰기/입력 처리를 추가하지 않는다.
- 현재/최저/친구 참조와 정규 Debug 빌드 각각 경고0/오류0, 한영606키/형식 인자 검사 통과. 테스트 추가·실행 없음. 준비 화면 단순화/두꺼운 테두리와 페이지 표식의 가독성은 인게임 확인 대기이며 이전 페이지 구현도 아직 대표 확인으로 올리지 않는다. Release/배포는 계속 대기다.

### 페이지 번호 표식 · 정확한 KR 자료와 테마 색상

- 사용자가 페이지 번호 강조 작업 계속 진행을 요청했다. 다른 페이지의 번호 오른쪽 위에 작은 표식을 표시하고 ‘N페이지로 이동’으로 안내한다. 직접 이동하면 번호 표식 대신 대상 미끼 테두리로 이어진다. 기존 선택 페이지/장착 미끼 체크를 변경하거나 페이지 이동/선택 함수를 호출하지 않는다.
- 설치된 KR `ffxiv_dx11.exe` 빌드2026.10.06.0000.0000, SHA256 `DB9824EFAC6D5370AB64B02353E882931DDA447E160EE1A5D9E5DCBA43695728`, image base `0x140000000`을 디스크에서 PEReader/Iced로 조사했다. 로컬 주소는 이 파일의 정적 근거이며 런타임 주소로 사용하지 않는다. 개발 도구는`.cache/bait-page-inspect/`에만 두었고 제품 의존성/게임 함수 호출을 추가하지 않았다.
- AgentModule 생성자`0x14048C0E0`에서 Agent119 등록`0x14048D81B`→AgentBait 생성자`0x140F26D40`를 확인했다. 자료 생성`0x140F27440`의`0x140F27658..67D`는 root AtkValues[6]에 미끼당5개 값(Item ID/수량/사용 가능/이름/아이콘)을 채운다. 제품은 첫 Item ID만 읽고 문자열 포인터/Agent의 내부 필드는 읽지 않는다. 기존 숫자 자료index2의13은 페이지 수가 아니므로 사용하지 않는다.
- `FishingBait` 문자열/가상 함수 연결로 찾은 addon refresh`0x141460310`는`0x14146033E..37F`에서 벡터 길이를5로 나눈다. `0x14146038C..39B`에서25칸으로 페이지 수를 계산하고`0x1414604B6..4D0`에서 현재 페이지×125개 값/25개 항목으로 접근한다. setup`0x14145FF20`의`0x14145FFD6..FFF8`은 번호 노드6~14를 순서대로,`0x141460048..060`은 미끼 노드17+slot을 등록한다. pager`0x141113A20`의`0x141113ACF..B08`은 번호 인자index+1을 준다. 이 KR 경로를 확인한 뒤에만 slot→페이지를 연결했다.
- `NativeBaitPageReader`는 기존 정확한 KR 호환성 가드와 Framework 호출 안에서만 빌려온 포인터를 읽는다. 번호9개/타입1010,8개 AtkValues와index6 벡터, 정렬/범위/5개 단위 길이/최대225개를 확인한다. 모든 Item ID의 미끼 범주/중복 없음, 현재 페이지 선택, 현재 보이는 모든 미끼의 Item ID와 전체 배열의 해당25칸을 대조한다. 실패 시 페이지 표식을 생략하고 기존 미끼 찾기/다른 기능을 막지 않는다. 숨긴 이전 페이지 칸은 매칭에서 제외한다.9페이지를 넘는 예상 밖 형태도 표식만 생략한다.
- 테마는 게임이 이미 적용한 선택 페이지의`ButtonTextNode.TextColor`를 우선 사용한다. 없으면 미끼 구역 글자15/45번 색상, 마지막으로 중립 흰색을 사용한다. 밝기에 따라 흑/백 외곽선을 덧그려 대비를 확보하고 현재 UI 배율을 반영한다. `AtkUIColorHolder.ActiveColorThemeType`은 진단으로만 복사한다. GetColor/테마 변경/게임 노드 쓰기 없이 managed 좌표/색상만 게시하며150ms보다 오래된 표본은 그리지 않는다.
- MIT 고정 [FFXIVClientStructs revision](https://github.com/aers/FFXIVClientStructs/tree/5ecda407c82597890b41f704e087381fc7dfb912)의`AtkUIColorHolder`와 GUI 구조를 참조했다. 외부 구현을 복제하지 않았다. 기본 UI6종/기존 추가16종 대조에 이어 StdVector/RadioButton/Button/TextNode/UIColorHolder/ByteColor 포함23종 전체 인스턴스 필드/크기와5개 managed getter/5개 AtkValueType 상수가 현재/최저/친구 DLL에서 같았다. `.cache/bait-preparation/page-layouts.json`, `.cache/bait-page-inspect/page-methods.json`에 대조 결과를 보관한다. 바이트코드 대조가 실제 KR 페이지 동작/테마 가독성의 실기 확인은 아니다.
- 조사 도구의 첫 컴파일은 Decoder 이름 충돌로 실패해 Iced 형식을 명시했다. 제품의 첫 컴파일은 nuint/int 연산3곳에서 실패해 row byte 크기를 명시적 nuint로 수정했다. 최종 현재/최저/친구 참조 및 정규 Debug 빌드 모두 경고0/오류0, 한영606키/형식 인자 검사 통과. 테스트 추가·실행/Release 패키지·게시 없음.
- 진단은`bait-ui/v7`이다. `Pages=` 한 줄에 State/Check/Entries/Current/Target/Total/Compared/Theme/AccentSource/Marker/PageRect를 고정 영문 필드/불변 숫자로 출력한다. 주소/문자열/캐릭터 ID를 출력하지 않는다. 이전 v6 표본을 새 페이지 로직 성공으로 해석하지 않는다.
- 별도 현재 참조/정규 Plugin·Core·ko·manifest 해시4/4 일치, Plugin/manifest0.3.0.0/API15를 확인했다. git diff 공백 검사와 변경 파일의 비의도 문자 검사도 통과했다. 정규 DLL 교체 완료를 인게임 확인으로 확대하지 않는다.
- 실제 확인 순서: 정규0.3.0.0 재로드→아직 장착하지 않은 다른 페이지의 보유 미끼 찾기→번호 표식→직접 해당 페이지 이동→대상 미끼 테두리→선택/닫기 해제. 다른 게임 테마에서도 색/외곽선과 기존 선택 표시가 구분되는지 확인한다. 실패 시 찾기를 요청한 뒤 자료 수집한v7의`Pages=` 한 줄만 받는다. 독립 준비 화면·대체 미끼/미확인 목록도 확인 대기다. 이후 최저 참조 Release/패키지/추출본 확인을 거쳐 승인된 배포를 진행한다.

### 준비 목록의 대체 미끼와 미확인 어종 표시

- 사용자 피드백에 따라 의미 없는 ‘대체 후보’ 표지를 제거했다. Framework 집계 때 어종별 첫 미끼의 실제 선택 집합을 정규화하고, 같은 집합의 대상만 묶는다. 각 미끼 아래에 적용 어종 수와 실제 대체 미끼의 아이콘/이름/소지 수량/아이템 링크를 보이며 마우스 오버로 해당 어종 이름을 확인한다. 표시용 대체 관계를 전체 대상 어종에 합쳐 적용하지 않는다. 렌더링 중 전체 어종/자료 검색은 추가하지 않았다.
- 상단 문구는 ‘미확인 어종 N종’으로 바꿨다. 해당 대상이 있으면 같은 준비 목록 맨 아래 ‘미확인’ 구역에 개수와 이름순 목록을 접지 않고 표시한다.0종이면 하단 구역은 없다. ‘없는 미끼만’을 켜도 미확인 대상을0개 소지로 간주하거나 숨기지 않는다. 미확인 대상만 있는 경우 ‘대상 없음’ 안내를 표시하지 않는다.
- 미확인은 기존 집계의 첫 미끼 확인 불가 대상을 그대로 사용한다. 수집 판정/선택 범위/즐겨찾기·현재 쿼리/미끼 데이터·대체 후보 자체를 변경하지 않았다. 빈 미끼와 조회 불가 수량 구분, 미끼 변경/게임 명령/런타임 HTTP 금지도 유지한다.
- 현재/최저/친구 및 정규 Debug 빌드 모두 경고0/오류0, 한영605키/형식 인자 검사 통과. 이번 표시 변경은 인게임 확인 대기다. 테스트 추가·실행/새 Release 게시 없음. 페이지 번호 강조는 계획을 유지하며 정확한 페이지 연결/테마 계약 조사 다음 작업으로 남긴다.

### Kind0 수정본 대표 확인과 다음 UX 논의

- 사용자 ‘정상 동작’으로 Kind0 수정 뒤 기본 미끼 찾기/강조를 대표 확인했다. 닫기/선택/만료/캐릭터 전환/친구 PC/Release ZIP 전체 확인으로 확대하지 않는다.
- 후속 피드백에 따라 질의했고 사용자가 독립 보조 화면을 승인했다. `BaitPreparationWindow`를 WindowSystem에 한 번 등록하고 기존 버튼으로 연다. 밖을 누르거나 메인을 닫아도 유지하고 직접 닫는다. 준비 목록의 찾기 버튼/상태를 제거하고 목록 영역은 보조 화면의 남은 높이를 사용한다. 기존 대상 집계/수량/아이템 링크는 유지한다.
- 페이지 밖 미끼를 UI 식별 실패로 표시하는 것은 부적절하다는 피드백을 받았다. 현재 어댑터는 그리드에 연결된 Item만 읽으며 전체 페이지의 배치/순서를 확인한 상태가 아니다. 화면에 없음과 계약/읽기 실패를 분리해야 한다. 아이콘 순서/가방 순서로 페이지를 추정하지 않는다.
- 현재 보이는 유효 미끼가 있지만 대상이 없거나 대상 노드가 숨겨진 경우 `NotOnPage`/`WaitingForPage`로 정상 대기한다. 한영 안내는 해당 미끼가 있는 페이지로 이동하도록 표현하며 페이지 이동 뒤 계속 관찰한다. 유효 자료가 없거나 중복/형태/좌표가 잘못된 경우와 구분한다. v6 진단의 필드는 유지하며 상태 코드가 추가됐다.
- 사용자는 페이지 번호에도 표식을 주는 방향에 동의했다. 제공된 게임 미끼 UI 사진은1/2 번호와 기본 선택/장착 표시를 보여 준다. KR ULD에서6~14번1010 페이지 버튼 후보를 확인했고 FishingBaitParameter 시트는291행/유효 Item286개였다. 실측25개 Item의 Parameter ID는 연속하지 않아 RowId/25 또는 아이콘/가방 순서로 페이지를 추정하지 않는다. 현재 정확한 전체 페이지 연결 계약은 미확인이다.
- 사용자 추가 요구로 여러 게임 테마를 고려한다. 고정 금색 점이라는 제안은 수정한다. 현재 테마 리소스 사용 가능성·전환 갱신·명암/형태 구분을 확인한 뒤 기본 페이지/장착 표시를 보존하는 방향으로 구현한다. 현재 고정 색 테두리를 테마 대응 완료로 표현하지 않는다. 페이지 표식/테마 연결/게임 UI 쓰기/페이지 이동은 이번에 추가하지 않았다.
- 현재/최저/친구 및 정규 Debug 빌드 모두 경고0/오류0, 한영603키/형식 인자 검사 통과. 독립 준비 화면/페이지 대기 안내는 실제 확인 대기다. 테스트 추가·실행/원격 게시 없음. 공개0.2.6.0과 이번0.3.0.0 배포 승인을 유지한다.
