# 목록·상세·화면 검증 요약

12개 UI 수정 기록을 [원문 이력](../../archive/ui/CHANGES.md)으로 통합했다. 이 문서는 확인 범위를 찾기 위한 진입점이며 과거의 대기를 일괄 완료로 바꾸지 않는다. 현재 동작은 [UI 설계](../../product/UI-UX-REDESIGN.md), 최신 대표 확인은 [STATUS](../../STATUS.md)를 따른다.

| 주제 | 확인된 사실과 한계 | 원문 |
|---|---|---|
| 아이템 링크·조건 아이콘 | 대표 어종 사용자 확인. 한영 전체 조합은 별도 | [링크/아이콘](../../archive/ui/CHANGES.md#mvp-01-item-links-icons) |
| 목록 요약 | 0.1.13.0 대표 확인. 현재 폭 대응은 이후 변경을 함께 참고 | [초기 요약](../../archive/ui/CHANGES.md#mvp-01-list-summary) |
| 메인/간이/독립 상세 | 구조 합의와 구현. 각 문서의 확인 대기를 전체 통과로 확대하지 않음 | [전면 개편](../../archive/ui/CHANGES.md#mvp-01-ui-ux-redesign), [필터 공유](../../archive/ui/CHANGES.md#mvp-01-ui-feedback) |
| 배치·제목·지도 | 사진 기반 시각적 확인과 개별 상호작용 확인은 구분 | [정렬](../../archive/ui/CHANGES.md#mvp-01-ui-alignment), [정보 정리](../../archive/ui/CHANGES.md#mvp-01-ui-refinement), [헤더](../../archive/ui/CHANGES.md#mvp-01-ui-header-polish) |
| 좁은 폭·정보 밀도 | 사용자 사진 문제/개선 합의·빌드 기록. 모든 크기/언어 조합 실기는 대기 | [사진 개선](../../archive/ui/CHANGES.md#mvp-01-ui-screenshot-polish), [반응형 행](../../archive/ui/CHANGES.md#mvp-01-responsive-rows) |
| 간이 목록 명칭·상단 바로가기 | 0.2.4.0 사용자 ‘확인 완료’ 대표 확인. 모든 화면 조합 아님 | [상단 탐색](../../archive/ui/CHANGES.md#mvp-01-main-navigation) |
| 설정 열기·접는 도구 | 구현/검사 기록. 옛 확인 대기 문구는 당시 상태 | [설정 콜백](../../archive/ui/CHANGES.md#config-ui-callback), [도구 모음](../../archive/ui/CHANGES.md#mvp-01-compact-controls) |

후속 UI 수정은 이 요약에 변경한 동작/확인 범위와 필요한 근거만 갱신한다. 새 화면 구조나 새 게임 접근 계약이 없는 간격/배치 수정마다 파일을 만들지 않는다. 재로드/선택·스크롤 유지·한영/폭·테마 중 변경 영향을 받는 항목을 구체적으로 확인한다.

## 0.3.7.0 변경 없는 데이터의 재사용 (2026-10-19)

성능 후보를 다시 소스 검토하여 계산/저장 정책을 유지하면서 제거할 수 있는 반복 생성만 수정했다. 실제 FPS·할당량·지연 시간을 측정한 결과는 아니다.

| 경로 | 변경 | 보존한 갱신 조건 |
|---|---|---|
| 일반/물고기의 눈 예측 | 값이 같으면 기존 딕셔너리 유지, 첫 차이에서 한 번만 복사. 이전 snapshot은 수정하지 않음 | 매초 기존 판정과 동일한 UTC/경계/재검색. 값 변경 시 ForecastRevision, 표본 시각 ForecastAt은 매번 갱신. 재로드는 빈 맵에서 시작 |
| 설정→목록/타이머 낚시터/미끼 준비 | 메모리 전용 CatalogRevision으로 재계산 조건 분리. 같은 즐겨찾기/수동 상태 집합도 재사용 | 캐릭터·즐겨찾기·수동 상태·목록 설정·UI 언어 변경 반영. 자동 수집·지역·카탈로그·조회 조건은 기존 별도 경로 유지. 알림 예약/채널/SE 변경은 필터 재계산 제외 |
| 알림 즐겨찾기 표시 | 구성/카탈로그 행 변경 시만 이름 정렬. 상태/시간/예측 변경 시 해당 항목과 배열만 복사하며 변화 없으면 기존 목록 유지 | 매초 실제 알림 판정과 모든 표시 상태는 계속 확인. 예정→출현 중·미수집/수집·개별 시간·비활성화·세션 변경 반영 |
| 소지품 | Framework 전용 집계 버퍼 재사용. 수량·상태·세션이 같으면 FrozenDictionary와 snapshot 생성 생략 | 0.5초 샘플링/모든 컨테이너 검증 유지. 실패/이동/로그아웃 때 수량을 숨기고 성공 시 불변 복사본만 게시 |
| 미끼 준비 어종 ID 집합 | 카탈로그 행이 바뀔 때만 생성 | 대상 선택과 미끼/생미끼 구분 기준 유지 |

- 초기 장기 예측/알림 후속 검색의 프레임 집중, 동기 설정 저장, 기록 전체 저장/언로드 대기, 요약 목록 전체 렌더링은 이번에 변경하지 않았다. 계산의 비동기 전환·저장 지연은 오래된 요청 폐기·영속 중복 방지에 미치는 영향과 실제 비용 측정이 더 필요하다.
- 설정 schema11·JSON 데이터·예측 공식·진단 형식은 유지했다. CatalogRevision은 저장하지 않는 내부 메모리 필드다.
- 별도 `.cache/snapshot-reuse-build/`와 정규 Debug 직접 빌드: 경고0/오류0. 한영634키/형식 인자·문서 링크·`git diff --check` 확인. 테스트 추가/실행·인게임·패키징·게시 없음.

인게임 확인 대기:

1. 예측 시작/종료 경계와 물고기의 눈 전환에서 목록 정렬·선택 상세·알림 즐겨찾기 시간이 갱신되는지 확인한다. 초가 줄어드는 표시는 기존처럼 유지되어야 한다.
2. 즐겨찾기/수동 수집/필터를 바꾸면 메인·타이머 낚시터·미끼 준비 대상이 갱신되어야 한다. 한영 전환·로그아웃/재접속 후 이전 캐릭터 상태가 남지 않아야 한다. 다른 캐릭터 실기는 기존 보류다.
3. 미끼 수량 변경 시 다음 정상 샘플에 반영되고, 이동/읽기 불가에서는 예전 수량을 확정값으로 표시하지 않아야 한다.
4. 알림 켜기/끄기·개별 시간·일반 기준 발송·동일 출현 중복 방지는 [0.3.6.0 확인](../alerts/SPAWN-ALERTS.md#0360-알림-예약-결함-수정-2026-10-19)을 함께 따른다.

## 0.3.9.0 업데이트 안내 (2026-10-19)

- 사용자 요청으로 버전별 업데이트 안내와 설정의 다시 열기 버튼을 추가했다. 설치된 버전은 실제 Plugin assembly에서 읽고 본문은 한영 TextKey/리소스를 사용한다. 최근 공개 릴리스5개를 최신순/버전별 접기로 표시하며 중간 개발 버전은 제외한다. 배포 준비에서 후보0.3.9.0 자체 내역을 맨 앞에 추가했다. 고정 후보는0.3.9.0/0.3.8.0/0.3.0.0/0.2.6.0/0.2.5.0이고 최신만 기본 펼침이다. 외부 데이터 요청은 없다.
- schema13의 공통 `LastSeenChangelogVersion`을 기존 Framework 설정 큐/복사/저장 경로에 추가했다. schema1~12를 허용하며 선택 필드가 누락/null/잘못된 버전이면 확인 전으로 정규화한다. 즐겨찾기·캐릭터 기록·WAV 경로는 유지한다. 더 새 버전 확인값은 이전 DLL로 낮추지 않는다.
- 본문 표시 후 닫으면 확인을 요청한다. 접기나 언로드만으로 확인하지 않으며 저장 실패는 기존 메모리/파일을 보존한다. 다시 열기는 언제나 가능하다. 확인 상태 변경은 CatalogRevision을 올리지 않는다. 같은 프레임의 프리셋 삭제가 다른 설정 변경 여부를 지우던 대입도 OR 누적으로 보완했다.
- 별도 `.cache/changelog-build/`→정규 Debug·최소 참조 Release 직접 빌드 경고0/오류0. 한영669키/형식 인자, 생성 manifest0.3.9.0의 Changelog와 csproj 문구 일치를 확인했다. 고정 ZIP7항목·추출/내장 데이터 해시도 확인했다. 테스트 추가/실행 없음. 이후 사용자 대표 확인과 게시 결과는 [Release 기록](../releases/RELEASE-0.3.9.0.md)을 따른다.
- GitHub 공개 Releases API에서 draft/prerelease가 아닌0.3.8.0/0.3.0.0/0.2.6.0/0.2.5.0/0.2.4.0의5개를 확인하고 각 docs/releases 요약을 한영 내장 내역으로 반영했다. 이 조회는 개발 중 확인이며 플러그인 런타임에는 추가하지 않았다. 릴리스 시 이력 갱신 절차는 [DISTRIBUTION](../../development/DISTRIBUTION.md#변경-내역)을 따른다.
- 별개로 공개0.3.8.0 설치 항목의 Changelog만 보완·게시했다. ZIP/태그/버전/다운로드 URL/LastUpdate를 바꾸지 않았고 실제 공유 raw URL HTTP200/문구 일치를 확인했다. [게시 기록](../releases/RELEASE-0.3.8.0.md#설치-화면-변경-내역-보완-2026-10-19).
- 고정0.3.9.0 Release 추출 DLL로 이력5개/접기·펼치기·닫기 후 재로드 생략·설정에서 다시 열기/한영 전환·기존 목록/타이머·설정 복원 대표 확인을 요청했고 사용자에게 ‘이상 없음 배포 진행’ 응답을 받았다. 아래 좁은 폭·장애/다른 캐릭터와 실제 설치 화면 렌더링까지 확인한 것으로 확대하지 않는다.

재현 순서와 남은 범위:

1. 고정 Release 추출 DLL 재로드 시 상단 설치 버전0.3.9.0과 후보 포함 이력5개가 표시되는지 확인한다.0.3.9.0은 펼침, 이전4개는 접힘이며 각각 펼쳐 해당 내역을 읽을 수 있어야 한다. 좁은 폭에서 본문 스크롤과 확인 버튼이 동작해야 한다.
2. 확인 또는 제목의 닫기로 닫고 다음 프레임 이후 재로드하면 자동으로 다시 뜨지 않아야 한다. 설정 → 업데이트 내역은 다시 열어야 한다. 본문을 보지 않고 접어 둔 채 언로드한 경우 다음 로드에서 확인 전 상태를 유지해야 한다.
3. 설정의 한영 전환은 안내 제목/본문/버튼에 반영되며 확인 상태·기존 즐겨찾기·타이머/기록·WAV 설정은 유지되어야 한다. 다른 캐릭터·설정 저장 실패 주입은 별도 확인이다.
4. 기존 저장소 새로고침 후0.3.9.0 설치 항목의 변경 내역이 표시되는지 확인한다. 실제 설치 화면 렌더링/저장소 업데이트 경로는 추출 DLL 대표 확인과 별개로 대기다.
