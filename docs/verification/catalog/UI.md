후속 UI 수정은 이 요약에 변경한 동작/확인 범위와 필요한 근거만 갱신한다. 새 화면 구조나 새 게임 접근 계약이 없는 간격/배치 수정마다 파일을 만들지 않는다. 재로드/선택·스크롤 유지·한영/폭·테마 중 변경 영향을 받는 항목을 구체적으로 확인한다.

## 0.3.11.0 UI 배율 (2026-10-20)

- 설정의 공통 배율 선택80/90/100/110/125/150/175/200%와100% 복원을 추가했다. `UiScale.Draw`는 그리기 시작 때 snapshot을 한 번 읽고 Dalamud의 FontGlobalScale에 배율을 곱하며, 스타일16항목을 push한다. 폰트 캐시 갱신을 위해 현재 폰트를 push하고 WindowSystem을 그린 뒤 finally에서 원래 배율·폰트·스타일을 복원한다. 제목/아이콘 폰트·팝업·툴팁과 최초/최소 크기에 같은 비율을 적용하며, 기존 화면 크기는 수동 조절한다. 게임 좌표를 사용하는 미끼 찾기 overlay는 복원 후 기존 콜백으로 그린다.
- schema14의 `UiScalePercent`는 Framework 큐/복사/저장/snapshot 경로를 사용한다. schema1~13을 허용하고 누락/선택 범위 밖의 값은100%로 정규화한다. 저장 실패는 이전 메모리/파일을 보존하며 배율 변경은 CatalogRevision을 올리지 않는다. 한영 TextKey4개와0.3.11.0 내장 내역을 추가했다.
- `.cache/ui-scale-build/` 별도→정규 Debug와 최소 지원 참조의 `.cache/ui-scale-minimum/` Debug 직접 빌드 경고0/오류0. 한영675키/형식 인자·문서 링크·`git diff --check` 통과. 테스트 추가/실행·인게임·패키징·게시 없음.

인게임 확인 대기:

1. 정규 Debug DLL을 로드하고 설정 → UI 배율을80→100→150→200%로 변경한다. 메인/간이 목록/상세·비교/타이머/낚시터 목록/미끼 준비/업데이트 내역에서 글자·아이콘·버튼·간격과 클릭 영역이 맞아야 한다. 좁은 폭은 화면 크기를 조절하고 팝업·툴팁·스크롤의 잘림을 확인한다.
2. 150%에서 언어를 바꾸고 재로드하면 배율이 유지되어야 한다.100% 복원은 원래 표시로 돌아가고 기존 즐겨찾기/수집/기록/WAV 설정은 유지되어야 한다.
3. Dalamud 기본 배율과 함께 조절해도 다른 플러그인/Dalamud 설정 화면의 글자·간격은 변하지 않아야 한다. 미끼 UI 찾기 표식은 원래 게임 슬롯에 맞아야 한다. 폰트 확대 선명도·다양한 테마/해상도·저장 실패·다른 캐릭터는 미확인이다.

## 0.3.11.0 목록·상세 조작 개선 (2026-10-20)

- 간이 목록에 상단 별 버튼과 옵션의 ‘즐겨찾기만’을 추가했다. CompactViewSettings.FavoritesOnly만 독립 저장하고 CatalogFilter에 이 값만 덮어 전달한다. 메인의 지역/확장팩·수집·등급/시간제 등 나머지 필터와 기존 출현 중/예정 범위는 유지한다. schema15는1~14를 허용하며 처음 이전할 때 당시 메인의 FavoritesOnly를 한 번 복사하고 이후에는 독립이다. 기존 Framework 저장/실패 보존 경로를 사용한다.
- 사용자가 상세 상단 버튼을 선택하고 후속으로 등급·별·수집 상태와 같은 줄을 요청했다. 메인에만 같은 줄의 ‘별도 화면으로 보기’를 노출하며 좁은 폭은 툴팁을 가진 ExternalLinkAlt 아이콘으로 줄인다. 기존 FishDetailWindow.Show의 독립 상세1개를 재사용하며 메인 선택 변경은 따로 연 어종을 바꾸지 않는다. 간이 목록/타이머 등에서 독립 상세를 명시적으로 열면 같은 상세를 갱신하고 비교 상세는 기존 별도1개를 유지한다.
- 낚시터 목록의 수집 상태는 최종 CollectionStatus를 받아 수집됨=녹색·미수집=붉은색·미확인=회색으로 표시한다. 후속 가독성 요청으로 문구에 좌우 여백·불투명 배경·밝은 테두리가 있는 배지를 추가했다. 문자열로 판정하지 않고 수동 우선/자동 관찰의 기존 상태 문구를 유지한다. 출현 중 배경은 예측 표시이며 수집 배지와 별개다.
- 낚시터 미식별 시 어종 보기 버튼에 AllowWhenDisabled 툴팁을 제공한다. 이전 낚시터가 새 시전에 남는 후속 재현과 발견 후 갱신은 [별도 판정/근거](../fishing/TIMER-HISTORY.md#03110-미지의-낚시터와-이전-위치-분리-2026-10-20)를 따른다. 등록 자동 해제 문구는 ‘첫 도감 등록 시 즐겨찾기 해제’로 줄이고 툴팁을 동작 순서로 정리했다. 수집/해제 로직은 유지한다.
- 같은 미게시 개발0.3.11.0 후보에 내역을 합쳤다. `.cache/catalog-options-build/` 별도→정규 Debug 직접 빌드 경고0/오류0, 한영679키/형식 인자 확인. 테스트 추가/실행·인게임·패키징·게시 없음. 이전 UI 배율 확인 대기도 유지한다.
- 후속으로 ‘어종 보기’를 SpotFishWindow.Toggle에 연결해 같은 버튼으로 열고 닫는다. 목록 밖 클릭/상세 열기/타이머 닫기는 기존처럼 목록을 유지한다. 식별 전 버튼 비활성 정책은 유지한다.
- 최신 업데이트 내역은 기능별8개 TextKey/아이콘 항목으로 나누고 설치용 Changelog도 기능별 개행했다. ReleaseNotes.PublishedAtUtc는 nullable UTC 기록이며 한국 시간(+09:00)으로 표시하고 한국어 `yyyy년 M월 d일 H시`/영어 시 단위 날짜 형식을 사용한다. 미게시0.3.11.0은 날짜를 만들지 않고 ‘배포 시각 미기록’으로 표시한다. 재로드/확인 저장 계약은 유지한다.

인게임 확인 대기:

1. 메인과 간이 목록의 즐겨찾기만 보기를 서로 반대로 설정하고 각각 유지되는지 확인한다. 지역/수집/등급/시간제 필터는 공유하며, 즐겨찾기 추가/해제는 다음 목록 갱신(약1초) 때 반영되어야 한다. 재로드 후 간이 목록 선택과 출현 예정 범위가 유지되어야 한다.

4. 낚시터 목록을 전체로 바꿔 수집/미수집/미확인과 수동 지정의 문구·색상을 확인한다. 수집 숨김 전환과 새 등록 갱신은 기존대로 동작해야 한다. 한영·80/100/150/200% 배율·좁은 폭과 폰트/테마별 가독성은 별도 확인이다.
5. 어종 보기를 반복 클릭해 열기→닫기→열기가 되고 목록의 전체/수집 숨김 선택은 유지되는지 확인한다. 설정 → 업데이트 내역에서 최신8개 항목이 별도로 나오고 이전 버전의 배포 날짜는 한국 시간의 시 단위까지 표시되어야 한다. 언어 변경·재로드 후 확인 상태가 유지되어야 한다.

## 0.3.7.0 변경 없는 데이터의 재사용 (2026-10-19)

성능 후보를 다시 소스 검토하여 계산/저장 정책을 유지하면서 제거할 수 있는 반복 생성만 수정했다. 실제 FPS·할당량·지연 시간을 측정한 결과는 아니다.
