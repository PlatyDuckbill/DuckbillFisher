# MVP-01 지역·확장팩 복수 선택

날짜: 2026-10-16 · Plugin 0.1.16.0 · 기능 대표 확인 통과, 선택 UI 보완 필요

## 사용자 선택과 의미

- 사용자는 두 그룹 각각 복수 선택, 확장팩은 낚시터 소속 기준을 선택했다. 지역은 Territory ID의 지도 구역이며 어종 도입 패치/광역 지명으로 분류하지 않는다.
- 같은 그룹 안은 OR, 서로 다른 그룹은 같은 낚시터에서 AND다. 현재 지역만이 켜져 있으면 그 낚시터가 현재 지역에도 있어야 한다. 한 어종의 서로 다른 두 장소를 섞어 조건을 충족시키지 않는다.
- 그룹의 선택 없음/전체는 그 그룹만 해제한다. 기존 검색·수집·시간제·등급·즐겨찾기와 함께 적용하며 다른 선택을 초기화하지 않는다. 모순된 선택은 빈 결과로 남는다.
- 구체적 지역/확장팩 선택은 일반 낚시터가 없는 어종·먼바다를 제외한다. 두 그룹 전체/현재 지역만 해제 상태에서는 기존 먼바다 포함 설정을 따른다. Unknown을 신생으로 변환하지 않는다.
- 지역·확장팩 이름은 클라이언트 시트에서 읽는다. 지역 검색/복수 체크/그룹별 전체 해제와 접었을 때의 선택 요약을 제공한다. 선택은 ID로 유지하며 언어 변경/목록 재조회로 초기화하지 않는다. 영속 저장은 추가하지 않았다.

## 근거와 책임

- 설치된 KR `2026.10.06.0000.0000`에서 TerritoryType.PlaceName/ExVersion→ExVersion.Name을 조회했다. 신생 ExVersion=0은 실제 존재하는 행이다. 확장팩 미확인은 nullable ID다.
- 기존 지도/일반 낚시터 검증을 만족하는 로컬 FishingSpot 307곳은 64개 지역/6개 확장팩에 연결된다. 표시 가능한 일반 어종에 실제 연결되는 선택 후보도 64/6임을 별도 읽기 전용 감사로 확인했다.
- 표본: 림사 상층 128/하층 129는 ExVersion 0, 올드 샬레이안 962는 4다. 후보와 낚시터별 메타데이터는 Framework에서 목록 로드 때 구성한다.
- Core `FishLocationFilter`는 숫자 위치/선택 집합만 받아 동일 장소 판정을 처리한다. Plugin은 시트 접근/옵션 캐시, `FishGeographyPanel`은 UI 선택을 담당한다. Draw는 전체 시트/파일을 읽거나 장기 예측을 하지 않는다.
- 목록 장소도 모든 위치 조건을 만족하는 낚시터를 선택한다. 기존 추천 장소의 조건/예측이 다른 지역 자료이면 문구를 붙여 현재 선택 장소의 예측으로 오해하지 않게 한다.
- 새 이벤트/네이티브 접근/의존성/외부 데이터/런타임 HTTP는 없다. 기존 내장 조건/분류 원본은 바꾸지 않았다.

- 최초 별도 빌드에서 새 패널의 namespace 누락으로 CS0246 5건 발생. namespace를 추가한 뒤 최신 별도 빌드 성공, 경고·오류 0.
- 별도 빌드: `dotnet build src/DuckbillFisher.Plugin/DuckbillFisher.Plugin.csproj --no-restore -c Debug "-p:DalamudLibPath=${env:DALAMUD_HOME}/" "-p:OutputPath=${env:DUCKBILL_ROOT}/.cache/geography-build/"`.
- `pwsh -NoLogo -NoProfile -File scripts/check-localization.ps1`: 한영 240키/형식 인자 일치 확인.
- 사용자 ‘언로드 완료’ 후 OutputPath 인자 없는 정규 Debug 빌드 성공, 경고·오류 0. 주 DLL 908800바이트/0.1.16.0, Core 31744바이트/1.0.0.0, ko 27136바이트/0.1.16.0, manifest DuckbillFisher/0.1.16.0/API 15 확인.
- `git diff --check` 확인. 테스트는 추가/실행하지 않았다. 메뉴 동작/복수 조합·한영 전환·실제 수와 정량 성능은 인게임 미확인이다.
- preferences/v5에 Regions/Expansions/RegionOptions/ExpansionOptions를 추가했다. 빈 ID 목록은 해당 제한 없음, Expansions=0은 신생 선택이다. summary/v4·catalog/v5와 기존 진단 표본 제한은 유지한다.

## 인게임 결과

- 사용자 ‘기능 자체는 이상 없음’과 preferences/v5에서 지역 64/확장팩 6개를 확인했다. Regions=128/Expansions=4/Displayed=0으로 림사 상층과 효월의 충돌 선택이 빈 결과를 유지하는 표본을 확인했다.
- CurrentRegionOnly=False, 수집/등급 전체, 시간제 해제다. 도감 미조회 상태의 자동 수집 0/Unknown은 정상이며 필터 실패로 해석하지 않는다.
- 화면에서 지역 팝업/내부 목록의 이중 스크롤을 확인했다. 사용자 요청은 확장팩 체크박스 직접 표시, 선택한 확장팩에 맞춘 지역 후보, 지역 선택 UI 개선이다. 0.1.17.0에서 후속으로 다룬다.
- 개별 모든 조합/한영 전환을 추가 확인했다고 확대하지 않는다. 이번 결과 기록은 문서만 변경하며 빌드/검사/테스트를 재실행하지 않았다.

## 재현 순서

1. 기존 개발 DLL로 0.1.16.0 로드 후 ‘지역·확장팩 선택’을 펼친다. 다른 필터는 전체/해제, 검색 비우기로 시작한다. 확장팩 여섯 개와 지역 검색/스크롤/복수 체크를 확인한다. 짧은 진단의 후보 수는 RegionOptions=64/ExpansionOptions=6이 기대값이다.
2. 확장팩 신생, 지역 림사 상층을 선택하면 황금나비어(194)가 포함되어야 한다. 확장팩만 효월로 바꾸고 지역 림사 상층을 유지하면 빈 결과여야 한다. 선택이 자동 해제되면 안 된다.
3. 지역에 올드 샬레이안을 추가하면 효월에 속한 해당 지역의 어종이 나와야 한다. 확장팩에 신생도 추가하면 선택한 두 지역을 함께 탐색할 수 있어야 한다. 지역 검색으로 숨겨진 체크도 유지한다.
4. 한 그룹의 전체를 눌러 다른 그룹·등급·수집 선택이 유지되는지 확인한다. 한영 전환/목록 재조회도 ID 선택을 유지해야 한다. 현재 지역만은 이 선택과 함께 적용되므로 현재 위치에 따라 빈 결과가 정상일 수 있다.
5. 짧은 진단 한 개와 화면 이상 여부로 회신한다. 이미 확인한 도감/분류 집계/전체 원본/지도 핀은 반복하지 않는다.
