# 0.6.0.0 터주작 추천 개발본

2026-10-25. [제품 계약/초기 추정/출처](../../product/NEXT-FISH-RECOMMENDATION.md), [현재 낚시터 알림](../alerts/SPAWN-ALERTS.md#현재-낚시터-출현-알림-0600-2026-10-25).

## 변경 범위

- Core의 단계별 준비 계획·시간/날씨 달력·단일 조건 참고 빈도와 Plugin의 작업자/수집 snapshot/추천 탭을 추가했다. 기존 FishingForecast의 직감 예측 계약은 바꾸지 않았다.
- 첫 진입/필터/다시 추천으로 계산하고 읽는 동안 순위를 유지한다. 조회 시각·현재 잔여·지난 회차·새로 수집된 후보를 구분한다. 미확인 수집은 명시 선택 때만 포함하며 준비 미확인/범위 밖 후보의 접근 경로를 남긴다.
- 보관 사용 여부는 검토한 롱카 경로만 바꾼다. 추가 여분1마리의 작업량/시작 참고는 별도이며 점수 가산이 없다. 목표 시전 전에 남는 연쇄와 직감 유효 시간을 계산한다.
- 사용자 승인에 따라 세 탭과 목록·선택 상세의 분할 화면으로 개편했다. 지금 노릴 어종은5분 이내 출발/준비할 후보, 미리 준비는 준비가 필요한 후보, 희귀 어종은30일 출현 횟수 순이다. 후속 요청으로 좁은 폭에서도 목록은 왼쪽/상세는 오른쪽으로 유지하며 준비 막대·단계별 아이콘·빈도 기준을 제공한다. 세 탭의 기간은 공유하고 별도 자동 확장을 하지 않는다.
- schema24는 현재 낚시터 알림 기본ON 및 캐릭터별 출현 알림 회차 종료 기록을 추가한다. 설정 백업은 스위치만 포함하고 발송/회차 기록은 포함하지 않는다. 이전 백업의 누락 스위치는 기본ON이다.

## 자료·소스 검토

- 내장 대표5종의 경로/요구 수량/시간 제한을 읽어 모델 입력과 대조했다. 롱카의 앞2단계와 Priest의 ET10–12, Charibenet의 공유 어획, 칠채천주의3종/분리 시간대, 스테타칸투스의 조각가2마리, 홍룡의 쿠얼 경로를 확인했다.
- 조각가는 내장 BigFish=false이므로 일반 선행 예산을 그대로 적용하지 않고 명시적 계획 여유를 둔다. 조건 ID/시간/마릿수 원본은 수정하지 않았다.
- 다른 선행 어종을 잡기 위한 미끼가 다시 직감 요구에 포함되는 교차 누적(예:52009→52002의43740)은 일반 경로로 확정하지 않고 확인 필요로 남긴다.
- 직감 최종 어획이 선행 구간 종료 직전에 가능하고 버프가 목표 출현까지 이어지는 경우를 허용한다. 준비 기준 경로를 과거에 시작시켜 누적을 이미 채운 것으로 만드는 계산을 제거했다.
- 자체 조건 빈도는 완전한 복합 경로 빈도가 아니다. 시간 예산·순위 품질·모든 어종의 경로를 독립 실측으로 대조하지 않았다.

- 게임 실기·화면 렌더링·성능 측정·패키징/원격 게시 없음. 컴파일/고정 입력 성공을 실제 추천 품질이나 알림 재현 성공으로 확대하지 않는다.
- 개발 DLL: `DUCKBILL_ROOT/src/DuckbillFisher.Plugin/bin/Debug/DuckbillFisher.dll`.

## 알고리즘 회귀 확인

후속 좌우 배치 수정은 UI 조건만 변경했다. 별도/정규 Debug 경고0·오류0, 한영 리소스/문서/diff 검사 통과. 이 수정에서 테스트는 추가/재실행하지 않았으며 아래616개 결과는 앞선 알고리즘 변경의 검사 기록이다. 실제 화면의 좌우 배치 확인은 대기다.

처음7개 입력에서3개 결함을 수정 전에 재현했고 수정 뒤 모두 통과했다. 이후 탭 기준·간격·갱신 검사를 더해13개를 고정했다. 결과는 로컬 `.cache/recommendation-tests/recommendation-before.trx`, `recommendation-repair.trx`, `recommendation-focus.trx`, `recommendation-final.trx`에 있다. 입력은 [FishRecommendationTests](../../../tests/DuckbillFisher.Core.Tests/Forecast/FishRecommendationTests.cs)의 통제된 시간/조건이며 실제 어획 시간 측정이 아니다.

## 게임 대표 확인 대기

1. 메인 → 추천 진입: 기본3시간/미수집/세 탭, 처음8종과 더 보기·추천 제외/확인 필요가 표시된다. 지금 노릴 어종은 현재 행동할 이유가 있는 후보, 미리 준비는 미래 준비도 포함, 희귀 어종은 적은 출현 횟수 순이다. 탭 간 중복은 정상이며 현재 생미끼/직감 수량을 반영하지 않는다.
2. 목록을1분 이상 읽는다: 기준 시각/순위는 유지되고 현재 잔여/갱신 안내만 바뀐다. 다시 추천 또는 필터 변경 후 기준 시각·순위가 갱신된다.
3. 수집 미확인 포함·즐겨찾기만·터주왕만·1/3/6/12/24시간을 변경한다. Unknown이 기본 미수집으로 섞이지 않고 기간 밖 어종이 자동으로 들어오지 않는다.
4. 롱카를 선택한다: 우측(좁으면 하단) 상세의 준비 막대/아이콘에 출현 전 앞2단계와 출현 중 Priest 연쇄가 분리된다. 보관 경로를 선택해 여분 작업·시작 시각을 비교하며 여분으로 점수가 증가하지 않는다. 직감 없는 상시 대상에 가짜 출현 막대를 만들지 않는다.
5. Charibenet·홍룡·칠채천주·스테타칸투스에서 선행 이름/수량/시간대와 최종 시전/직감 잔여를 상세와 대조한다. 특히 준비 늦음과 조건상 불가를 구분한다.
6. 직감 지속 미확인 후보는 순위 보류와 사유가 나타나며 정상 어종처럼175초로 확정하지 않는다. 단계 시간은 설계 추정 안내가 표시된다.
7. 새 수집·출현 종료 후 기존 행은 상태를 표시하고 다시 추천에서 제외/재평가된다. 언어 변경은 순위를 초기화하지 않으며 이름은 클라이언트 시트를 따른다.
8. 계산 중 추천 화면 닫기·필터 연속 변경·로그아웃/캐릭터 변경·재로드에서 오래된 결과가 다시 나타나지 않는다. 기본980px/최소700px·UI 확대·한영/테마·열 너비 변경에서도 좌우 배치를 유지하고 독립 스크롤·툴팁·버튼·긴 이름/시각이 겹치지 않는지 확인한다. 세 하위 탭 전환은 재계산하지 않고 같은 기준 시각을 유지한다.
9. 지도/상세는 클릭한 어종을 열고 일정표 버튼은 기존 일정표로 이동한다. 게임 조작·미끼 변경·이동은 실행하지 않는다.
