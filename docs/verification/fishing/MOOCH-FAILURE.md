# MVP-02 생미끼·실패 기록과 메인 바로가기

2026-10-17 · Plugin0.2.3.0 · 정규0.2.2.0 사용자 표본 기반 수정, 새 언로드 확인 후 정규 반영 완료/인게임 확인 대기.

후속 사용자 결과: ‘나머진 정상 동작’으로 생미끼/실패·빈 어획 아이콘의 대표 확인을 받았다. 모든 실패 유형/보관 생미끼/저장·재로드 조합으로 확대하지 않는다. 같은 사진에서 확인된 상단 줄 배치와 새 이름은 [0.2.4.0 간이 목록/탐색 줄](../../archive/ui/CHANGES.md#mvp-01-main-navigation)에서 다룬다.

## 실제 근거

- 사용자는 생미끼가 ‘어종 미확인’, 실패가 ‘결과 미확인’으로 나오는 점과 실패 행에 미끼 아이콘이 보이는 점을 보고했다. 메인 간략 보기/타이머 버튼의 우측 정렬·기능 식별 개선도 요청했다.
- 0.2.2.0 관찰기 두 표본 모두 KR 계약25/25, 거부/큐 누락/이력 누락0, Territory401/어부18, Read=Ready다. 아래만 대표 확인이며 전체 생미끼·실패 유형이나 새 UI 확인으로 확대하지 않는다.

## 설치 자료와 구현

- 기존 KR 빌드2026.10.06.0000.0000/API15/MVID·SHA 가드를 그대로 사용한다. 새 네이티브 필드/주소/호출/후크/의존성을 추가하지 않았다.
- 무시된 `.cache/casting-audit` 도구를 `dotnet run --no-restore`로 실행해 디스크 KR LogMessage macro를 재확인했다. 테스트나 게임 프로세스 관찰 실행이 아니다. 1121의 lnum1은 생미끼 Item,1118은 놓친 어종,3515는 잃은 미끼이므로 서로 바꾸어 쓰지 않는다.
- [고정 ClientStructs 소스](https://github.com/aers/FFXIVClientStructs/blob/cae2c3755ef02f9f2728082ae8043669ac9fbfe3/FFXIVClientStructs/FFXIV/Client/Game/Event/FishingEventHandler.cs)의 Mooch0x10/Swimbait0x20을 설치 구조·이번 Flags16 표본과 대조했다. 라이선스 MIT. 기존 열거 의미를 확인했으며 외부 구현 복사 없음.
- [고정 공개 로그 소스](https://github.com/goatcorp/Dalamud/blob/896d83190a34e7ff92deef967ba635ebb7dbdbae/Dalamud/Game/Chat/LogMessage.cs)대로 콜백 안에서 숫자만 복사한다. 라이선스 AGPL-3.0, 외부 구현 복사 없음. NoSource/다른 캐릭터는 본인으로 승격하지 않는다.
- 본인1121의 유효 어종 Item을2초 후보로 보관하고 Phase1/12·같은 캐릭터/지역·시전 시작과2초 이내·생미끼 플래그를 함께 확인해 연결한다. 입질/낚아채기 이후에는 보정하지 않고 확정한 생미끼는 덮어쓰지 않는다. 장착 미끼나 마지막 성공 어종을 대체값으로 넣지 않는다.
- 기존100묶음×2000회/schema2를 유지한다. 새 기록은 실제 생미끼 Item을 저장해 이후 장착 미끼 변경의 영향을 받지 않는다. 타이머 상단도 이때 ‘사용 미끼’로 실제 어종을 표시한다. 기존 미확인 기록은 소급 추정하지 않는다.
- KR macro 일치/본인/활성 시전/시전 이후 이벤트/Phase2 또는4를 모두 충족하는1117/1118/1119/1120/1127/1129/3515/3527을 Failed로 끝낸다.1119/1129만 이번 실제 대표 표본이 있으며 나머지 메시지는 정적 계약/구현까지만 확인했다. 일반 시간 초과·출처 없음·시작 미확인은 계속 Unknown이며 취소/중단/성공을 실패로 합치지 않는다.
- FailureLog 종료 코드는 기존 enum 마지막에 추가해 예전 값의 번호를 보존했다. schema2 파일 구조는 그대로다. 새 종료 코드를 모르는 이전 버전으로 내리면 해당 파일을 미지원으로 취급하여 읽기/저장을 막을 수 있다. 기존 파일을 변환하거나 지우지 않는다.
- 타이머/좁은 기록 행은 Caught의 실제 어종만 아이콘으로 그린다. 실패·미확인·취소·진행 행의 어획 자리는 빈 공간으로 두고 미끼 이름은 원래 정보 줄에 유지한다. 묶음 상세 요약에 실패 횟수도 표시한다.
- 메인 바로가기는 탭에 섞인 아이콘 버튼을 제거하고 상단 우측에 목록/초시계 아이콘+현지화된 이름을 함께 둔다. 기존 간략 열기/타이머 토글 동작과 고정 ID를 유지한다. 화면 분리나 탐색 구조는 추가하지 않았다.
- timer/v3 짧은 진단은 MoochLogs/MoochApplied/Failures/LastFailureLog를 추가한다. 원시 로그 전체/이름/캐릭터 ID는 복사하지 않는다. 수집 판정/등록 자동 해제/필터/알림 정책은 유지한다.

## 검사와 다음 확인

- 별도 직접 `dotnet build --no-restore -c Debug`/현재 KR DalamudLibPath: 경고0/오류0. 한영555키/형식 인자 검사 통과. Plugin1,166,848바이트/0.2.3.0, Core56,320바이트/1.0.0.0, ko52,736바이트/0.2.3.0, manifest DuckbillFisher/0.2.3.0/API15 확인. `git diff --check`와 변경 파일의 비의도 문자 검사 통과. 테스트는 추가/실행하지 않았다.
- 구현 커밋 `30d69af` 후 사용자 새 ‘언로드 완료’ 확인을 받아 정규 `dotnet build --no-restore -c Debug`를 실행했다. 경고0/오류0, 한영555키 재검사 통과. 정규 Plugin/Core/ko 크기·버전과 manifest가 위 별도 출력과 일치한다. 이번 언로드 확인은 사용했으며 다음 교체는 새 확인이 필요하다. 실제 재로드/동작은 아직 확인하지 않았다. 푸시/릴리스 없음.
- 재로드 후 생미끼 시전1회에서 실제 어종 이름/아이콘을 확인하고, 미끼를 바꿔도 해당 과거 행은 유지돼야 한다. 입질 없는 종료 또는 낚아채기 실패1회는 ‘실패’이며 어획 아이콘은 비어 있어야 한다. 타이머의 낚아채기 정지는 계속 유지돼야 한다.
- 상단 우측의 글자+아이콘 버튼으로 간략 보기/타이머가 열리는지 확인한다. 다른 실패 유형/보관 생미끼/성공 생미끼·재로드 조합과 이전 기록 관리/상한 확인 대기는 유지한다. 문제 때만 timer/v3 짧은 진단과 행동 설명을 받고 같은 원시 표본을 반복 요청하지 않는다.
