# MVP-02 캐스팅 타이머·공유 히스토리 첫 구현

## 타이머 인내·직감 남은 시간 (2026-10-22)

0.5.1.0 고정 추출 DLL에서 사용자가 최소 잔여/예정 빈칸·인내/직감 표시 확인 요청에 ‘정상’으로 응답했다. [고정 해시와 대표 확인](../releases/RELEASE-0.5.1.0.md)에 연결하며 아래 초기 구현의 실기 대기를 이 대표 범위에서 해소한다. 원시 상태/모든 기술·언어/폭·장애 조합의 전수 확인으로 확대하지 않는다.

- 개발 후보는 기존 타이머 시전 ET 아래에 두 상태 아이콘·이름·남은 분:초를 표시한다. 활성은 청록, 미적용/미확인은 회색이며 좁은 폭에서는 다음 줄로 배치한다. 인내1·2를 남은 시간/Param으로 추측 구분하지 않는다. 현재 효과는 최근 낚시의 과거 표본이 아니다.
- KR 게임2026.10.06.0000.0000의 로컬 Status 시트에서850=월척 확률 증가/icon216023,568=어부의 직감/icon211101을 확인했다. Action4102/4106과 ActionTransient는 인내/인내2·월척 확률 증가/낚아채기 성공률 감소·60/145초를 설명한다. 표시에는 고정60/145초를 쓰지 않고 현재850의 RemainingTime을 사용한다. 851은 정비이며 인내2로 취급하지 않는다. 실제 기술 사용→상태850/568/게임 표시 동시 대조는 실기 대기다.
- 공개 `IObjectTable.LocalPlayer.StatusList`의 `StatusId`/`RemainingTime`만 Framework.Update에서200ms마다 읽는다. 로그인·현재 ContentId·어부·이동 중 여부와 기존 검증 KR 조합 가드를 먼저 확인하고, 게임 객체/StatusList는 콜백 안에서만 사용한다. Draw는 복사한 관리 값·단조 만료 시각만 사용한다. NotObserved/Ready/Unavailable을 구분하고 세션 불일치·1초 넘은 표본은 미확인으로 표시한다. 종료/닫기·전환은 표본을 폐기하며 타이머 기록/예측/수집/알림에는 쓰지 않는다.
- 현재 wasdcxz15.0.3.7, 최소15.0.3.6, dal4kr15.0.3.7의 정확한 MVID/SHA256이 [기존 조합](../native/NATIVE-RUNTIME-DAL4KR.md)과 일치한다. Mono.Cecil로 Status/StatusList/BattleChara 관련 getter·enumerator IL/필드와 ClientStructs.Status 전체 필드를 대조해 동일함을 확인했다. Status 크기16, StatusId0/ushort·Param2/ushort·RemainingTime4/float·SourceObject8이다. 새 직접 포인터/시그니처/오프셋 접근이나 가드 완화는 없다. 상세 결과는 로컬 `.cache/timer-status-api.json`이다.
- 소스 근거는 설치 ProductVersion의 고정 revision [Dalamud f3eeb5e Status](https://github.com/goatcorp/Dalamud/blob/f3eeb5e18bd982d1ae928cbf6dd0653997d3a916/Dalamud/Game/ClientState/Statuses/Status.cs)·[BattleChara](https://github.com/goatcorp/Dalamud/blob/f3eeb5e18bd982d1ae928cbf6dd0653997d3a916/Dalamud/Game/ClientState/Objects/Types/BattleChara.cs)다. AGPL3 참조이며 구현 코드를 복제하지 않았다. 최소/친구의 고정 revision·원본 라이선스/배포 출처는 기존 네이티브 기록을 유지한다.
- 별도 `.cache/timer-filters-build/`→정규 Debug 빌드 경고0/오류0, 한영845키·형식 인자 검사 통과. 테스트는 요청 없어 추가/실행하지 않았다. 공개0.5.0.0 ZIP/원격은 변경하지 않았다. 실제 게임/다른 캐릭터/전체 폭·언어 조합은 미확인이다.

대표 확인: 정규 Debug DLL을 로드하고 `/dbfs ct`를 연 뒤 인내·인내2를 각각 수동 사용한다. 아이콘과 남은 시간이 게임의 월척 확률 증가 효과와 맞고 만료 후 미적용으로 바뀌어야 한다. 직감을 직접 획득해568의 남은 시간을 비교한다. 재적용·해제·타이머 닫기/다시 열기·이동·직업 변경·재로드에서 과거 값이 남지 않는지 확인한다. 최근 낚시를 표시 중이어도 효과는 현재 기준이어야 한다. 한영/좁은 폭에서 두 표시가 겹치지 않아야 한다.

## 판정과 시간

- Core FishingAttempts는 API 없는 단일 작성자 모델이다. 변경 시에만 새 불변 기록 배열을 게시한다. 중복 Phase1 표본으로 새 기록을 생성하지 않는다.
- 새 Phase1 전이를 관찰할 때 캐스팅 하나를 시작하고 장착 미끼를 복사한다. Phase5/6 및 본인1116은 입질/낚아채기의 별도 관찰 경과로 저장한다.
- 본인3512만 단일 성공/Item/수량1로 연결한다. 진행 기록·낚아채기 관찰·결과 단계(2/4)·시각을 함께 확인해 이전 시전의 늦은 결과가 새 던지기/입질 대기에 붙는 것을 막는다. 게임이 제공하는 고유 캐스팅 ID는 없어 지연 사건의 완전한 식별을 보장하지 않는다.
- 본인5584는 진행 기록의 직접 회수다. Phase2는 성공/실패를 구분하지 않는다. Phase4에서 결과 없이2초 지나면 결과 미확인, 새 캐스팅이 먼저 오면 이전 기록은 미확인이다. Fishing=False는 연속 세션을 끝내지 않고 관찰한 Phase0에서 완전히 종료한다.
- 로드/관찰 공백 직후 이미 진행 중인 시전은 기록을 추가하거나 시작 시각을 만들지 않는다. 첫 정상 전이를 본 다음 새 캐스팅부터 기록한다. 이미 낚시 자세였으면 연속 세션 시작은 미확인이다.
- 현재 미끼는 ‘장착 미끼’로 표시한다. 생미끼/보관 생미끼 플래그가 있으면 기록 종류만 구분하고 실제 미끼 Item은 미확인으로 둔다. 장착 미끼를 생미끼 어종으로 저장하지 않는다.
- 실패/복수/소장품/방생 등 미검증 결과는 성공/실패로 추정하지 않는다. 먼바다는 게임 IKDSpot의 낚시터 Territory를 기준으로 아직 기록을 비활성화한다. 작살 결과를 기존 진행 캐스팅 없이 붙이지 않는다.
- UTC는 관찰 시각으로 저장하고 ET 표시와 로컬 표시를 분리한다. 경과는 Stopwatch로만 계산하며 OS 시각 변경으로 길이를 다시 계산하지 않는다. 입질 초 수 통계/예측은 추가하지 않았다.

## 저장·수명·성능

- FishingTracker가 Framework에서 네이티브 표본/검증한 공개 로그를 Core에 전달한다. 공개 로그의 본인 비교는 관찰기와 FishingLogContracts.Actor를 공유한다. 콜백 내에서 값만 복사, 제한64건/최대2초/세션·지역 확인 후 적용. Draw에서 게임 데이터/파일/장기 예측을 읽지 않는다.
- 현재 낚시터 어종/수집 숨김 결과는 데이터·낚시터·수집/수동 revision이 바뀔 때 Framework에서 계산한다. 저장된 Item 이름/아이콘도 최대16개씩 Framework에서 캐시하고 Draw에서는 관리 값만 쓴다.
- FishingHistoryStore는 일반 설정과 분리한 `<plugin config>/fishing-history/<local character key>.json`(schema1), 캐릭터별1000회/최대4MiB다. 이름/대화/포인터를 저장하거나 진단에 캐릭터 키를 내보내지 않는다.
- 단일 저장 작업자가 캐릭터별 최신 snapshot을 병합하고 같은 디렉터리 임시 파일을 flush 후 교체한다. 손상/미지원/읽기 불가 원본은 덮어쓰지 않고 새 기록은 메모리로 유지한다. 쓰기 실패는5초 간격 재시도하며 화면에 표시한다.
- 진행 기록도 저장한다. 정상 언로드는 중단/Reload로 끝내고 저장 작업을 기다린다. 비정상 종료 후 Pending 복원은 중단/Reload이며 소실된 경과를 추측하지 않는다. 로그인/캐릭터 전환 때 기존 표시/활성 기록/큐/낚시터를 비우고 해당 캐릭터 파일만 복원한다.
- 지역 전환/관찰 불가/5초 초과 공백도 미완료 기록을 중단으로 끝내고 기존 전이를 재생하지 않는다. 서비스/관찰기 이벤트는 Dispose에서 해제한다.
- 기존 도감 판정/수동 우선/필터 설정·프리셋/schema v11/알림·예약·등록 자동 해제는 변경하지 않는다. 타이머가 어획 성공을 봐도 기존 수집 서비스에 별도 값을 주입하지 않는다.

## 0.3.11.0 미지의 낚시터와 이전 위치 분리 (2026-10-20)

사용자 재현: 알고 있는 낚시터에서 종료한 뒤 같은 지역의 미지의 낚시터에서 시전하면 이전 낚시터의 어종 보기가 계속 활성화됐다. `spot ?? lastConfirmedSpot`이 새 시전에도 이전 표본을 현재 값으로 돌려주던 경로를 수정했다. 종료 후 마지막 위치 보기 자체는 유지한다.

## 0.4.1.0 기록 위치·시간·최근 타이머 (2026-10-20)

- 코드 원인: ApplySpotDiscovery는 타이머의 spot/목록만 갱신했다. Core.SetSpot은 Active만 받는데 성공3512 처리에서 이미 Active를 비우므로, 발견 당시 종료된 시전/묶음에는 위치가 남지 않았다. 검증한 성공 시전 ID를 보관하고 기존 발견/본인 어획의2초·지역/유일 매핑·결과 단계 가드를 통과할 때 그 행과 비어 있는 묶음 위치를 갱신해 기존 저장 큐에 넣는다. 과거 다른 미확인 행의 위치는 소급 추측하지 않는다. 새 네이티브 필드/시그니처·KR 계약 변경 없음.
