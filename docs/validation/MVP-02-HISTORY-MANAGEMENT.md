# MVP-02 낚시 기록 관리 개선

2026-10-17 · Plugin0.2.2.0 · 별도 빌드 완료, 정규 반영/인게임 검증 대기.

## 실제 피드백과 합의

- 정규0.2.1.0 사용자 사진에서 기록5행(성공3/중단2)과 어종·미끼·ET 표시를 확인했다. 저장/재로드·전체 전이 검증으로 확대하지 않는다.
- 사용자는 낚아채기 때 타이머 정지, 낚시터 어종 버튼 수정, 기록 관리와 공백 개선을 요청했다.
- ‘낚시 기록’ 탭의 요약 목록 → 같은 탭 상세/목록 복귀, 묶음별 삭제/종료 기록 전체 삭제, 타이머 현재 기록만 유지에 동의했다.
- 최종 보관 합의는 **캐릭터별 최근100묶음, 묶음별 최근2000회**다. 앞선20/50묶음·1000회 제안은 사용하지 않는다. 진행 중 묶음 보호/총 시전·결과 횟수 유지.

## 구현과 경계

- Core FishingAttempts에 순번/지역·낚시터/시작·종료/총 시전·결과별 횟수의 묶음 요약을 추가했다. 완전 접기/로그아웃/지역 전환/공백/재로드는 기존 종료 경계를 사용한다. 기록 시작과 물리적인 낚시 시작의 미확인은 구분한다.
- 타이머와 행의 대표 경과는 HookSeconds를 우선하여 본인1116 또는 Phase6 관찰에서 멈춘다. 입력 후 첫 관찰까지 지연될 수 있으며 키 입력을 직접 감시하지 않는다. DurationSeconds는 결과 관찰까지의 경과로 별도 유지한다. 낚아채기 없는 회수 등은 종료 관찰 경과를 표시한다.
- 기존1110 위치 로그가 Phase1보다 먼저 도착하고 당시 Phase0이면 위치가 즉시 지워지던 순서를 수정했다. 후보를2초 동안 별도 보관해 새 시전에 연결한다. 같은 낚시 중에는 확인한 위치를 유지하며 완전 종료 후는 ‘최근 낚시터’라고 명시한다. 이동/로그아웃/관찰 불가는 모두 비운다. 수정 효과는 인게임 확인 대기다.
- 디스크 KR 시트 조사: Place425/Territory339 → Spot104/Map72로 연결됨을 재확인했다. 매핑 누락으로 단정하지 않는다. 새 API/후크/네이티브 오프셋 변경은 없다.
- 글자 ‘어종 보기’ 버튼과 기존 FishRowRenderer 팝업을 사용한다. 전체↔수집 숨김/수동 우선/Unknown 유지, 메인 일반 필터와 독립이라는 기존 정책을 유지한다.
- 타이머는 현재 묶음 기록만 표시하고 완전 종료 후 비운다. 메인은 요약 표/선택한 묶음의 상세 표를 사용하고 좁은 상세는 기존 두 줄 행으로 전환한다. 불필요한 세션 구분 행/예약 공백을 제거했다. 한국어 ‘연속 낚시’ 표시를 없앴다.
- UI 선택/삭제 요청은 캐릭터 세션과 함께 Framework에 전달한다. 삭제는 확인 대화 후 종료 기록만 허용한다. 실패 파일은 목록에 남고 오류를 표시한다. 이전 세션의 요청은 폐기한다.
- 기존 수집 판정/수동 우선/필터·프리셋/알림·등록 자동 해제는 바꾸지 않았다. 타이머 결과를 수집 판정에 주입하지 않는다. 미검증 실패/복수/소장품/생미끼 실제 Item/먼바다 제한도 유지한다.

## 파일과 성능

- schema2: `<plugin config>/fishing-history/<character:X16>/<tripGUID:N>.json`. 한 묶음당 최대8MiB,2000행. 이름/대화/포인터는 보관하지 않는다. 단일 작업자가 현재 묶음 최신 snapshot을 병합해 같은 디렉터리 임시 파일 flush/교체한다.
- 요약 목록은 저장 메타데이터만 캐시한다. 상세 DTO는 선택한 묶음만 읽으며 UI Draw에는 파일/전체 어종 조회가 없다. 행은 clipper를 사용하고 아이템 이름/아이콘은 Framework에서 프레임당 최대16개 해석한다.
- schema1의 `<character:X16>.json`은 원본을 남기고 기존 SessionId별로 가져온다. 성공 후 `.legacy-imported` 마커를 남겨 사용자가 삭제한 묶음을 원본에서 다시 생성하지 않는다. 중간 실패 재개는 이미 저장한 GUID를 건너뛴다. 이전1000건에서 이미 소실된 기록은 복구할 수 없다.
- 미완료 파일 복원은 Pending만 중단/Reload로 전환하고 종료 시각/경과를 만들어내지 않는다. Windows 파일 교체 전에 원본 읽기 스트림을 닫는다. 손상/미지원 읽기 실패는 해당 캐릭터 저장·삭제를 차단한다.
- 100묶음 초과 시 가장 오래된 종료 기록만 정리한다. 묶음2000회 초과 시 최근 행만 남겨도 총 시전/결과 횟수는 유지한다. 진행 중 기록은 삭제/정리에서 보호한다. GUID/로컬 캐릭터 키로 생성한 파일만 삭제하며 재귀 삭제는 사용하지 않는다.

## 실행한 검사

- 직접 별도 `dotnet build --no-restore -c Debug`/현재 KR DalamudLibPath: 경고0/오류0. 한영554키/형식 인자 검사 통과. 출력 Plugin1,163,776바이트/0.2.2.0, Core55,808바이트/1.0.0.0, ko52,736바이트/0.2.2.0. manifest DuckbillFisher/0.2.2.0/API15 확인. `git diff --check`와 변경 파일의 비의도 문자 검사도 통과했다.
- 코드 검토로 캐릭터 요청 격리/쓰기·삭제 순서/원본 가져오기/진행 기록 보호/구독 해제/UTC·단조 시계 분리를 확인했다. 자동 테스트는 추가하거나 실행하지 않았다.
- 현재 정규 DLL은0.2.1.0이다. 이번 작업의 새 언로드 확인 전에는 교체하지 않는다. 푸시/릴리스 없음.

## 다음 실제 확인

1. 새 언로드 확인/정규 반영 후 재로드. 메인 ‘낚시 기록’에서 이전 기록이 묶음 요약으로 보이고 클릭/목록 복귀가 되는지 확인한다.
2. 일반 낚시1회에서 낚아채기 직후 숫자가 멈추고 성공 결과만 나중에 붙는지 확인한다. 직접 회수는 별도 결과로 유지한다.
3. ‘어종 보기’를 눌러 현재 낚시터와 두 수집 선택을 확인한다. 완전히 접으면 타이머 행은 사라지고 메인 종료 요약은 남아야 한다. 최근 낚시터 조회에는 ‘최근’ 표시가 있어야 한다.
4. 종료 묶음 하나의 삭제 취소/확정과 진행 중 삭제 비활성, 종료 기록 전체 삭제를 확인한다. 재로드 후 삭제한 묶음이 다시 나타나지 않아야 한다. 사용자 확인 없이 실제 기록을 삭제하지 않는다.
5. 보관 상한/비정상 종료/쓰기 실패/절전/한영·좁은 화면 조합은 미확인으로 남긴다. 다른 캐릭터는 보유 캐릭터가 없어 실기 보류한다. 기본 보고는 짧은 timer/v2 진단과 동작 설명만 받는다.
