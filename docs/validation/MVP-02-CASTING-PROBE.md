# MVP-02 KR 캐스팅 관찰 첫 구현

2026-10-17 · 0.2.0.0 · 별도 빌드 완료 / 새 언로드 확인·정규 반영·인게임 관찰 대기.

## 확정한 범위

- 사용자 승인: 별도 캐스팅 타이머+아래 최근100회, 낚시터 어종 팝업(전체↔수집 숨김), 메인 히스토리 탭, 캐릭터별1000회 영속/최신순/연속 세션 구분. [요구사항/데이터 표](../CASTING-TIMER-HISTORY.md).
- 이 변경은 위 기능에 앞선 **KR 이벤트의 실제 의미 확인용 관찰기**다. 타이머 화면/어종 팝업/영속 히스토리는 아직 제공하지 않는다. 숫자 상태를 실제 캐스팅/성공/실패로 승격하지 않는다.
- 메인 설정에서 개발자 도구를 켜고 기존 ‘낚시 상태 관찰’에서 시작/중지/수동 표식/복사를 사용한다. 기록 시작은 Framework 요청이며 첫 표본 이후 게임 행동을 한다.
- 사용하지 않을 때는 네이티브 읽기/로그 매개변수 복사를 하지 않는다. 새 관찰 시작 시 기존 관찰200행을 초기화하고, 기본 보고서는 마지막40행만 복사한다.

## 책임과 경계

| 코드 | 책임/실패 동작 |
|---|---|
| NativeFishingActivityReader | 기존 KR/DLL 호환성 가드+Framework+해당 ContentId/IsLoaded+어부 직업 확인 후 생성형 정적 주소를 읽음. EventFramework 이중 포인터/handler null과 phase/index 범위 검사. 포인터/Span을 보관하지 않고 예외로 포인터 오류를 덮지 않음 |
| FishingActivityProbe | 명시 시작 중 매 Framework 상태 변화와 공개 플래그/로그를 기록. 한 번 게시한 관리 snapshot을 Draw에서 표시하고 값 변화/이벤트가 없으면 전체 이력을 재복사하지 않음 |
| FishingLogContracts | KR sqpack에서 추출한25개 LogMessage macro의 UTF-8 SHA256과 현재 시트를 시작 시 한 번 비교. 일치한 ID만 관찰, 조회 실패 시0개. 번역된 화면 문장으로 동작을 판정하지 않음 |
| 기존 FishingObservation | 시작부터 단조 경과/최근200행/오래된 행 제외 수. 원시 사건 기록이며 제품의 캐스팅 이력 모델로 간주하지 않음 |

- SourceEntity가 플레이어이며 이름/본국이 로컬 캐릭터와 모두 같으면 `Local`, 명시적으로 다른 플레이어는 `Other`, 출처 없음은 `NoSource`, 불충분한 항목은 `Unknown`. `NoSource`를 본인으로 간주하지 않는다.
- 이름은 콜백의 비교에만 쓰고 원문/대화 본문/ContentId/포인터를 보고서에 넣지 않는다. 매개변수는 숫자 슬롯만 복사하고 문자열 슬롯은 `string`으로 표시한다. FormatLogMessageForDebugging/PreventOriginal 호출 없음.
- 콜백 안에서 빌린 객체/SourceEntity/매개변수를 읽고 즉시 관리 값으로 복사한다. 큐는64개, 처리 유효시간2초, 세션/지역 불일치는 폐기하며 제외 수를 기록한다. 콜백 시점의 플래그와 단조 시각을 보존한다.
- 사용자 중지 직전에 큐에 도착한 동일 캐릭터의 이벤트는 먼저 처리한다. 캐릭터 경계/지역 전환/개발자 도구 해제/5초 초과 관찰 공백은 기록을 중지하고 큐·로컬 식별 캐시를 폐기한다. 자동 재시작/이전 사건 재생 없음.
- Dispose에서 Framework/LogMessage/ConditionChange 구독을 해제한다. 일반 목록/수집 비트/도감 준비/수동 우선/프리셋/알림·자동 즐겨찾기 해제는 변경하지 않는다.
- 첫 표본/로그는 관찰 사실이다. 단조 경과는 입력 지연/착수 시각/서버 시각의 정밀 측정으로 표현하지 않는다. 아직 Product F07/F13의 완료 조건을 충족하지 않는다.

- `.cache/casting-audit/casting-audit.csproj`는 설치 Lumina로 **디스크의 KR sqpack만** 읽어25개 macro의 해시를 생성했다. 생성 배열은 FishingLogContracts.cs에 반영했다. 외부 코드/새 라이브러리 도입 없음.
- 허용 ID: 1110/1111/1112/1113/1116/1117/1118/1119/1120/1121/1127/1129/3511/3512/3515/3525/3527/3528/3559/5528/5556/5557/5558/5559/5584.
- 본인 새 도감 등록1114는 별도 수집 서비스에서만 처리한다. 어획3512/복수3559가 일반/작살/주변인 중 어느 범위로 발생하는지는 이번 실기로 구분한다.

## 첫 인게임 확인 — 아직 실행하지 않음

1. 정규0.2.0.0 반영 후 로드, 설정에서 개발자 도구 켜기 → ‘낚시 상태 관찰’ 열기. 일반 낚시터에서 어부 직업/미끼를 준비한다.
2. ‘관찰 시작’ 후 마지막 읽기가 Ready, 계약25/25인지 확인한다. 미끼가 현재 게임과 대응하는 Item ID인지 이후 매핑한다. Ready는 어획 지원 완료 판정이 아니다.
3. 직접 한 번 던져서 일반 어획 성공 → 낚시 자세를 유지하고 한 번 더 던진 뒤 직접 중단/완전히 접기 → 1초 뒤 ‘관찰 중지’와 ‘관찰 복사’. 행동 설명 한 줄과 제한된 보고서 하나를 받는다. 어종/미끼를 사용자가 알려주면 Item ID와 대조한다.
4. 첫 결과로 경계를 확인한 뒤 미끼 변경/생미끼/실패 한 가지를 작은 별도 관찰로 진행한다. 아직 실패가 없으면 억지로 실패했다고 기록하지 않는다.
5. 읽기가 Ready가 아니거나 계약이 부족하면 해당 보고서만 먼저 받고 자동 타이머로 연결하지 않는다. 로그아웃/재로드/개발자 해제 시 구독과 오래된 이벤트 수명은 별도로 확인한다.

## 다음 한 작업

사용자 새 언로드 확인 → 정규 빌드/출력 검사 → 위 1~3의 KR 실제 관찰. 결과에 따라 상태 전이를 확정하고 타이머/공유 기록 모델을 구현한다. 입질 초 수 통계·Teamcraft 조사는 재개하지 않는다.
