# MVP-03 선택형 Toast

날짜: 2026-10-16 · 정규 DLL 0.1.24.0 · 인게임 검증 대기

## 범위와 사용자 동작

- 즐겨찾기 관리의 `화면 팝업도 표시`를 켜면 로컬 채팅과 같은 사전 알림에 화면 상단 팝업을 추가한다. 기본은 꺼짐이며 채팅/효과음/대상 선택과 함께 공통 설정에 저장한다. 전체 알림을 끄면 팝업도 발송하지 않는다.
- 팝업에는 최대 3종의 이름과 분 단위 남은 시간을 표시하고 나머지는 건수로 요약한다. 한 예약 묶음에 한 번 호출하며 클릭 가능한 아이템/지도 링크는 기존 채팅에 남긴다. 시간·날씨 예측 안내이며 개인 준비 완료나 실제 어획 가능성 확정이 아니다.
- 기존 Core 예약과 캐릭터별 저장된 창 기록을 그대로 사용한다. 별도 타이머/재전송 큐/구독을 추가하지 않는다. 로그인·재로드·절전 복귀의 지난 시각을 소급하지 않고 팝업 옵션을 켜도 지난 알림을 재생하지 않는다.
- 채팅 큐 등록 뒤 팝업/효과음을 각각 시도한다. 팝업 실패는 이미 등록한 채팅/발송 이력을 취소하지 않으며 다시 시도하지 않는다. 발송 기록의 `팝업 요청`은 API 큐 등록을 뜻하고 실제 화면 표시를 보장하지 않는다. Dalamud 내부 큐에 넘긴 요청은 플러그인이 취소하지 않는다.
- 설정 schema v6는 v1~v5를 보존하고 새 팝업 옵션을 꺼짐으로 시작한다. 짧은 진단 `alerts/v5`는 Toast 필드를 추가하며 분 단위 설정/기존 예측 공식/네이티브 효과음 게이트는 유지한다.

## 설치 API와 실행 근거

- 실제 KR 설치 `addon/Hooks/dev/Dalamud.dll` 15.0.3.6, MVID `d2fe7e59-9fb6-480d-9e6d-00ece6410e34`의 메타데이터/IL과 같은 폴더 Dalamud.xml을 읽었다. `IToastGui.ShowNormal(string, ToastOptions)`와 `ToastPosition.Top=1`을 확인했다.
- IL상 문자열 호출은 UTF-8 바이트와 옵션을 Dalamud의 normalQueue에 넣는다. 새 시그니처/오프셋/네이티브 호출을 추가하지 않고 기존 Plugin 출력 어댑터에서 Framework 스레드의 공개 서비스를 사용한다.
- `pwsh -NoLogo -NoProfile -File .cache/inspect-toast-api.ps1`: 위 API/큐 등록 경로 확인. 무시된 개발 조사 파일이며 제품이나 배포물에 포함하지 않는다.
- `pwsh -NoLogo -NoProfile -File scripts/check-localization.ps1`: 한영 380키/형식 인자 일치. 최초 샌드박스 pwsh 실행 차단 후 승인 실행으로 통과했다. `git diff --check` 통과.
- 초기 소스 수정 단계의 빌드 생략 뒤 사용자가 새 언로드를 확인하여 별도/정규 0.1.24.0 빌드를 완료했다. 최종 한영 387키/형식 인자 검사 통과. 테스트/인게임 검증은 미실행이다. [빌드 명령/산출물](MVP-01-COMPACT-CONTROLS.md)을 따른다.

## 로드 후 확인

1. 팝업 꺼짐에서 기존 채팅/SE가 유지되고, 켬에서 같은 알림에 상단 팝업 한 번과 한 줄 발송 기록의 팝업 요청 표시를 확인한다.
2. 동시 여러 대상은 팝업 한 개/선택 효과음 한 번이어야 하며 아이템/지도 링크는 채팅에서 계속 열려야 한다.
3. 재로드/로그아웃/절전 복귀의 과거 알림이 팝업으로 재생되지 않는지 확인한다. 실제 확인 전에는 통과로 기록하지 않는다.
