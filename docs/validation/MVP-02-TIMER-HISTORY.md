# MVP-02 캐스팅 타이머·공유 히스토리 첫 구현

2026-10-17 · 별도0.2.1.0 · 정규 교체/인게임 확인 대기.

## 근거와 범위

- [0.2.0.0 실제 KR 표본](MVP-02-CASTING-PROBE.md#실제-kr-표본--사용자-제공-2026-10-17)과 [화면/보관 합의](../CASTING-TIMER-HISTORY.md)를 사용한다.
- 기존 메인/간략/독립 상세에 승인받은 캐스팅 타이머를 추가했다. 메인의 타이머 아이콘, 히스토리 탭 버튼 또는 `/duckbillfisher timer`로 직접 연다. 자동 표시/게임 조작 없음.
- 타이머 상단은 현재 확인한 낚시터/장착 미끼/던진 ET·단조 경과/연속 낚시 시작·경과다. 아래 최근100회 최신순 스크롤, 메인 히스토리 탭은 같은 캐릭터 기록1000회와 세션 구분선을 사용한다. 행 클릭은 기존 독립 상세 하나를 재사용한다.
- 낚시터 옆 어종 버튼은 기존 FishRowRenderer 팝업이다. `전체 ↔ 수집한 어종 숨기기` 한 버튼(기본 숨김)만 제공한다. 모든 일반 목록 필터/검색/진단과 독립이며 수동 우선/Unknown 유지의 기존 수집 판정을 쓴다. 각 행의 지도/조건 툴팁도 재사용한다.
- 낚시터는 검증한 본인1110의 PlaceName+Territory가 유일한 게임 시트 낚시터와 맞을 때만 표시한다. 완전히 접으면 현재 낚시터를 비우며, 주변 좌표/지역/마지막 낚시터로 현재 위치를 추측하지 않는다. 최초 시전 전에는 ‘낚시터는 시전 후 표시’다.

## 판정과 시간

- Core FishingAttempts는 API 없는 단일 작성자 모델이다. 변경 시에만 새 불변 기록 배열을 게시한다. 중복 Phase1 표본으로 새 기록을 생성하지 않는다.
- 새 Phase1 전이를 관찰할 때 캐스팅 하나를 시작하고 장착 미끼를 복사한다. Phase5/6 및 본인1116은 입질/낚아채기의 별도 관찰 경과로 저장한다.
- 본인3512만 단일 성공/Item/수량1로 연결한다. 진행 기록·낚아채기 관찰·결과 단계(2/4)·시각을 함께 확인해 이전 시전의 늦은 결과가 새 던지기/입질 대기에 붙는 것을 막는다. 게임이 제공하는 고유 캐스팅 ID는 없어 지연 사건의 완전한 식별을 보장하지 않는다.
- 본인5584는 진행 기록의 직접 회수다. Phase2는 성공/실패를 구분하지 않는다. Phase4에서 결과 없이2초 지나면 결과 미확인, 새 캐스팅이 먼저 오면 이전 기록은 미확인이다. Fishing=False는 연속 세션을 끝내지 않고 관찰한 Phase0에서 완전히 종료한다.
- 로드/관찰 공백 직후 이미 진행 중인 시전은 기록을 추가하거나 시작 시각을 만들지 않는다. 첫 정상 전이를 본 다음 새 캐스팅부터 기록한다. 이미 낚시 자세였으면 연속 세션 시작은 미확인이다.
- 현재 미끼는 ‘장착 미끼’로 표시한다. 생미끼/보관 생미끼 플래그가 있으면 기록 종류만 구분하고 실제 미끼 Item은 미확인으로 둔다. 장착 미끼를 생미끼 어종으로 저장하지 않는다.
- 실패/복수/소장품/방생 등 미검증 결과는 성공/실패로 추정하지 않는다. 먼바다는 게임 IKDSpot의 낚시터 Territory를 기준으로 아직 기록을 비활성화한다. 작살 결과를 기존 진행 캐스팅 없이 붙이지 않는다.
- UTC는 관찰 시각으로 저장하고 ET 표시와 로컬 표시를 분리한다. 경과는 Stopwatch로만 계산하며 OS 시각 변경으로 길이를 다시 계산하지 않는다. 입질 초 수 통계/예측은 추가하지 않았다.

## 저장·수명·성능

- FishingTracker가 Framework에서 네이티브 표본/검증한 공개 로그를 Core에 전달한다. 공개 로그의 본인 비교는 관찰기와 FishingLogContracts.Actor를 공유한다. 콜백 내에서 값만 복사, 제한64건/최대2초/세션·지역 확인 후 적용. Draw에서 게임 데이터/파일/장기 예측을 읽지 않는다.
- 현재 낚시터 어종/수집 숨김 결과는 데이터·낚시터·수집/수동 revision이 바뀔 때 Framework에서 계산한다. 저장된 Item 이름/아이콘도 최대16개씩 Framework에서 캐시하고 Draw에서는 관리 값만 쓴다.
- FishingHistoryStore는 일반 설정과 분리한 `<plugin config>/fishing-history/<local character key>.json`(schema1), 캐릭터별1000회/최대4MiB다. 이름/대화/포인터를 저장하거나 진단에 캐릭터 키를 내보내지 않는다.
- 단일 저장 작업자가 캐릭터별 최신 snapshot을 병합하고 같은 디렉터리 임시 파일을 flush 후 교체한다. 손상/미지원/읽기 불가 원본은 덮어쓰지 않고 새 기록은 메모리로 유지한다. 쓰기 실패는5초 간격 재시도하며 화면에 표시한다.
- 진행 기록도 저장한다. 정상 언로드는 중단/Reload로 끝내고 저장 작업을 기다린다. 비정상 종료 후 Pending 복원은 중단/Reload이며 소실된 경과를 추측하지 않는다. 로그인/캐릭터 전환 때 기존 표시/활성 기록/큐/낚시터를 비우고 해당 캐릭터 파일만 복원한다.
- 지역 전환/관찰 불가/5초 초과 공백도 미완료 기록을 중단으로 끝내고 기존 전이를 재생하지 않는다. 서비스/관찰기 이벤트는 Dispose에서 해제한다.
- 기존 도감 판정/수동 우선/필터 설정·프리셋/schema v11/알림·예약·등록 자동 해제는 변경하지 않는다. 타이머가 어획 성공을 봐도 기존 수집 서비스에 별도 값을 주입하지 않는다.

## 검사와 확인 대기

- 직접 별도 `dotnet build --no-restore -c Debug` + 현재 KR DalamudLibPath: 경고0/오류0. 자동 테스트는 추가/실행하지 않는다.
- 한영526키/형식 인자 검사 통과. 별도 출력 Plugin1,132,544바이트/0.2.1.0, Core50,688바이트/1.0.0.0, ko50,688바이트/0.2.1.0. manifest DuckbillFisher/0.2.1.0/API15 확인. 현재 정규는0.2.0.0이며 새 언로드 확인 전 교체하지 않는다.
- 새 구현의 인게임 확인은 아직 없다. 위 원시 관찰 결과가 타이머/JSON 저장/화면/필터 확인을 대신하지 않는다. 다른 캐릭터 실기는 사용자 보유 캐릭터가 없어 보류한다.

## 다음 실제 확인

1. 새 언로드 확인/정규 반영 후 기존 경로 재로드. 메인의 타이머 아이콘 또는 `/duckbillfisher timer`로 연다. 개발자 도구를 끈 상태에서도 기록해야 한다.
2. 일반 낚시터에서 어부로 일반 미끼를 장착하고 직접 성공 어획1회 → 재시전 후 직접 회수 → 완전히 접는다. 던진 ET/실시간 경과/계속되는 연속 세션/성공·직접 회수2행/미끼 고정을 확인한다.
3. 접기 전에 낚시터 옆 어종 팝업을 열어 전체↔수집 숨김을 확인한다. 메인을 터주/시간제 등 강하게 제한해도 이 팝업은 낚시터 전체 범위를 보여야 한다. Unknown은 숨김에서 유지한다.
4. 메인 히스토리와 타이머 최근 기록이 일치하는지 확인하고, 캐스팅이 끝난 상태에서 재로드해 동일 기록이 중복 없이 복원되는지 본다. 진행 중 재로드/절전/실패/생미끼 등은 별도 후속 표본으로 확인한다.
5. 이상이 있으면 개발자 도구를 켜고 히스토리의 ‘타이머 진단 복사’ 짧은 보고서와 동작 설명만 받는다. 원시 전체 로그는 기본 요청하지 않는다.
