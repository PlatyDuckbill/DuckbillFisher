# 초기 시간·날씨 예측 계산 대조

갱신: 2026-10-16. **계산 대조 통과 / 실제 게임 ET·날씨 동시 대조 대기**. 운영 코드와 데이터, Plugin 0.1.5.0 DLL은 변경하지 않았다.

## 기준과 결과

고정 Fish Tracker `weather.js`의 실제 목표값 함수를 JavaScript로 실행했다. 시간 창은 별도 이벤트 분할 방식으로 계산했다. 전체 웹 앱을 실행하거나 웹 화면에서 예측을 조회한 결과는 아니다. 입력·생성 방식·원본 SHA256·재생성 명령은 [fixture 설명](../../tests/DuckbillFisher.Core.Tests/Fixtures/README.md)을 따른다.

| 항목 | 결과 |
|---|---|
| 한섭 10개 낚시터의 날씨 확률과 원본 누적 확률 | 10/10 일치 |
| 날씨 목표값 | 434구간, 각 시작/1초 뒤/마지막 초에서 일치 |
| 초기 10종의 현재/다음 창 | 고정 시각과 이후 7일, 시작/종료 ±1ms 포함 134건 일치 |
| 직접 계산한 경계 | 시작 포함/종료 제외, ET 자정 통과, 소수 ET 시간 통과 |
| 실패/범위 경계 | 잘못된 시간·확률표는 Unknown, 범위 내 미발견은 NotFound, 끝 미확인은 null |
| 기타 | UTC 오프셋 불변, 개인 준비 조건을 자동 판정하지 않음 |
| 전체 Core 테스트 | 기존 15개 + 새 586개 = 601개 통과, 실패/건너뜀 0 |
| 다국어 검사 | 137키·형식 인자 일치 |

새 테스트의 첫 실행은 통과했으나 테스트 MemberData의 nullable 경고 2개가 있었다. 인자 배열을 `object?[]`로 수정한 뒤 표준 파이프라인을 재실행했고 경고 없이 통과했다.

```powershell
dotnet test tests/DuckbillFisher.Core.Tests/DuckbillFisher.Core.Tests.csproj --no-restore -c Debug
pwsh -NoLogo -NoProfile -File scripts/build.ps1 -CoreOnly
```

고정 보고 시각 `2026-10-15T16:50:59.114Z`에서 독립 기대값이 사용자 보고의 10종 상태·시작·종료와 모두 일치했다. 대표적인 다음 창은 넵토드래곤 `2026-10-16T00:30:00Z~00:53:20Z`, 헬리코프리온 `04:46:40Z~04:58:20Z`다. 이는 보고서 자체를 정답으로 복사한 결과가 아니다.

## 남은 범위

- 실제 게임의 ET와 현재/직전 날씨를 같은 UTC 시각에 기록해 대조한 결과는 아직 없다. 커뮤니티 출현 조건이 한섭에서 실제 어획 조건과 일치하는지도 이번 계산 검증으로 확정하지 않는다.
- 현재 열린 창의 start는 현재 날씨 구간에서 잘릴 수 있다. 과거부터 이어진 원래 시작 시각은 복원하지 않는다. UI는 열린 창의 종료까지 남은 시간을 표시한다.
- 432개 날씨 구간의 제한, 통상 시간/날씨 창만 계산하는 범위는 유지한다. 물고기의 눈·직감·개인 준비 상태와 실제 어획 가능 여부는 별개다.
- 인게임 정렬/영어 전환·넵토드래곤 직감 상세 등 기존 추가 UI 확인은 [상세 검증 기록](MVP-01-DETAILS.md)에 남아 있다.

계산 수정 사항이 없어 Plugin 재빌드/언로드/재로드는 요청하지 않았다. 다음 구현 단위는 MVP-01 즐겨찾기·수동 수집 상태 및 필터다. 미끼/생미끼 아이템 링크·스킬/날씨 아이콘은 [후속 목록](../ROADMAP.md)에만 추가했다.
