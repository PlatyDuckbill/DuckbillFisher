# 낚시 기록 저장·복구 안정성: 0.2.7.0

2026-10-17. 사용자 승인 범위는 기록의 저장·복원·삭제 점검과 발견한 문제 수정이다. 기존100묶음×최근2000회/schema2·캐릭터 격리·수집/알림/관찰 정책은 유지한다.

## 코드 검토에서 찾은 경로와 수정

| 경로 | 기존 문제 | 변경 |
|---|---|---|
| 저장 실패 후 다음 묶음/로그아웃 | 작업자가 실패 snapshot을 버리고 Tracker는 현재 묶음만 재시도했다 | Store가 묶음별 최신 실패 snapshot을 보유하고5초마다 직렬 재시도. 새 snapshot/삭제가 오래된 재시도를 대체 |
| 읽기 대기 중 이전 쓰기 완료 | 쓰기 완료가 목록 읽기보다 먼저 Ready를 게시할 수 있었다 | 캐릭터의 Loading과 쓰기 권한을 분리. 목록 검증이 끝날 때까지 읽기 대기 유지 |
| 오류 뒤 다른 작업 성공 | 다른 묶음의 저장/삭제 성공이 이전 오류 표시를 지웠다 | 묶음별 쓰기/삭제 실패와 캐릭터 읽기 오류를 각각 유지. 해당 작업 성공만 오류 해제 |
| 정상 summary/손상 records | 초기 목록에서 summary만 검사해 상세 손상 상태에서도 정리/저장이 가능했다 | 초기 작업자에서 모든 본문을 제한 크기로 검사한 뒤 미완료 복구/보관 정리. 상세 읽기 오류도 저장·삭제 차단 |
| 재로드 직후 첫 시전 | 기존 최대 Sequence를 읽기 전에 새 묶음에 순번을 부여할 수 있었다 | Archive/쓰기 권한을 먼저 반영한 뒤 시전 관찰 |
| 오래된 상세 요청/빠른 재접속 | 이전 요청의 결과·오류가 최신 선택에 반영될 수 있었다 | 상세 요청 세대 값 대조. 같은 캐릭터의 새 Load가 대기 중이면 이전 Load 완료가 Loading을 해제하지 않음 |

위 항목은 코드의 실행 순서로 확인한 문제 경로이며 실제 게임에서 오류를 재현했다고 표현하지 않는다.

## 저장·삭제·실패 경계

- 파일 작업은 기존 단일 작업자만 실행한다. Timer는 복사된 DTO의 재시도를 큐에 넣으며 게임 API·렌더링에 접근하지 않는다. 잠금 중 파일 IO는 하지 않는다.
- 재시도는 큐에 넣을 때 소비하므로 오래된 snapshot이 최신 쓰기 뒤에 다시 덮어쓰지 않는다. 삭제 요청은 미실행 쓰기/재시도를 제거하고 tombstone으로 같은 ID의 재저장을 막는다. 진행 중 보호/확인 대화/세션 검증은 기존대로다.
- 읽기 오류는 같은 캐릭터의 저장·삭제·자동 정리를 차단한다. 원인을 수정한 뒤 다시 Load하여 검증을 통과해야 해제된다. 다른 묶음의 성공으로 해제하지 않는다.
- 삭제 파일의 미완료 상세 요청은 정상 취소로 처리한다. 단순 외부 삭제·손상은 성공으로 숨기지 않는다. 삭제 실패는 목록에 남으며 재시도 중임을 표시한다.
- schema1 원본/가져오기 마커를 유지한다. 가져오기 도중 실패하면 읽기 실패 상태로 변경을 막고 원본에서 재개한다. 완료 마커 뒤에는 삭제한 묶음을 다시 가져오지 않는다.
- 기존 같은 디렉터리 `.tmp` 쓰기→Flush(true)→최종 파일 교체를 유지한다. 미완료 `.tmp`를 임의로 복원하지 않는다. 갑작스러운 프로세스 종료/전원 차단에서 마지막 미완료 쓰기까지 보장하지 않는다.
- Dispose는 Timer를 해제하고 남은 재시도를 한 번 더 큐에 넣어 작업자를 기다린다. 여전히 실패한 변경은 메모리에만 남으며 진단 로그 `FishingHistoryDrainIncomplete`로 개수만 남긴다. 캐릭터 ID/파일 내용은 출력하지 않는다.
- 쓰기/삭제 재시도 안내와 읽기 차단 안내를 EN/KO 리소스로 구분했다. 재시도 간격은 Store 상수를 UI 형식 인자로 전달한다. 진단 timer/v3 필드는 변경하지 않았다.

## 짧은 인게임 확인 순서

1. 기존 자료 대신 새 확인용 묶음으로 시전2회 후 완전히 접는다. 메인 기록에 위치/시각/횟수와 상세가 일치하는지 확인한다.
2. 플러그인 언로드→재로드 후 같은 묶음/결과가 한 번만 표시되는지 확인한다. 다시 낚시해 만든 새 묶음이 최신순 맨 위에 오는지 확인한다.
3. 새 확인용 종료 묶음의 삭제를 취소하면 유지되고, 삭제 확정하면 사라지는지 확인한다. 다시 언로드→재로드해 삭제한 묶음이 돌아오지 않는지 확인한다. 기존 기록 전체 삭제는 요청하지 않는다.
4. 진행 중인 시전에서 언로드한 경우 저장된 미완료 시전은 중단/Reload로 남고 성공·실패나 경과를 새로 만들어내지 않아야 한다. 재로드가 진행 중 시전을 새 기록으로 복제하지 않아야 한다.

쓰기 실패 재시도·손상 파일·이전 형식·100묶음/2000회 한도·절전·비정상 종료의 실기 확인은 남아 있다. 위 대표 확인을 전수 검증으로 확대하지 않는다. 다른 캐릭터 실기는 보유 캐릭터가 없어 기존 보류를 유지한다.
