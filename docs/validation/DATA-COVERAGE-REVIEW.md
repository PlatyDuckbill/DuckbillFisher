# 전체 데이터 확대 전 누락 점검

날짜: 2026-10-16 · 현재 DLL 0.1.11.0 · 자료/코드 점검 완료, 기능 구현 전

## 범위와 자료

- 사용자 요청: 확장팩별 추가 대신 전체 원본을 대상으로 확대하기 전에 유용한 누락 정보를 점검한다. 입질 초 수는 후순위다.
- 입력은 기존 고정 revision `d0e1ab5bba62c2b57356e690a73676cd4751b64d`의 `private/fishData.yaml`, `js/app/data.js`, `private/manageFishData.py`와 현재 UI/Core/변환 도구다. JS 해시는 `data/fishing-source.json`을 따른다.
- 실제 KR `2026.10.06.0000.0000`의 FishParameter/Item/GatheringSubCategory/FishingNoteInfo/SpearfishingItem을 로컬 Lumina로 읽었다.
- 한섭 일반 낚시 도감 1258종 중 원본 Item ID 대응 903종/미대응 355종. 먼바다 259종의 원본 상세 대응은 0종이다. 원본 전체는 1110건이며 대응 수는 조건 완전성이나 바로 가져올 수 있는 종 수를 뜻하지 않는다.
- 작살 원본 203건이 한섭 SpearfishingItem과 대응한다. 이 중 115건은 원본 조건 미확인이다. 일반 목록/위치 정보와 커뮤니티 상세 조건의 출처·수록 범위를 구분한다.

## 조건 누락을 막기 위한 보완

- YAML `dataMissing: true` 115건 모두 작살이며 JS에서는 `dataMissing: null`, `gig: UNKNOWN`으로 변환되어 있다. JS의 null만 보고 자료가 완전하다고 판정하지 않는다. 기존 ARR 140종에는 해당하지 않는다.
- 대응 일반 원본 80종은 hookset이 비어 있다. 이를 강력한 낚아채기나 강한 입질로 채우지 않는다. 필드별 미확인과 전체 자료 미존재를 구분해야 한다.
- 작살 predators는 특수 채집 지점 생성 조건을 담기도 한다(예: Shogun's Kabuto의 Cloudy Cat Shark 10마리). 일반 낚시의 직감/지속 시간으로 그대로 변환하지 않는다.
- 한섭 대응/부분 정보/미지원 방식/조건 미확인/자료 없음 개수를 기록한다. 알려진 정보는 표시하면서 미지원 조건이 있는 어종을 완전한 예측으로 표현하지 않는다.
- 전체 확대 시 초당 장기 예측 비용을 확인한다. 렌더링 중 계산 금지와 짧은 진단 기본 원칙을 유지한다.

## 실행 및 다음 작업

- 로컬 `.cache/data-preflight/` 도구로 시트 대응/필드/전승록 참조를 읽고 캐시된 YAML·JS의 필드/미확인 표시를 비교했다. 제품 코드/데이터/DLL은 변경하지 않았다. 제품 빌드·인게임 확인·단위 테스트는 실행하지 않았다.
- 다음은 전체 원본 분류와 데이터 모델 보완 후 지원 가능한 상세의 일괄 도입이다. 우선 대체 미끼·훌치기/유인·물고기의 눈 안내·전승록 참조·필드별 미확인을 수용한다. 먼바다 출처 보강과 작살 별도 계약은 분류에 드러내고 부족한 값을 추측하지 않는다.
- 다음 창 여러 개/알림·미끼 보유량/구매처·소장품 보상은 후속 기능이며 입질 초 수 통계는 계속 미룬다.
