# ENV-03 Windows 관찰 절차

판정: **낚시 중단/정상 어획과 관찰 기능 기본 검증 통과**. 아래는 재현 절차다. 낚시 자체 중단 3회와 자세를 유지한 정상 어획 3회의 보고서 및 기본 수명 주기 확인은 [관찰 결과](ENV-03-WIN-RESULTS.md)에 따로 기록했다. 도중 시작·추가 경계 등은 미확인으로 구분한다.

## 목적과 기록 방식

직접 낚시할 때 공개 `ICondition.ConditionChange`의 `Fishing`, `ExecutingGatheringAction`, `Casting` 세 플래그가 언제 변하는지 대조한다. 정밀 시전 시작, 입질 감지, 수첩 읽기는 이번 구현에 포함하지 않았다.

- 로드 직후 관찰은 꺼져 있다. `/duckbillfisher` 창에서 **새 관찰 시작**을 눌러야 기록한다.
- 시작/중지/수동 메모 때 세 플래그의 표본을 읽고, 관찰 중 대상 이벤트가 발생하면 이벤트 이름·값과 표본을 기록한다. 다른 플래그는 무시한다. 매 프레임 폴링하지 않는다.
- `START`와 `STOP`은 표본이며 상태 변경 이벤트가 아니다. `CHANGE`만 공개 API 이벤트다. 동시에 바뀐 플래그는 같은 시각 또는 같은 표본을 가질 수 있다. 행 순서를 게임 동작의 세부 순서로 단정하지 않는다.
- `MARK (manual)`은 사람이 **메모 추가**를 클릭한 시각이다. 행동 감지나 타이머 정확도 측정의 기준으로 사용하지 않는다.
- 시간은 관찰 시작 기준 Stopwatch 경과 초다. UTC는 보고서의 시작 시각에만 사용한다.
- 최근 200행만 메모리에 보관하고, 넘친 행 수를 표시한다. 창은 최신순, 복사 보고서는 시간순이다. 파일·채팅·일반 로그에는 자동 저장하지 않는다.
- 관찰 중 창을 닫아도 계속 기록한다. **관찰 중지** 후 복사할 수 있다. 새 관찰 시작은 이전 기록을 지운다. 언로드/재로드·게임 종료 시 기록은 사라진다.
- 보고서는 캐릭터명·계정·좌표를 수집하지 않는다. 형식 버전, Plugin/Dalamud assembly 버전, 시작 UTC, 세 플래그와 고정 메모만 담는다. 게임 빌드와 사용한 소스 식별은 별도로 기록한다.

## Windows에서 새 코드 빌드

기존 소스 ZIP에는 관찰 기능이 없다. 새 소스 ZIP을 별도 폴더에 풀거나 이번 변경이 포함된 소스를 받는다. ZIP 방식은 동봉된 `.sha256`과 아래 출력으로 파일을 대조할 수 있다.

```powershell
Get-FileHash "받은 ZIP의 전체 경로" -Algorithm SHA256
```

1. Dalamud 개발 플러그인 목록에서 기존 DuckbillFisher를 **언로드**한다.
2. PowerShell 7에서 새 소스 루트(README.md/global.json이 있는 폴더)로 이동한다.
3. 다음을 실행한다. SDK/PowerShell 재설치는 필요 없다.

```powershell
Get-ChildItem .\scripts\*.ps1 | Unblock-File
.\scripts\build.ps1 -DalamudPath "$env:APPDATA\XIVLauncherKR\addon\Hooks\dev"
```

4. Core 테스트 **15개 통과**와 Plugin 빌드 성공을 확인한다. 실패하면 로드하지 말고 오류 전문을 남긴다.
5. 새 폴더를 사용했다면 Dev Plugin Locations의 기존 DLL 항목을 새 빌드의 `src\DuckbillFisher.Plugin\bin\Debug\DuckbillFisher.dll` 절대 경로로 교체한다. 동일 플러그인 두 경로를 함께 등록하지 않는다.
6. 다시 로드하고 `/duckbillfisher`를 입력한다. **ENV-03 낚시 상태 관찰**과 **새 관찰 시작** 버튼이 보여야 한다. 예전 시작 문구만 보이면 이전 DLL을 로드한 것이다. 창이 작으면 늘린다.

## 직접 실행할 순서

안정적인 한 낚시터에서 일반 낚시로 시작한다. 인벤토리 공간과 미끼는 직접 준비한다. 각 묶음이 끝나면 **관찰 중지 → 기록 복사**로 텍스트 파일에 붙여 넣는다. 다음 관찰 시작 전에 반드시 복사한다.

| 묶음 | 직접 수행할 행동 | 확인할 내용 |
|---|---|---|
| A. 기본 주기 | 낚시 전 새 관찰 시작 → 찌 던지기 → 기다리기 → 입질 → 낚아채기 → 다시 던지기를 포함해 3회 → 낚시 종료 → 관찰 중지 | 각 행동 근처의 CHANGE 이름/값과 반복 패턴. 입질 때 아무 변화가 없어도 그대로 결과로 기록 |
| B. 취소 | 새 관찰 → 찌 던지기 → 입질 전 회수/취소 → 다시 던지기 → 종료 | 취소와 정상 낚아채기를 세 플래그로 구분할 수 있는지. 사용할 수 있으면 생미끼 시전도 별도 관찰 |
| C. 도중 시작 | 이미 낚시 대기 중일 때 새 관찰 → 한 주기 진행 → 종료 | START에 당시 표본이 들어가는지. START를 새 시전으로 해석하지 않는지 |
| D. UI와 수명 | 관찰 중 창 닫기 → 한 주기 → 명령으로 다시 열기 → 중지·복사 → 언로드·재로드 → 새 관찰로 한 주기 | 창이 닫혀도 기록 유지, 중지 후 행 수 고정, 재로드 후 기본 중지/빈 기록, 명령·창·이벤트 행의 중복 여부 |
| E. 경계 | 새 관찰 → 낚시 종료 후 지역 이동 → 가능하면 로그아웃/로그인 → 다시 창 확인 | 낚시 밖의 플래그 변화도 원시 상태로 기록, 오류/크래시 없음. 불가능한 항목은 미실행으로 기록 |

행동 직후 여유가 있을 때 수동 메모를 추가하면 구간 대조에 도움이 된다. 메모 때문에 낚아채기 시기를 놓칠 필요는 없다. 입질 구간에서 이벤트가 없었다면 보고서와 함께 그 사실을 별도로 적는다. `Fishing=True`가 찌를 던질 때마다 생겨야 한다는 기대는 두지 않는다.

게임 자체가 숨기는 상황(로그아웃 화면 등)에서는 창이 보이지 않을 수 있다. 로그인 후 다시 확인한다. 관찰은 캐릭터별 상태를 추론하거나 저장하지 않는다.

## 보고서 형태 예시

아래 값과 시각은 **형식 설명용 가상 데이터**다. 한섭 기대 전이가 아니다.

```text
DuckbillFisher ENV-03/public-conditions/v1
Plugin: 0.1.0.0; Dalamud: 15.0.3.6
Started UTC: ...
Recording: False; retained: ...; dropped: 0
...
#0001 +0.000s START (snapshot) | F=False G=False C=False
#0002 +2.125s MARK (manual): 찌 던짐 | F=True G=False C=False
#0003 +3.100s CHANGE ExecutingGatheringAction=True | F=True G=True C=False
```

변경 이벤트가 없어도 START/STOP은 남아야 한다. 행이 많으면 먼저 짧은 관찰로 나눠 `dropped: 0`인 보고서를 확보한다. 같은 값의 CHANGE가 인접해 반복되면 합치지 말고 그대로 제공한다. 중복 구독인지 실제 이벤트인지 추가로 확인한다. 오류는 `/xllog`에서 DuckbillFisher 관련 부분을 함께 기록한다.

## 결과 입력

- 사용한 소스: 커밋 SHA 또는 소스 ZIP 파일명/SHA256:
- KR 게임 빌드 / Dalamud 표시 버전 / 보고서 assembly 버전:
- Windows 빌드: 테스트 통과 수 / 경고·오류:
- A~E: 수행/미실행과 행동별 실제 관찰:
- 기록 복사 결과: 묶음별 텍스트:
- 중지/창 닫기/언로드·재로드/지역 이동/로그아웃 결과:
- `/xllog` 관련 오류(있을 때):

이 결과를 보고 공개 플래그만으로 개별 시전/종료를 구분할 수 있는지 판단한다. 구분할 수 없으면 추가 API 조사를 다음 작업으로 정한다. 수첩 읽기는 별도 검증으로 남긴다.
