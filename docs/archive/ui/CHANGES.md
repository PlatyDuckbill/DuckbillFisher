## 0.1.30.0 설정 UI 콜백 등록

갱신: 2026-10-17 · 0.1.31.0 정규 DLL에 포함 · 인게임 확인 대기

- 사용자 화면에 설정 UI 콜백 미등록 검증 경고가 표시됐다. Plugin은 OpenMainUi만 등록하고 OpenConfigUi는 등록하지 않은 상태였다.
- 설치 Dalamud 15.0.3.6의 IUiBuilder.OpenConfigUi 문서에서 설정 UI 열기 요청 이벤트임을 확인했다.
- Plugin 로드 시 OpenConfigUi에 MainWindow.OpenSettings를 등록하고 Dispose에서 같은 핸들러를 해제한다.
- OpenSettings는 메인을 열고 기존 설정 탭을 선택한다. 이미 열려 있어도 닫지 않으며, 즐겨찾기의 설정 버튼도 같은 경로를 사용한다. 빈 콜백으로 경고만 숨기지 않는다.
- 새 화면/문구/게임 접근/설정 스키마 변경 없음. 기존 탭 고정 ID와 설정값 유지.
- 별도 빌드: `dotnet build src/DuckbillFisher.Plugin/DuckbillFisher.Plugin.csproj --no-restore -c Debug "-p:DalamudLibPath=${env:DALAMUD_HOME}/" "-p:OutputPath=${env:DUCKBILL_ROOT}/.cache/config-ui-build/"` → 경고 0/오류 0.
- `pwsh -NoLogo -NoProfile -File scripts/check-localization.ps1` → 한영 448키/형식 인자 일치. 테스트 추가/실행 없음.
- 0.1.30.0은 별도 빌드만 수행했고 수정은 0.1.31.0 정규 DLL에 포함했다. 사용자 새 언로드 확인 후 정규 빌드 경고·오류 0. 인게임에서는 경고 해제와 Dalamud 설정 버튼 → 메인 설정 탭, 기존 화면이 열렸을 때도 설정 탭으로 이동하는지 확인한다. [통합 빌드 기록](CHANGES.md#mvp-01-ui-refinement).
- 사용자 tmp_note.md는 읽기/수정/스테이징하지 않았다. 원격 게시/릴리스 없음.

## 목록·즐겨찾기 설정 영역 정리

날짜: 2026-10-16 · 정규 DLL 0.1.24.0 · 인게임 확인 대기

<a id="mvp-01-compact-controls--변경과-유지할-동작"></a>

### 변경과 유지할 동작

- 어종 목록은 검색과 두 열의 정렬/수집 필터를 상단에 둔다. 시간제·등급·즐겨찾기만·현재 지역만·먼바다 포함·수첩 포함은 `목록 필터` 접힘 영역으로 묶었다. 해당 영역에 적용 개수를 표시하고 마우스를 올리면 여섯 조건의 현재 값을 안내한다. 지역/확장팩은 기존 별도 선택 영역과 범위 밖 선택 안내를 유지한다.
- 새로 읽기/짧은 진단/전체 진단은 상세 진단 안에 모았다. 정상 목록 로드 문구와 수집 판정 도움말은 평상시 반복 표시하지 않으며 해당 안내 영역에서 확인한다. 미접속/저장 오류/목록 읽기 실패는 접힌 상태에서도 표시한다.
- 즐겨찾기 관리는 알림 켜기와 예약/발송 요약을 항상 표시한다. 다음 알림은 요약 툴팁으로 옮겼다. 대상·새 등록 자동 해제·분·채널·SE/미리 듣기·Toast는 `알림 설정`, 짧은 진단 복사는 `알림 진단`으로 묶었다. 팝업 체크 추가 뒤 미리 듣기 버튼의 위치도 효과음 옆으로 맞췄다.
- 즐겨찾기의 긴 안내는 표시 개수의 툴팁으로 옮겼다. 공통 어종 행/남은 시간/개별 분/삭제/발송 기록은 그대로 사용한다. 추가 스크롤 자식을 만들지 않는다.
- 접기/펼치기는 필터 변경이나 알림 설정 저장으로 취급하지 않는다. 검색/선택/필터/예약 상태를 초기화하지 않고 전체 행 재계산이나 예측을 추가하지 않는다. 새 문자열은 한영 리소스와 고정 ImGui ID를 사용한다.

<a id="mvp-01-compact-controls--실행한-검사와-미실행"></a>

### 실행한 검사와 미실행

- `pwsh -NoLogo -NoProfile -File scripts/check-localization.ps1`: 한영 387키/형식 인자 일치. `git diff --check` 통과.
- 초기 소스 수정은 사용자 요청으로 빌드하지 않고 커밋했다. 이후 사용자가 새로 `언로드 했음`을 확인하여 별도 빌드와 정규 빌드를 진행했다. 테스트는 요청이 없어 추가/실행하지 않았다.
- 별도 빌드: `dotnet build src/DuckbillFisher.Plugin/DuckbillFisher.Plugin.csproj --no-restore -c Debug "-p:DalamudLibPath=${env:DALAMUD_HOME}/" "-p:OutputPath=${env:DUCKBILL_ROOT}/.cache/toast-ui-build/"` 경고·오류 0.
- 정규 빌드: 위 명령에서 OutputPath 옵션을 제외하여 실행, 경고·오류 0. 한영 387키/형식 인자 검사도 다시 통과했다.
- 정규 산출물: 주 DLL 981504바이트/0.1.24.0, Core 39936바이트/1.0.0.0, ko 리소스 39424바이트/0.1.24.0. manifest DuckbillFisher/0.1.24.0/API 15 확인.
- 실제 창 크기/스크롤/언어 전환/팝업 화면은 미확인이다. 이후 DLL 교체에는 새 언로드 확인이 필요하다.

<a id="mvp-01-compact-controls--로드-후-대표-확인"></a>

### 로드 후 대표 확인

1. 목록에서 필터를 펼쳐 한 조건을 바꾸고 다시 접어도 결과/정렬/선택이 유지되며, 제목 적용 개수와 툴팁 값이 맞는지 확인한다. 현재 지역/지역·확장팩의 기존 교집합 정책은 유지되어야 한다.
2. 즐겨찾기 관리의 알림 설정을 열고 채널/분/SE/팝업을 바꾼 뒤 접어도 저장된 값이 유지되는지 확인한다. 설정 접기/언어 전환만으로 과거 알림이 재생되어서는 안 된다.
3. 작은 창과 큰 창에서 정렬/수집 선택, 즐겨찾기 행/개별 분/삭제, 진단 복사가 접근 가능한지 확인한다. 원치 않는 스크롤 초기화가 있으면 해당 화면과 짧은 진단만 받는다.

## 미끼 아이템 링크와 스킬·날씨 아이콘

날짜: 2026-10-16 · Plugin 0.1.10.0 · 대표 어종 링크/조건 아이콘 확인 통과

<a id="mvp-01-item-links-icons--동작과-경계"></a>

### 동작과 경계

- 상세 조건의 미끼·중간 생미끼는 순서 번호/아이콘/이름으로 표시한다. 아이콘이나 이름을 클릭하면 실제 NQ 게임 아이템 링크를 내 채팅창에 출력한다. 채팅의 링크를 누르면 게임 아이템 정보를 확인할 수 있다.
- 직감에 필요한 어획 대상도 아이콘/필요 수량/아이템 링크를 제공한다. 어획 달성 여부는 자동 추론하지 않는다.
- 낚아채기는 해당 Action 아이콘과 게임 시트 이름, 현재/직전 날씨는 각각 Weather 아이콘과 이름을 표시한다. 날씨 목록은 OR 조건임을 문구에 명시한다. 무제한 조건은 기존 안내를 유지한다.
- 링크는 공개 SeString.CreateItemLink(uint, bool, string)와 IChatGui.Print(SeString, tag)만 사용한다. 채팅 입력창 삽입·명령 실행·서버 채팅 전송·추가 네이티브 호출은 없다. 직접 아이템 창을 여는 공개 API는 확보하지 못해 게임 표준 채팅 링크 경로를 사용한다.
- 링크 클릭은 현재 세션과 함께 대기시켰다가 Framework.Update에서 처리한다. 로그아웃/캐릭터 변경 때 이전 요청은 실행하지 않는다. Dispose에서 구독과 대기를 해제한다.
- 아이콘 로드 실패 시 자리와 텍스트를 유지한다. 공유 게임 텍스처는 Dalamud 소유라 직접 해제하지 않는다.

<a id="mvp-01-item-links-icons--한섭-근거"></a>

### 한섭 근거

- 게임 2026.10.06.0000.0000, 설치 KR Dalamud 15.0.3.6의 Mono.Cecil 메타데이터와 Lumina 실제 시트를 조사했다. 게임 파일/캐릭터 메모리는 변경하지 않았다.
- 공개 API의 서명과 의미는 설치 Dalamud.dll/Dalamud.xml의 CreateItemLink 및 IChatGui.Print에서 확인했다. 원래 아이템 링크 payload와 이름을 사용한다.
- Action 4103=강력한 낚아채기/Icon 1115, 4179=섬세한 낚아채기/Icon 1116. 둘 다 ClassJob=18/IsPlayerAction=True다. 실행 시 Action 시트에서 이름과 아이콘을 읽고 직업/플레이어 스킬 조건을 확인한다. 이 ID를 동작 실행에 사용하지 않는다.
- 초기 10종 조건에 사용된 Weather는 1/2/3/4/5/7/8/14의 8종이며 아이콘/이름이 모두 존재한다. 미끼 경로와 직감 대상의 서로 다른 Item 15종도 이름/아이콘 누락이 0건이다.
- 아이콘 번호는 제품 코드에 고정하지 않는다. 실제 한섭 Item/Action/Weather 시트의 참조를 캐시한다. 조건 데이터와 예측 알고리즘은 변경하지 않았다.

<a id="mvp-01-item-links-icons--유지보수와-문자열"></a>

### 유지보수와 문자열

- FishingDetailView는 이름 배열 대신 ID/이름/아이콘이 함께 있는 참조를 보관한다. FishCatalog가 Framework에서 시트를 읽으며 Draw는 시트 조회나 링크 메시지 출력을 직접 하지 않는다.
- 조건 표현은 FishingConditionPanel, 명시적 링크 요청/게임 접근은 FishingItemLinkService로 분리했다. 기존 목록/수집 상태/예측의 책임은 유지한다.
- 한영 리소스와 고정 위젯 ID를 사용하며 표시 이름을 상태 판정에 사용하지 않는다. Item/Action/Weather 이름은 게임 클라이언트 언어를 따른다.
- 기본 짧은 진단은 늘리지 않았다. 이번 시각적 변경은 성공 여부와 필요한 화면만 확인한다.

<a id="mvp-01-item-links-icons--실행-결과"></a>

### 실행 결과

- 별도 경로 및 사용자 언로드 후 정규 Debug 빌드 경고·오류 0. 한영 리소스 181키/형식 인자 검사 통과.
- 실제 주 DLL 176128바이트/어셈블리 0.1.10.0, Core 25088바이트, ko 리소스 21504바이트, manifest 0.1.10.0/API 15 확인.
- 이번 구현에서 테스트를 추가/실행하지 않았다. 대표 어종의 채팅 링크/아이템 정보와 조건 아이콘은 아래 사용자 확인을 받았다. 한영 전환·로그아웃 중 링크 대기 요청 폐기·모든 참조 항목의 개별 확인은 별도 미검증이다.

<a id="mvp-01-item-links-icons--사용자-결과"></a>

### 사용자 결과

- 0.1.10.0 재로드 후 황금나비어 미끼 링크, 헬리코프리온 중간 생미끼 링크/날씨 아이콘, 넵토드래곤 직감 대상 링크의 확인을 요청했고 사용자가 ‘정상’으로 답했다.
- 요청한 대표 사용 흐름은 통과로 기록한다. 화면 캡처나 항목별 상세 로그는 추가로 요청하지 않는다. 정적 시트의 전체 참조 조사와 대표 어종의 실제 확인 범위를 구분한다.
- 이번 결과 반영은 문서만 변경했으며 DLL·빌드·테스트를 변경/실행하지 않았다.

<a id="mvp-01-item-links-icons--확인-순서"></a>

### 확인 순서

1. 같은 개발 DLL 경로로 0.1.10.0 로드. 상세 조건 어종만 켜고 황금나비어 선택 → 미끼 이름 또는 아이콘 클릭 → 내 채팅의 링크를 눌러 같은 아이템 정보가 표시되는지 확인.
2. 헬리코프리온(290)의 2단계 미끼/생미끼와 낚아채기·현재 작열파/직전 안개 또는 흐림 아이콘·이름을 확인한다. 중간 물고기도 같은 방식으로 링크가 열려야 한다.
3. 넵토드래곤(276)의 직감 필요 어획 이름/개수/아이콘과 링크를 확인한다. 한영 전환 후 선택은 유지되고 UI 문구만 바뀌어야 한다.
4. 이상이 없다면 짧은 성공 응답이면 충분하다. 문제가 있으면 해당 화면과 증상만 보내며 전체 진단은 요청하지 않는다.

## MVP-01 목록 행 요약

날짜: 2026-10-16 · Plugin 0.1.13.0 · 사용자 대표 확인 통과

<a id="mvp-01-list-summary--동작과-범위"></a>

### 동작과 범위

- 목록에서 상세 선택 없이 미끼·현재/다음 시간 창·주요 조건을 읽는다. 이름 / 수집 상태·낚시터 / 시간·날씨 창 / 미끼 경로 / 조건의 고정 5줄이다.
- 행 높이와 clipper 간격을 함께 변경했다. 아이콘은 3줄 높이로 제한하고 긴 문구는 열 경계에서 잘라 표시하며 마우스를 올리면 줄 전체를 감싼 툴팁으로 표시한다.
- 미끼는 실제 캐시 Item 이름을 쓴다. 단계는 `→`, 한 단계 안의 대체 선택지는 `(A / B)`로 보존한다. 아이템 링크 동작은 기존 상세 패널에 있다.
- ET 시간대·현재/직전 날씨·직감/전승록 필요·갈고리 낚시/루어·인내 사용 시 낚아채기를 확인된 값만 요약한다. 직감 달성/전승록 습득 여부나 낚을 준비 완료를 판정하지 않는다.
- 미끼/조건 자료가 없으면 미확인으로 표시한다. 먼바다는 해역 안내를 유지하고 일반 창 예측 미적용과 어종별 조건 미확인을 표시한다.
- 목록과 상세가 같은 시간 창 문구 생성 함수를 사용한다. UTC 현재 시각은 목록 렌더링마다 한 번 읽고, 기존 예측에서 남은 시간을 계산한다. 장기 예측/시트/파일 읽기를 렌더링에 추가하지 않았다.
- 정적 요약은 보이는 행부터 캐시하고 목록 참조/언어 변경 때 비운다. 언어 변경이 선택·검색·필터·수집 상태를 초기화하지 않는다.
- 원본 데이터/네이티브 접근/수집 로직/진단 형식은 변경하지 않았다. 현재 지역/F12 분류 필터는 이번 범위 밖이다.

- 상세 Patch를 이름 오른쪽의 전용 열에 우측 정렬하고 조건 하단의 중복 표시는 제거했다. 원본 패치가 없는 어종에는 값을 추측하지 않는다.
- 물고기의 눈 지원 문장을 별도 한 줄로 표시하지 않는다. 즐겨찾기/수집 상태와 같은 동작 줄의 작은 아이콘으로 표시하며, 미지원은 흐린 아이콘+사선, 지원/미지원과 기술 이름은 툴팁으로 제공한다. 목록에서는 제거했다.
- 생미끼/직감 대상은 이름 왼쪽·낚아채기/입질/ET 오른쪽의 한 행으로 묶는다. 긴 날씨/추가 기술/미확인 설명은 오른쪽 정보 아이콘 툴팁에 항목별로 표시한다. 기존 정보의 범위와 미확인 구분은 유지한다.
- 목록의 조건 정보 아이콘 툴팁을 문장 사이 구분점 대신 항목별 줄바꿈으로 변경했다. 미끼 경로 툴팁은 기존 순서/대안 표현을 유지한다.
- 공통 목록 첫 줄은 이름/등급과 수집 상태, 둘째 줄은 핀/위치와 출현 또는 종료 남은 시간이다. 목록의 물고기의 눈은 제거하고 직감 아이콘은 어류 아이콘 오른쪽 위 안에 배경을 둬 겹쳐 표시한다.
- 메인·간략·즐겨찾기 공통 행에서 지도 핀을 직접 누를 수 있다. 메인/간략은 현재 지역 필터 범위에 맞는 표시 낚시터를 사용한다. 위치 없음/캐릭터 없음은 비활성화하고 핀 클릭은 상세 선택/열기와 구분한다.
- 상세 출현의 남은 시간과 실제 시간 범위는 `종료 00:05:00 | 오늘 13:06 – 13:29`처럼 같은 줄에서 구분한다. 좁은 화면에서 잘리는 내용과 전체 현지 날짜는 툴팁으로 확인한다. 출현 상태/배경은 유지한다.

<a id="mvp-01-ui-alignment--유지보수와-경계"></a>

### 유지보수와 경계

- FishRowRenderer는 캐시된 어종/낚시터와 기존 FishingMapService만 사용한다. 클릭 시 Request로 전달하고 실제 지도 처리는 기존 Framework 어댑터가 수행한다. 새로운 네이티브 조회/게임 명령/입력은 없다.
- Pin 버튼은 행 내부의 별도 고정 ID이고, 그 위에서 발생한 클릭은 행 선택 결과에서 제외한다. 같은 위치에 보이는 어종 선택을 지도 동작으로 오해하지 않게 한다.
- 목록 높이는 공통 GetHeight로 계산한다. 넓은 행/간략 3줄, 좁은 메인 4줄이며 클리퍼/예정 이동/즐겨찾기 추가 설정 행 모두 같은 높이를 사용한다.
- 조건 옆 표시가 좁으면 잘린 정보는 툴팁으로 제공한다. 미끼의 낚아채기·입질·시간을 대상 어종에서 추측 복사하지 않는다. 기존 RelatedDetails 범위만 사용한다.
- 설정 schema v10/preferences/v8, 필터 공유/Unknown/수동 우선/알림 정책/예측 계산/데이터 버전은 바꾸지 않았다. 새 리소스 WindowInline은 문장 전체와 형식 인자를 한영으로 제공한다. UI 고정 ID 유지.

## 0.1.28.0 UI 피드백 반영

갱신: 2026-10-17 · 별도/정규 빌드·리소스 검사 통과 · 인게임 확인 대기

<a id="mvp-01-ui-feedback--사용자-결정과-변경"></a>

### 사용자 결정과 변경

- 세 창 구조는 유지한다. 사용자에게 필터 공유 범위를 질문했고, `메인 필터 전체 공유, 검색어·예정 범위는 별도`를 선택했다. 0.1.27.0의 독립 즐겨찾기 필터 정책을 대체한다.
- 메인과 간략은 `CatalogFilter`로 수집·지역·확장팩·현재 지역·등급·시간제·즐겨찾기·도감 포함 조건을 공유한다. 수동 우선/Unknown 구분은 기존 CollectionFilter를 사용한다. 간략은 기존처럼 열린 창→예정 창 순서이며 상시/예측 미확인/먼바다는 제외한다. 메인의 검색어·진단 체크·정렬 선택은 공유하지 않는다.
- 간략 창의 독립 즐겨찾기 체크를 제거하고 `메인 필터 적용`을 표시한다. 메인 필터를 공유한다는 툴팁과 기존 예정 분 설정을 제공한다. 표시 낚시터도 선택 지역에 맞추고, 외부 지역 예측 안내를 유지한다.
- 간략 창의 메인 열기 버튼을 실제 메인 Toggle에 연결했다. 새 창 생성이나 다른 창 닫기는 수행하지 않는다.
- 공통 목록 행은 폭이 글자 크기 36배 이상이면 3줄 가로 배치, 그보다 좁으면 기존 세로 배치(메인 5줄/간략 4줄)를 쓴다. 메인/즐겨찾기/간략의 클리퍼가 같은 높이 계산을 사용한다.
- 메인/간략에 `출현 예정으로 ↓`와 `맨 위로 ↑` 버튼을 추가했다. 메인은 현재 정렬에서 첫 예정 어종으로, 간략은 예정 섹션으로 스크롤한다. 예정 대상이 없으면 이동을 비활성화한다.
- 목록 직감 텍스트는 실제 직감 상태 아이콘으로 바꿨다. 물고기의 눈 지원 어종도 아이콘을 표시한다. 이는 지원/요구 조건이며 현재 버프 상태를 자동으로 관찰한 표시가 아니다.
- 상세 상단에 물고기의 눈 지원 여부, 출현 표시 아래에 접지 않은 보라색 직감 영역(대상·수량·지속 시간)을 둔다.
- 상세의 `시간·날씨 기준 · 개인 준비 조건 별도` 문장을 제거했다. 출현 중은 녹색 배경과 `출현 중`, 남은 시간으로 표시한다. 시각은 `오늘 13:06 – 13:29`, 날짜가 바뀌면 `오늘 23:50 → 내일 00:15` 형식이다. 전체 현지 날짜는 툴팁으로 확인한다. 예측 공식/지원 범위는 바꾸지 않았다.
- 생미끼의 전체 상세를 재귀적으로 펼치던 부분을 없앴다. 각 미끼/직감 대상에 연결된 자료가 있으면 낚아채기·입질·필요한 ET/날씨/기술만 짧게 표시한다. 중간 미끼 자료가 없으면 `낚아채기 정보 미확인`을 유지한다. 대상 어종 조건을 중간 미끼에 복사하지 않는다.
- 중복 `추가 정보`/추천 낚시터를 제거했다. 기존 낚시터 목록·지도 기능은 유지하며 조건 하단에는 `Patch 3.0` 형태로 출처 패치만 표시한다. 전승록 요구는 유지한다.
- 추가 피드백으로 즐겨찾기 관리의 공통 행 요약 별을 제거하고 N분 전 옆 삭제 별 버튼만 유지했다. 메인/간략의 즐겨찾기 표시와 별도 상세의 상태 변경 버튼은 유지한다.
- 한국어 리소스에서 `창`을 모두 제거했다. 시간은 출현/종료, UI는 화면, 채팅 영역은 채팅으로 표현하며 AGENTS에 용어 규칙을 추가했다. 게임 데이터의 고유 이름은 바꾸지 않는다.

- 상세 제목은 왼쪽 어류 아이콘, 오른쪽 어종 이름/Patch와 그 바로 아래 등급·즐겨찾기·수집 선택으로 구성한다. 조작 줄을 아이콘 아래 전체 폭에 두던 배치를 수정했다. 메인/독립 상세는 같은 컴포넌트를 사용한다.
- 낚시터 연결 누락 31행은 큰 배경 안내 영역 대신 작은 ‘예측 정보 없음’ 문구를 사용한다. 구체적인 누락 이유는 마우스 오버에서만 제공한다. 예측 미확인을 상시로 표시하지 않는다.
- 지도 버튼의 파랑 배경·금색 직접 그리기를 제거했다. 기존 UI 아이콘 글꼴의 지도+위치 표시(MapMarkedAlt), 평상시 투명 배경과 테마의 호버/누름 색상을 사용한다. 글자 라벨은 없다. 목록/간략/상세에 같은 버튼을 사용한다.
- 간략 상단의 ‘메인 필터 적용’ 글자를 제거했다. 한 줄 왼쪽에 출현 예정 이동/맨 위 이동, 오른쪽에 메인 화면 토글/간략 설정을 둔다. 맨 위 이동은 화살표 아이콘이며 기존 문구를 툴팁으로 유지한다. 필터 공유 설명은 설정 팝업에 유지한다.
- 시간·날씨 계산, 수집·수동 우선, 필터 저장, 알림 정책, 게임 접근, 원본 데이터는 변경하지 않았다.

### 인게임 확인 순서

## 0.1.34.0 실제 화면 피드백 반영

갱신: 2026-10-17 · 정규 빌드 완료 · 인게임 확인 대기

사용자는 도감 열기 버튼 정규 반영 전에 [사진 개선 제안](../../product/UI-UX-REDESIGN.md#사진-기반-개선-근거) 1~7번도 함께 진행하도록 승인했고 언로드 완료를 확인했다. 별도 빌드 후 이 작업에 대한 확인으로 정규 DLL을 교체했다. 새 화면 구조나 자동화는 도입하지 않았다.

<a id="mvp-01-ui-screenshot-polish--구현"></a>

### 구현

1. 미끼 경로는 상세의 전체 폭을 사용한다. 단계는 화살표, 같은 단계 대체 미끼는 /로 구분하고 폭이 부족하면 다음 묶음을 줄바꿈한다. 중간 어종 이름 옆에 낚아채기/입질, 공간이 되면 ET를 표시한다. 생략된 조건은 바로 옆 툴팁으로 제공한다. 아이템 링크 동작은 유지한다.
2. 날씨는 한 행에 직전 후보 / 후보 → 현재 후보 / 후보로 표시한다. 직전 제약이 없으면 현재 조건만 표시한다. 각 아이콘의 역할과 OR/전환 의미는 툴팁에 유지한다. 좁으면 묶음 단위로 줄바꿈한다.
3. 수집 선택은 어종 이름 바로 아래를 유지하고 현재 상태 문구/화살표에 필요한 폭만 사용한다. 수동 지정 시 복귀 버튼 공간을 예약한다.
4. 목록의 정보 아이콘은 내용이 잘리거나 다른 지역 예측 안내가 필요할 때 표시한다. 노출된 아이콘/문자는 자체 툴팁을 유지한다. 전승록/갈고리/루어도 토큰으로 표현해 정보 아이콘 제거로 요구 조건이 사라지지 않게 했다. 중간 어종 조건의 정보 버튼도 인접 배치하며 추가 정보가 있을 때만 표시한다.
5. 메인 상단은 검색 → 정렬/수집/필터/기본값 복원 → 결과 수/이동의 구조다. 반복 제목 줄을 제거하고 복원은 툴팁 있는 아이콘으로 상시 노출한다. 부족한 폭에서는 컨트롤 묶음이 줄바꿈한다. 간략 열기는 탭 바 우측 아이콘으로 옮겨 독립된 한 줄을 줄였다.
6. 세 화면의 배경 불투명도는 공통 0.94로 설정하고 기존 테마 색을 유지한다. 출현 중 행의 녹색 배경은 약하게 하고 왼쪽 표시선/남은 시간 강조를 병행한다. 상세 출현 배경도 채도를 낮췄다. 상태 문구는 유지한다.
7. 넓은 목록의 3줄 배치 기준을 폰트 36배에서 28배로 조정했다. 미끼는 실제 필요한 폭을 기준으로 최대 55%를 쓰고 조건을 옆에 배치한다. 좁은 메인 목록은 4줄, 좁은 간략 목록은 기존 3줄을 유지한다. 높이 산식은 렌더링/클리퍼/예정 이동에서 공유한다.

0.1.33.0의 [어류도감 열기 버튼](../../verification/catalog/GUIDE-OPEN.md)도 정규 0.1.34.0에 포함한다. 수집/수동 우선/필터 저장/예측 공식/알림 정책/원본 자료/게임 접근 계약은 이번 디자인 변경에서 바꾸지 않았다. 사진의 종료 1초 표본은 오류로 확정하지 않았으며 별도 재현이나 계산 변경을 수행하지 않았다.

- 0.1.26.0은 사용자 대표 확인을 통과했다. 이번 작업 중 큰 화면 구조는 먼저 질문하도록 지침을 추가했고, 사용자는 이후 최대 세 창 구성을 명시적으로 승인했다.
- 메인: 어종 목록/즐겨찾기 관리/설정. 어종 클릭은 같은 창 오른쪽 패널을 갱신한다.
- 간략: 즐겨찾기 기본, 현재 출현 중과 30분 이내 예정 표시. 전체 어종으로 전환하거나 예정 범위를 1~180분으로 변경 가능하다. 메인 필터/수집 숨김/알림 대상과 독립이다.
- 독립 상세: 간략 창에서 클릭한 어종만 표시한다. 인스턴스 하나를 재사용하며 메인 창을 열지 않는다. 각 창의 닫기는 다른 창의 정보 요청이 아니다.
- 메인 `간략 창 열기` 또는 `/duckbillfisher compact`로 간략 창을 연다. 간략 창의 목록 아이콘으로 메인을 열 수 있다. 새 명령은 플러그인 창 토글만 수행한다.

<a id="mvp-01-ui-ux-redesign--현재-코드에서-발견한-문제와-대응"></a>

### 현재 코드에서 발견한 문제와 대응

| 문제 | 구현한 대응 |
|---|---|
| 진단 탭이 즐겨찾기보다 먼저 노출, 언어/도움말이 항상 목록 공간 사용 | 메인 탭 순서를 목록/즐겨찾기/설정으로 변경. 언어/개발자 옵션/알림 설정/출처는 설정 탭으로 이동 |
| 상단 접는 영역이 길어져 목록 높이 감소 | 검색/정렬/수집/초기화는 상단 유지, 추가 필터는 팝업. 진단도 개발자 모드의 팝업으로 제공 |
| 숨겨진 진단 필터가 계속 적용될 가능성 | 개발자 모드 해제 시 확인 불가 행/상세 조건만 체크를 해제. 일반 필터는 유지 |
| 도감 안내가 일반 설명과 구분되지 않음 | 경고 아이콘·배경·동작 안내를 함께 표시. 기존 세션의 GuideState.Complete 뒤 사라짐 |
| 미끼/날씨/시간 문장 반복 | 공통 행에 게임 아이콘·시계·짧은 시작/종료 시간을 표시. 상세 이름과 의미는 툴팁/정보 아이콘에 제공 |
| 수집 버튼 3개와 자동/수동 결과 중복 | 현재 상태를 보여주는 메뉴 하나 + 수동일 때만 복귀 버튼. 자동 접미사는 제거하고 수동 접미사는 유지 |
| 즐겨찾기를 색상만으로 구분 | 빈 별/채운 별을 직접 그려 상태를 구분. 버튼 설명은 툴팁 |
| 상세 정보와 버튼 정렬 불일치 | 공통 FishDetailPanel: 제목/동작 → 출현 → 낚시터 → 조건. 조건은 이름/값 2열. 지도는 위치 옆 아이콘 |
| 즐겨찾기의 어종 클릭은 강조만 변경 | 같은 메인 창의 오른쪽 상세 패널에 연결. 개별 사전 분과 삭제는 행에서 유지 |
| 좁은 화면에서 긴 텍스트 넘침 | 행 폭 클리핑+툴팁, 조건 값 줄바꿈, 메인 최소 700×450/간략 300×260/상세 320×300. 실제 배율별 결과는 대기 |

조사 출처와 적용 이유는 [개편 문서](../../product/UI-UX-REDESIGN.md)의 근거 구역을 따른다. NN/g, Microsoft Fluent, W3C, Fish Tracker의 실제 문서를 조회했으며 외부 코드/에셋을 도입하지 않았다. 웹 원칙을 적용한 설계 판단이며 접근성 인증이나 인게임 시각 검증을 뜻하지 않는다.

<a id="mvp-01-ui-ux-redesign--구현-경계와-수명"></a>

### 구현 경계와 수명

- `FishRowRenderer`는 기존 목록/즐겨찾기 및 새 간략 창에 사용한다. 미끼 단계는 화살표, 같은 단계 대안은 괄호와 `/`, 직전→현재 날씨는 화살표와 툴팁으로 구분한다. 상세는 이전/현재를 별도 행으로 표시한다.
- 게임 아이콘은 기존 ITextureProvider를 사용하고 소유권을 가져오지 않는다. 실패하면 `?`와 이름 툴팁을 제공한다. 일반 상태 아이콘은 설치 Dalamud의 FontAwesome 및 별 도형을 사용한다.
- `FishDetailPanel`은 캐시된 데이터와 기존 preferences/지도/아이템 링크 요청만 사용한다. 자동 수집과 수동 우선순위·Unknown 구분은 그대로다. 상세 창은 세션 변경 시 선택을 비운다.
- `CompactFishObserver`는 창이 열려 있을 때 Framework에서 단조 시계 기준 1초 간격으로 기존 예측을 필터링한다. Draw에서 전체 검색/파일 읽기/장기 예측을 하지 않는다. 닫을 때 갱신 중지, 재개 때 오래된 표본 초기화, Dispose에서 이벤트 해제.
- 간략 정렬은 열린 창 종료순 → 예정 시작순, 동률 이름/ID. 상시/먼바다/예측 미확인 제외. 데이터 로딩/실패 상태와 빈 결과를 구분한다. 예측 경계의 화면 갱신 지연은 약 1초다.
- 설정 schema v9는 v1~v8을 허용한다. 언어·개발자 모드(기본 꺼짐)·간략 대상/분을 기존 Framework 저장 큐로 병합한다. 기존 v8의 자동 해제 꺼짐 선택을 덮어쓰지 않는다. 저장 실패 시 기존 snapshot/오류를 유지한다.
- preferences/v7에 InterfaceLanguage/DeveloperMode/CompactFavoritesOnly/CompactUpcomingMinutes를 추가했다. summary/v5, collection/v2, alerts/v6는 그대로다. 진단용 체크는 저장하지 않는다.
- UI 리소스 428키(한영). 창/탭/입력은 번역과 분리한 고정 ID. Core·예측 공식·네이티브 조회·등록 계약·알림 예약/전송은 수정하지 않았다. 런타임 HTTP 없음.

<a id="mvp-01-ui-ux-redesign--실행한-확인"></a>

### 실행한 확인

1. `dotnet build src/DuckbillFisher.Plugin/DuckbillFisher.Plugin.csproj --no-restore -c Debug "-p:DalamudLibPath=${env:DALAMUD_HOME}/" "-p:OutputPath=${env:DUCKBILL_ROOT}/.cache/ui-redesign-build/"`: 최종 경고 0/오류 0.
2. 첫 빌드의 ImGuiSelectableFlags.AllowOverlap 이름 불일치를 설치본의 AllowItemOverlap으로 수정했다. 최종 성공으로 첫 실패를 숨기지 않는다.
3. `pwsh -NoLogo -NoProfile -File scripts/check-localization.ps1`: 한영 428키/형식 인자 일치.
4. 사용자가 이번 작업 시작 때 언로드 완료/정규 교체 가능을 명시했다. 그 승인으로 정규 경로 `dotnet build` 실행: 경고 0/오류 0.
5. 정규 Plugin 0.1.27.0(1,019,392 bytes), Core 1.0.0.0(39,936 bytes), ko 리소스 0.1.27.0(43,520 bytes), manifest DuckbillFisher/API15 확인.
6. 최종 코드 리뷰: 설정 병합/기존 schema 보존, 세션 변경 선택 초기화, 화면 ID, 서비스 해제, 클리퍼 행 높이/좁은 열의 개별 시간 줄바꿈, 새 어종 선택 시 상세 스크롤 복귀, 진단 숨김, 한영 문자열과 diff 범위 확인. `git diff --check` 통과.
7. 테스트는 추가/실행하지 않았다. 인게임 로드/시각 결과는 아직 받지 않았다. 사용자 tmp_note.md는 읽기/수정/스테이징하지 않았다. 원격 게시/릴리스 없음.

<a id="mvp-01-ui-ux-redesign--인게임-대표-확인-순서"></a>

### 인게임 대표 확인 순서

1. 같은 개발 DLL 경로로 0.1.27.0 로드. 기본 탭이 목록/즐겨찾기/설정인지, 도감 조회 전 배너와 조회 완료 뒤 해제를 확인한다.
2. 목록 어종 선택 → 오른쪽 상세. 빈 별/채운 별, 수집 메뉴/수동 복귀, 아이템 링크/지도 핀과 미끼·날씨 툴팁 확인. 기존 필터/즐겨찾기/사전 분이 유지되는지 확인한다.
3. `간략 창 열기` → 메인 닫기 → 간략 어종 클릭. 독립 상세 하나가 열리고 다른 어종 클릭 시 내용만 바뀌는지 확인한다. 세 창을 동시에 열고 각각 닫아 본다.
4. 간략 창에 결과가 없으면 즐겨찾기 체크를 해제하거나 범위를 늘린다. 열린 창 종료순/예정 시작순과 메인 필터 독립, 재오픈 갱신을 확인한다.
5. 설정에서 English/한국어 전환과 개발자 모드 켜기/끄기. 창 선택/스크롤/수집 기록 보존, 껐을 때 진단 탭/체크 숨김 확인. 최소 크기와 평소 글자 배율에서 잘림 확인.

정상 여부와 문제가 있는 화면만 우선 받는다. 로그가 필요하면 개발자 도구를 켜고 목록의 짧은 진단을 받으며 전체 로그는 기본 요청하지 않는다.
