# 실제 화면 기반 UI 후속 제안

갱신: 2026-10-17 · 사용자 0.1.32.0 화면 기반 · 제안은 미구현/협의 대상

사용자는 어종 이름 아래 조작 줄·지도 아이콘·간략 도구 모음이 보이는 화면에 ‘좋다’고 답했다. 시각적 대표 확인으로 기록하며 모든 버튼·화면 크기·언어 조합의 기능 확인으로 확대하지 않는다. 이번에 승인된 구현은 연동 안내의 어류도감 열기 버튼이다.

## 다음 개선 후보

| 우선 | 화면의 관찰 | 제안과 적용 이유 |
|---|---|---|
| 1 | 미끼 단계마다 아래 화살표/행이 추가되어 긴 경로가 상세를 차지하고, 중간 어종의 스킬과 정보 버튼이 멀리 떨어져 있다. | 넓으면 가로 미끼 경로, 좁으면 줄바꿈. 각 미끼 이름 바로 옆에 낚아채기·입질을 붙여 관계를 명확히 한다. 정보 버튼은 해당 단계 옆으로 옮긴다. |
| 1 | 상세 날씨는 직전/현재를 세로로 나누고 ‘이 중 하나’를 반복한다. | ‘직전 후보 / 후보 → 현재 후보 / 후보’를 한 묶음으로 표시하고 상세 설명은 툴팁. OR/날씨 전환 의미는 유지한다. |
| 1 | 상세 수집 선택 상자가 남은 폭 전체를 차지한다. | 등급·별·수집은 이름 아래를 유지하되 수집 선택 폭을 실제 문구와 화살표에 맞춰 제한한다. 수동 해제 공간도 예약한다. |
| 2 | 목록마다 흰 정보 아이콘이 반복되어 미끼/날씨보다 강하게 눈에 띈다. | 아이콘/묶음 자체에 보조 툴팁을 제공하고 별도 정보 아이콘은 생략된 정보가 있을 때만 표시한다. 핵심 상태/오류는 숨기지 않는다. |
| 2 | 메인 상단은 검색·정렬·수집·필터·결과·이동이 여러 줄로 분리된다. | 검색 한 줄 + 정렬/수집/필터/복원 도구 모음으로 정리하고 결과 수와 이동을 묶는다. 좁은 폭에서는 규칙적으로 줄바꿈한다. |
| 2 | 목록과 상세의 여유 공간이 화면 폭에 따라 한쪽에 몰린다. | 넓은 목록에서는 미끼/조건을 한 줄의 두 묶음으로 정렬한다. 목록/상세 분할 폭 조절은 별도 협의할 후보이며 바로 도입하지 않는다. |
| 2 | 출현 중인 행이 많으면 녹색 면적이 커지고 배경 게임 텍스트가 상세에 비친다. | 녹색 채도를 낮추고 시간 강조/얇은 상태 선을 병행한다. 본문 배경 불투명도를 조금 높이는 안을 비교한다. |
| 확인 | 사진의 여러 출현 중 어종이 동시에 종료 00:00:01이며 상세에는 실제 시간 범위가 있다. | 한 프레임만으로 타이머 오류를 확정하지 않는다. 계속 유지되는지 확인한 뒤 표시 갱신을 따로 조사한다. 현재 작업에서 예측 공식을 바꾸지 않는다. |

권장 순서는 상세 미끼/날씨/조작 폭 정리 → 목록 정보 아이콘/상단 도구 모음 → 대비/공간 조절이다. 최대 세 화면 구조와 수집/알림/필터 정책을 유지한다. 주요 배치 변경은 사용자 답변 후 진행한다.

## 조회한 근거

- [NN/g 사용성 원칙](https://www.nngroup.com/articles/ten-usability-heuristics/), 2026-10-17 재조회: 불필요한 정보와 경쟁을 줄이고 상태를 보이게 하며 자연스러운 순서와 일관성을 유지한다. 상단 도구 모음/관련 미끼 정보 묶기/대비 조절의 근거다.
- [Fluent 툴팁 지침](https://fluent2.microsoft.design/components/web/react/core/tooltip/usage), 2026-10-17 재조회: 툴팁은 비필수 보조 정보에 한정하고 시스템 피드백은 숨기지 않는다. 반복 정보 아이콘 축소 후보에도 도감 상태/오류/핵심 출현 정보는 화면에 남긴다.
- 위 레이아웃과 우선순위는 자료의 특정 수치 규칙이 아니라 실제 사용자 화면에 적용한 설계 제안이다. 외부 코드/에셋 도입은 없다.
