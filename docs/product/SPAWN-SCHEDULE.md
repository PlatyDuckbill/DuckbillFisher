# 출현 일정표 기획안

작성: 2026-10-20 · **검토용 제안 / 플러그인 미구현 / 화면 구조 미합의**

> 즐겨찾기한 목표의 출현 구간을 같은 시간축에서 비교하고, 다음에 확인할 어종을 직접 고르는 화면.

- [직접 조작하는 HTML 시안](mockups/spawn-schedule.html) — 파일을 브라우저로 열면 된다. 설치·인터넷 연결이 필요 없다.
- 시안의 어종 A~J, 지역, 시각, 조건은 모두 **화면 설명용 가상 자료**다. 실제 게임 예측값이나 게임 화면이 아니다.
- 기존 기능은 [PRODUCT](PRODUCT.md), 후보의 배경은 [터주작 제안](TROPHY-FISHING-PROPOSALS.md)을 따른다. 아래 기본값과 배치는 구현 전에 합의할 제안이다.

## 1. 사용 흐름

| 순서 | 사용자 동작 | 화면에서 얻는 정보 |
|---|---|---|
| 1 | 메인의 `출현 일정표` 탭을 연다 | 즐겨찾기 중 지금부터 6시간 안의 시간제 일반 낚시 일정 |
| 2 | 같은 시간대의 막대를 비교한다 | 지금 출현 중인 목표, 곧 시작할 목표, 겹치는 출현 구간 |
| 3 | 관심 있는 막대를 누른다 | 해당 회차의 정확한 시작·종료, 길이, 다른 목표와 겹치는 시간 |
| 4 | `어종 상세`를 누른다 | 기존 독립 상세 화면에서 미끼·날씨·직감 선행 조건 확인 |
| 5 | 기간을 바꾸거나 검색한다 | 더 먼 일정 또는 특정 목표로 범위를 좁힘 |

핵심 질문은 **“A가 끝나기 전에 B도 시작하는가?”**다. 이동 경로, 준비 시간, 실제 어획 성공 여부는 사용자가 판단한다.

## 2. 추천 화면 구조

**메인에 새 탭 하나를 추가하고 일정표에는 가로 폭 전체를 사용한다.** 기존 오른쪽 어종 상세는 이 탭에 붙이지 않고, 막대 선택 요약을 아래에 둔다. 상세 버튼은 기존 독립 상세 한 개를 재사용한다.

```text
DuckbillFisher                                  [간이 목록] [타이머]
어종 목록 | 수집 현황 | 출현 일정표 | 즐겨찾기 관리 | 낚시 기록 | 설정
──────────────────────────────────────────────────────────────────
출현 일정표                          실제 시각 · PC 현지 시간 UTC+09:00
[이름·지역 검색                 ] [3시간] [6시간] [12시간] [24시간]
[✓ 수집한 어종 숨기기] [✓ 선택 구간과 겹침 강조]   일반 / 물고기의 눈
10/20 20:00 ─────────────────────────────────────── 10/21 02:30
                  지금 20:30 ↓
어종 / 지역          20:00     21:00     22:00     23:00 ...
가상 터주 A          ──[출현 중]──────────[예정]────────────────
가상 터주 B          ─────[선택]────────────[예정]──────────────
가상 터주 C · 직감   ─────────────[예정]────────────────────────
가상 터주 D          ──────│───────────────────────────────────
──────────────────────────────────────────────────────────────────
선택: 가상 터주 B · 예정 20:38~20:53 · 15분          [어종 상세]
출현까지 8분 / A와 10분, D와 1분 겹침
──────────────────────────────────────────────────────────────────
기간 내 출현 없음 (1)
조건 미확인 (1) / 상시 (1) / 일정표 미지원 (1)              [펼치기]
```

선택 막대는 테두리로 표시하고, 아래 요약에 해당 회차를 명시한다.

### 크기와 정보량

| 상황 | 추천 표현 |
|---|---|
| 기본 크기 | 현재 메인 기본 크기 980×680을 출발점으로 조정. 이 높이에서는 약 3~4행과 선택 요약을 우선하고, 높이를 늘리면 약 6~8행 표시. 실제 글꼴/배율에서 재조정 |
| 행이 많음 | 어종 행만 세로 스크롤. 시간 머리글과 왼쪽 이름을 유지하며 보이는 행 위주로 그리기 |
| 실제 가용 폭 800px 미만 | 같은 탭에서 `시간 목록`으로 자동 전환. 어종별 출현 회차를 시작·종료 텍스트로 표시 |
| 폭이 다시 넓어짐 | 시간축으로 복귀. 검색·기간·선택 회차는 유지 |
| UI 배율 변경 | 픽셀 수 자체보다 가용 폭/글자 폭으로 전환 판단. 기존 공통 UI 배율을 따름 |

좁은 폭에서도 시간을 읽을 수 있게 하는 것이 우선이다. 모바일 웹을 플러그인에 넣는 제안은 아니다. HTML의 `좁은 폭 보기`는 이 대체 표현을 비교하는 시안 전용 조작이다.

## 3. 대상과 필터

| 항목 | 첫 구현 추천 |
|---|---|
| 기본 대상 | 즐겨찾기한 일반 낚시 어종 전체. 터주 외 일반 어종도 즐겨찾기했다면 포함 |
| 메인 목록과 관계 | 메인 검색·지역·등급·시간제 필터와 독립. 메인에서 가려진 즐겨찾기도 일정표에서 찾을 수 있음 |
| 검색 | 일정표 안에서 이름·지역 검색. 이름 미식별 시 기존 ID 표시/검색 정책 활용 |
| 수집 | `수집한 어종 숨기기` 기본 ON. 최종 Caught만 제외하고 수집 Unknown은 남겨 `수집 미확인` 표시 |
| 기간 | 지금부터 실제 3·6·12·24시간, 기본 6시간 |
| 물고기의 눈 | 기존 세션 공통 ON/OFF를 공유. 전환하면 일정표와 기존 목록의 탐색 기준이 함께 바뀜을 툴팁에 명시 |
| 알림 | 일정표 검색·숨김·기간·물고기의 눈 전환은 알림 대상/기준을 바꾸지 않음. 기존 일반 예측 알림 유지 |
| 저장 제안 | 기간·수집 숨김은 공통 저장. 검색·선택 회차·겹침 강조는 세션 상태. 물고기의 눈은 기존 세션 정책 유지 |

앞서 말한 `미수집만 보기`는 여기서는 **수집한 어종 숨기기**로 구체화한다. 수집 미확인을 미수집으로 단정하지 않으면서 목록에서 확인할 수 있기 때문이다. 기존 알림의 ‘미수집만’ 정책과 구분한다.

## 4. 시간축과 막대

- 가로축은 **실제 시각 / PC 현지 시간**이다. 머리글에 날짜와 UTC 오프셋을 표시하고 자정을 넘으면 다음 날짜를 쓴다. 내부 저장·계산은 UTC, ET는 선택 요약의 보조 정보로만 구분해 표시한다.
- 표시 시작은 지금 직전의 30분 경계, 끝은 `지금 + 선택 기간`이다. 예를 들어 20:30에 6시간을 고르면 20:00~다음 날 02:30이다. 앞 여백은 진행 중인 막대와 현재선을 구분하기 위한 것이다. 과거 기록 조회 기능은 아니다.
- 진행 중인 회차는 화면 왼쪽에서 잘려도 유지한다. 좌우 끝을 넘는 막대는 화살표로 잘림을 알리고, 정확한 원래 시각을 요약/툴팁에 표시한다. 화면 밖 종료와 계산으로 종료를 모르는 상태는 구분한다.
- 어종 하나에 행 하나를 사용하고, 표시 범위에 걸치는 **여러 회차**를 같은 행에 그린다. 이미 끝난 회차만 있는 어종은 다음 상태로 재분류한다.
- 현재 시각은 세로선과 `지금 HH:mm`으로 표시한다. 기본은 현재를 따라가며 30분 경계를 넘을 때 축을 이동한다. 시각만 흐른다고 행을 매초 재정렬하지 않는다.
- 행 순서는 출현 중의 종료순 → 예정의 첫 시작순 → 이름/ID다. 초기 진입·대상/기준 변경 때 정렬하고, 사용 중에는 회차 종료 등 의미 있는 변화에 반영한다. 선택은 어종 ID와 회차 UTC로 유지하며 종료되면 `선택한 출현 종료`를 알린다.

### 시각 규칙

| 상태 | 표현 | 함께 제공할 텍스트 |
|---|---|---|
| 출현 중 | 녹색 막대 | `출현 중`, 종료까지 남은 시간 |
| 출현 예정 | 청색 막대 | `예정`, 시작·종료 |
| 선택 회차 | 막대 테두리와 `선택` 표식 | 하단에 어종·회차를 고정 표시 |
| 선택과 겹침 | 다른 행에서 실제 교집합 부분에 주황색 빗금 | 요약에 상대 어종과 교집합 시각·길이 |
| 직감 반영 | 어종 이름 옆 `직감` | 실제 직감 버프 관찰이 아닌 조건 예측 |
| 직감 지속 시간 가정 | 이름/요약의 `가정` | `직감 지속 시간 175초 가정`을 요약에 항상 표시 |
| 수집 Unknown | 이름 옆 `수집 미확인` | 미수집으로 표기하지 않음 |

색상만으로 상태를 구분하지 않는다. 기존 테마에서 읽을 수 있게 색·대비를 조정하고 상태명·테두리·빗금을 함께 쓴다.

### 짧은 구간과 긴 표시 기간

실제 1분 출현은 24시간 축에서 1px 미만이 될 수 있다. 막대 길이를 임의로 10분처럼 늘리지 않는다.

1. 실제 길이대로 그리되 화면상 3px 미만이면 **짧은 세로 표식**으로 대체하고 `짧은 구간` 툴팁을 제공한다.
2. 클릭 범위는 넓힐 수 있지만, 시각적 표식과 실제 지속 시간을 혼동시키지 않는다. 인접 표식이 겹치면 한 회차를 임의 선택하지 않고 후보 시각 목록을 제공한다.
3. 막대에 글자가 들어가지 않으면 글자를 생략한다. 정확한 시각은 툴팁과 선택 요약에서 읽는다.
4. 12·24시간은 일정의 분포를 보는 용도다. 자세히 볼 때는 3·6시간으로 줄인다. 첫 구현에 자유 확대/축소·드래그 이동·미니맵은 넣지 않는다.

## 5. 선택과 겹침의 의미

선택은 **어종 하나가 아니라 특정 출현 회차 하나**에 대응한다. 같은 어종의 두 번째 막대를 누르면 두 번째 회차의 시각으로 요약이 바뀐다.

예시: 고정 현재 시각 20:30, 아래는 모두 가상 자료다.

| 회차 | 출현 시각 | B 첫 회차를 선택했을 때 |
|---|---|---|
| A 첫 회차 | 20:20~20:48 | 20:38~20:48, 10분 겹침 |
| B 첫 회차 | 20:38~20:53 | 선택 회차 |
| D 첫 회차 | 20:45~20:46 | 20:45~20:46, 1분 겹침 |
| C 첫 회차 | 21:40~21:46 | 겹치지 않음 |

겹침은 반열린 구간 `[시작, 종료)`의 교집합으로 계산한다. A가 20:48에 끝나고 다른 회차가 20:48에 시작하면 겹치지 않는다. 화면에서 클릭하기 쉽게 넓힌 범위는 계산에 사용하지 않는다.

겹친다고 포기해야 한다거나, 겹치지 않으면 연속 어획할 수 있다는 뜻은 아니다. 첫 구현은 이동 시간·텔레포·직감 준비 시간을 빼거나 자동 추천하지 않는다. 선택한 어종 자신과의 비교는 제외하고, **현재 검색·숨김 조건으로 보이는 목표**끼리 비교했다고 명시한다.

## 6. 일정표에 막대로 그리지 않는 상태

시간축 아래에 상태별 접힘 구역을 둔다. 기본은 구역명과 개수만 표시하며 펼치면 어종·이유·상세 버튼을 제공한다.

| 구역 | 의미 | 표시 예 |
|---|---|---|
| 기간 내 출현 없음 | 조건은 계산 가능하지만 선택한 범위에 회차 없음 | `6시간 내 없음`과, 기존 30일 검색으로 확인된 경우에만 다음 출현 시각 |
| 조건 미확인 | 대상/선행 조건 부족 등으로 계산 불가 | 이유를 표시. 빈 일정이나 상시로 대체하지 않음 |
| 상시 | 현재 선택한 예측 기준에서 시간/날씨 제한 없음 | `상시`. 전체 폭 막대로 도배하지 않음. 물고기의 눈으로 바뀐 경우 기준도 표시 |
| 일정표 미지원 | 먼바다·작살 등 첫 구현의 일반 예측 대상 밖 | `먼바다 — 일정표 미지원` 등 범위 안내 |

30일 검색에서 못 찾은 경우도 ‘영구적으로 출현하지 않음’이라고 하지 않는다. 전체 계산 미완료·부분 실패·표시 상한 도달은 별도 `계산 중`/`일부 계산 미완료`로 남기며, `기간 내 없음`으로 바꾸지 않는다.

즐겨찾기 0종이면 `즐겨찾기한 어종이 없습니다`와 즐겨찾기 관리로 가는 동작을 제공한다. 검색·수집 숨김 때문에 0종이면 적용 조건을 안내하고 해당 조건만 해제할 수 있게 한다.

## 7. 실제 구현에서 필요한 작업

현재 `FishingForecast.Find`는 한 번에 현재/다음 구간 하나를 반환한다. 기존 계산을 재사용하더라도 **시간축만 그리면 끝나는 작업은 아니다.**

| 책임 | 구현 방향 제안 |
|---|---|
| Core | 같은 규칙으로 지정 UTC 범위의 구간을 열거하는 경로. 인접 구간 연결, 직감 선행 조건, 물고기의 눈, Unknown 의미 유지 |
| Plugin | 즐겨찾기/수집/자료 revision과 기간·기준으로 계산 요청 및 snapshot 관리 |
| UI | 준비된 행·구간 표시, 선택·툴팁·상세 열기 요청. Draw에서 장기 예측/파일 읽기 금지 |
| 시각 | 실제 시각의 흐름은 UTC, 처리 예산/요청 만료는 단조 시계. 시각 변경·절전 복귀 시 오래된 결과 재계획 |
| 수명 | 닫기·캐릭터 전환·자료 재로드·기준 변경 시 이전 요청 무효화. 오래된 결과를 현재 결과로 덮어쓰지 않음 |
| 부하 | 즐겨찾기 대상만 계산하고 여러 갱신에 나눠 처리. 변경 없는 결과 재사용. 행/회차를 자르면 상한 도달과 미완료를 노출 |
| 번역 | 확정 후 TextKey와 기본 영어·한국어 리소스 추가. ID와 상태 판정은 번역 문구와 분리 |

`Find`를 종료 시각 다음으로 계속 호출하는 방식을 바로 확정하지 않는다. 매번 30일 재검색하거나 직감 기준 시각을 바꿔 회차 경계가 달라질 수 있어, 범위 열거의 결과와 비용을 먼저 점검해야 한다. 구간 수/프레임 처리 예산의 실제 상한은 구현 조사에서 정하고 누락을 숨기지 않는다.

## 9. 검토할 결정과 완료 기준

실제 플러그인 착수 전에 아래 세 가지를 확인한다. **문서/HTML 제작 요청 자체를 화면 구조 승인으로 취급하지 않는다.**

1. **진입과 배치:** 메인 새 탭 + 전체 폭 시간축 + 아래 선택 요약으로 할지. 게임 중 계속 띄울 독립 화면이 필요한지.
2. **대상:** 즐겨찾기 전체를 메인 필터와 독립적으로 볼지. 수집한 어종 숨김을 기본 ON으로 할지.
3. **밀도:** 기본 6시간, 기본 높이 약 3~4행/확장 시 6~8행이 적절한지. 좁으면 시간 목록으로 바꾸는지.

합의 후 구현 결과의 대표 확인 기준은 다음과 같다. 자동 테스트 추가/실행은 사용자 명시 요청 때만 하며, 아래는 향후 직접 확인할 동작 기준이다.

- 같은 UTC·예측 기준에서 기존 상세와 일정표 해당 회차의 시작·종료가 일치한다.
- 동일 어종의 여러 회차·현재 진행 중·자정 넘김·짧은 회차가 구분된다.
- B 예시 선택에서 A 10분·D 1분의 교집합을 확인하고, 단순 끝/시작 접점은 겹침으로 세지 않는다.
- Unknown을 출현 없음/미수집으로 표시하지 않고, 직감 175초 가정 안내를 숨기지 않는다.
- 기간·검색·수집 숨김·물고기의 눈 변경 시 선택과 표시 상태가 설명한 규칙을 따른다.
- 좁은 폭·한영·기존 UI 배율에서도 시각과 선택 정보에 접근할 수 있다.
- 닫기·캐릭터 전환·절전/시각 변경에서 오래된 결과나 중복 요청이 남지 않는다.

### HTML 시안에서 확인할 수 있는 것

기간 전환, 검색, 수집 숨김, 물고기의 눈 가상 전환, 회차 선택, 교집합 강조, 접힘 상태 목록, 좁은 폭 시간 목록을 조작할 수 있다. `어종 상세`는 가상 자료 안내를 열며 게임 기능을 호출하지 않는다. 상단 기존 탭 이름은 위치를 보여주는 비활성 표식이다.

고정 시각을 사용하므로 실제 시간은 흐르지 않는다. 실제 예측 계산·게임 아이콘·ET 계산·자동 축 이동·가상화·프레임 예산·겹친 클릭 후보 선택은 이 시안으로 검증하지 않는다. 브라우저 글꼴/툴팁/여백은 ImGui와 달라 실기에서 조정해야 한다. **시안은 배치와 동선의 검토 자료이며 완성된 플러그인 화면을 보장하지 않는다.**

HTML은 전체 구성을 검토하기 쉽게 세로로 펼친 높이를 사용한다. 실제 메인 높이에 맞춘 일정표 스크롤·선택 요약 고정 배치는 구현 시 조정한다.

작성 시 문서 검사·JavaScript 문법·로컬 HTTP 응답과 파일 일치를 확인했다. 사용 가능한 브라우저가 없어 실제 렌더링·클릭 동작 확인은 대기다. 플러그인 빌드·테스트·게임 실기는 수행하지 않았다.
