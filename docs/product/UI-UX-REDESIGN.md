# UI 구성과 사용성 기준

현재 사용자 동작은 [PRODUCT](PRODUCT.md#화면과-상호작용), 구현 책임은 [ARCHITECTURE](../development/ARCHITECTURE.md)를 따른다. 이 문서는 화면 합의와 조사 근거를 유지한다. 과거의 최대 세 화면/독립 필터 설명을 현재 제약으로 적용하지 않는다.

## UI V2 디자인 방향 비교 (2026-11-06 · 미승인)

사용자가 기존 화면 코드를 보존하면서 디자인 버전을 선택하는 방식의 가능성을 물었고, 이어 시각적 방향을 요청했다. [세 가지 비교 시안](mockups/design-directions.html)은 같은 가상 어종6종과 정보로 메인 목록/상세의 분위기를 비교한다. 첫 안만 보인다는 사용자 피드백 뒤 전환 UI에 의존하지 않고 세 안을 제목과 함께 위아래로 모두 펼치도록 바꿨다. 일반 브라우저에서도 세 안을 볼 수 있다. 비교 시안 전체의 화면 구조는 미승인이며, 이후 아래 테마5종의 구현을 진행했다.

- **정돈된 클래식:** 기존 가로 메뉴·목록 왼쪽/상세 오른쪽의 동선을 유지하고, 차콜/중성색·절제한 금빛 강조·선택 행·정보 구역을 정리한다. 기본 권고안이다.
- **항해 도구:** 남청색/청록 강조와 분리된 목록 행으로 작업 화면 느낌을 낸다. 왼쪽 세로 메뉴와 상세에 더 넓은 폭을 주는 구조 차이가 있으며 별도 승인이 필요하다.
- **도감 노트:** 따뜻한 중성색/차분한 녹색·넉넉한 간격으로 수집품을 살펴보는 느낌이다. 넓은 폭의 어종을2열 타일로 바꾸는 구조 차이는 미승인이다. 실제 어종 아이콘은 기존 게임 텍스처 사용을 전제로 하며 시안은 공통 대체 아이콘이다.

각 안에서 어종 선택·즐겨찾기·검색·수집 숨김·납품 한 행과 동작 안내를 확인했다.320/736/1024px의3개 방향에서 가로 넘침 없음·JavaScript 오류 없음과 밝은/어두운 대표 렌더링을 확인했다. 화면 폭/목록 간격은 비교용 조절이다. 가상 상태/수치는 제품 동작 검증이 아니며 실제 UI 전체 개편·신규 사이드 메뉴/타일·어종 상세 확장의 승인을 대신하지 않는다. 이 HTML 시안 확인에서는 제품 빌드·테스트·게임 실기를 하지 않았다.

## 현재 지원 테마와 페이퍼 마감 (2026-11-06)

사용자 결정으로 설정에는 **기존 · Dalamud / 그라파이트 / 페이퍼**만 남긴다. 터미널·오로라·블루프린트는 선택지뿐 아니라 enum·팔레트·행 장식·한영 이름/도움말 코드를 제거했다. 기존 ID0/1/2는 유지하며 폐기된3/4/5와 알 수 없는 숫자는 기존 디자인으로 정규화한다. 설정 로드와 공통 백업 복원에 같은 정규화를 사용하고 다른 설정은 보존한다.

- 두 테마는 같은 메뉴 높이/좌우 분할·행 규격·정렬된 조건·좁은 폭의 한 열 전환·내부 탭/필터/프리셋 윤곽·역할색 규칙을 공유한다. 기존 Dalamud 디자인은 별도 선택지이며 전역 간격/배율/게임 판정에는 관여하지 않는다.
- 페이퍼는 목록 `#EEECE5`·상세 `#FAF9F4`·입력 `#FFFFFF`·버튼 `#E0E4DC`, 본문 `#2A342F`·보조 `#59665F`·윤곽 `#87958D`를 사용한다. 선택은 옅은 청록 `#DBE8E1`·누름은 `#C4D8CF`이며 큰 색면 대신 어두운 청록/황토/자주/파랑의 제목·아이콘·핵심 값을 사용한다. 밝은 메뉴 띠 위 활성 탭은 아이보리와 황토색 표시로 구분한다.
- 그라파이트와 페이퍼는 그리기 중 등록 화면의 BgAlpha를1로 맞추고 finally에서 기존 값을 복원한다. 흰 바탕의 글자/조작부가 게임 배경에 묻히지 않도록 하며 원래 디자인/저장된 화면 설정에는 적용하지 않는다. 수집/일정 그래프도 같은 크기·의미의 채움/윤곽 규칙과 밝고 어두운 전용 상태색을 사용한다.
- 빌드·오프라인 대표 렌더와 실제 게임 확인은 [현재 후보](../verification/catalog/UI.md#지원-테마-정리와-페이퍼-마감-개발본-2026-11-06)로 구분한다. 과거 다섯 테마의 제작/확인 기록은 아래에 보존하며 현재 지원 목록이 아니다.

## 디자인 테마5종 개발본 (2026-11-06)

이 절은 초기 구현 기록이다. 현재 지원 목록과 제거된 코드의 처리 방침은 위 절을 따른다.

사용자는 첫 V2의 장식과 복귀 버튼이 평가를 방해한다고 보고했고, 메인·캐스팅 타이머를 포함한5가지 테마와 설정에서의 변경을 요청했다. 이후 단일 톤의 가독성과 낮은 공간 효율성을 지적해, 그라파이트의 색 구분을 유지하면서 전역 크기/간격 덮어쓰기와 큰 제목·타이머 카드를 제거했다. 그라파이트는 후속 승인으로 아래 목록/상세 내부 배치를 바꿨으며 나머지는 기존 표시 규격을 따른다. 가로 메뉴·좌우 목록/상세와 기능별 조작 흐름은 유지하며 초기 V2 별도 화면·안내줄·복귀 버튼과 v1/v2 명령은 제거했다.

| 설정 선택지 | 색과 모양 |
|---|---|
| 01 그라파이트 | 차콜의 표면 명암·어종별 묶음·선택면과 안쪽 강조선 |
| 02 페이퍼 | 밝은 종이색·잉크색·괘선 |
| 03 터미널 | 검정·라임·각진 외곽선 |
| 04 오로라 | 자주·연보라·둥근 목록 행 |
| 05 블루프린트 | 짙은 파랑·청록·직각 외곽선 |

- `설정 → 화면 설정 → 테마`에서 바꾸며 기본은 ‘기존 · Dalamud 테마’다.5종은 추가 선택지다. 메인/타이머/보조 화면/팝업과 제목줄에 함께 적용한다. 화면 안에는 복귀용 버튼/추가 헤더를 두지 않는다.
- 선택은 기존 Framework 설정 큐를 통해 저장하며 재로드·언어/캐릭터 전환에도 유지한다. schema26의 선택 필드 `Theme`를 백업에도 포함한다. 이전 설정/백업의 누락·알 수 없는 값은 기존 디자인으로 정규화하며 다른 설정을 보존한다. 화면 위치/크기와 선택 데이터·기존 좌우 분할 폭을 유지한다.
- 새5종의 전역 스타일은 활성 Dalamud의 여백·글자/행 간격과 기존 UI 배율을 사용한다. 그라파이트는 후속 피드백으로 조작부의 프레임 윤곽을 추가하고 구역 제목·상태·목록 행을 아래와 같이 다듬었다. 타이머는 기존 상태·경과 한 줄이며 별도 제목 높이·확대 숫자·타이머 카드/장식 눈금은 없다. 설정의 테마 설명은 선택지 툴팁에 둔다. 실제 표시량과 전체 패널의 줄바꿈은 같은 폭/높이/배율에서 확인 대기다.
- 밝은 페이퍼에서는 상태 글자의 색을 더 짙게 보정한다. 새 테마의 수집 배지는 수집됨만 초록, 미수집/미확인은 중성색으로 표시하며 실제 상태 문구를 유지한다.
- 사용자 지시로 스테이징·커밋·게시하지 않는다. 실제 게임에서의 배율·폭·테마/저장 확인은 [검증 기록](../verification/catalog/UI.md#디자인-테마5종-개발본-2026-11-06)을 따른다.

### 그라파이트 가독성 개선 (2026-11-06)

- 후속 상단 마감은 기존 높이 안에서 짙은 중성 회색 명암 띠와 밝은 은회색 선택 탭 `#656D69`를 사용한다. 비선택 탭은 투명하게 두고 활성 탭에만 밝은 상단 가장자리와 금빛 아이콘/밑줄 `#EAD4A3`를 넣는다. 앞선 파란 선택면의 변화가 약하고 전체가 푸르다는 피드백을 반영했다. 메뉴 아이콘은 기존 예약 폭 안에서88%이며 오른쪽 간이 목록/캐스팅 타이머는 윤곽 버튼이다. 메뉴 순서·ID·스크롤/키보드 동작·본문 배치와 다른 테마는 바꾸지 않는다.
- 네 장의 후속 캡처와 사용자 승인으로 차콜/은회색 방향을 반영했다. 푸른 기를 줄이는 후속 마감으로 목록 `#161819`·상세/화면 바탕 `#242627`·버튼 `#343738`·윤곽 `#626769`, 본문 `#F0EFE9`·보조 `#AAB0B3`·링크 강조 `#A3C6E2`를 사용한다. 일반 선택면 `#3B3F40`·호버 `#303536`·누름 `#4A5051`은 중성 회색이며 입력란 `#171A1E`는 버튼보다 어둡다. 기존 좌우 폭·정보 위치·글자/버튼 크기·간격은 유지한다.
- 일반 클릭 링크와 얇은 선택 표시는 낮은 채도의 파랑, 미끼/생미끼·직감 선행 경로의 이름은 황토색 `#DCC393`, 출현 정보는 파랑, 출현 중/어획/수집 완료는 초록, 주의/중첩은 주황, 실패/미끼 부족은 붉은색, 즐겨찾기는 금색이다. 미수집을 실패색으로 표시하지 않는다. 공통 `UiThemeColors`를 추천/일정표/어종 행/직감 조건/상세 예측/타이머·기록/안내에 연결한다. 다른 테마의 색감은 유지한다.
- 중성 마감 뒤 색을 조금 더 요청한 피드백은 작은 면적의 역할색으로 반영했다. 위치/지도는 청록 `#9ABCB4`, 미끼/확인된 최소 획득력은 모래색, 직감/전승록/확인된 소장품 납품 안내는 라벤더 `#BCB0D2`, 시간/출현은 파랑이다. 상세 구역 제목과 구분선의 짧은 시작 부분·지도 아이콘·핵심 값에 적용하고 바탕/선택면은 중성 회색으로 둔다. 상단 비선택 아이콘은 탐색(청록)·준비/즐겨찾기(모래색)·일정(파랑)·기록/수집(라벤더)으로 낮은 채도로 구분하며 활성 메뉴의 실버/금빛 표시는 유지한다. 타이머 직감 준비 버튼도 라벤더로 연결하되 실제 활성/완료·주의·실패의 상태색과 미확인 회색은 유지한다. 배치·높이·표시량·동작에는 변화가 없다.
- 그라파이트는 메인·독립 상세·타이머 등 플러그인 화면을 그리는 동안 BgAlpha=1로 맞춘다. UiScale에서 기존 각 화면의 값을 보관하고 finally에서 복원하며 저장 설정은 바꾸지 않는다. 나머지 테마의 불투명도에는 적용하지 않는다. 지도 보조 아이콘과 타이머 미끼/세션 문장은 보조색으로 낮추고 시전 경과 줄은 본문색으로 유지한다.
- 테마별 표시량 차이를 없애기 위해 목록의 넓은 행 기준을 모두 글자 크기×21로 통일했다. 기존 그라파이트의 조밀한 기준을 공통으로 사용하며 행 높이 계산·아이콘 크기·폭/배율이 같으면 같은 줄 수를 사용한다. 큰 카드/추가 헤더·전역 여백 증가는 없다.
- 수집 표의 내부 선을 조작부 윤곽보다 약하게 하고 클릭 가능한 수집 막대에만 호버 윤곽을 표시한다. 먼바다에서 고른 항로 셀과 출항편 상세 제목은 같은 선택 강조색을 사용하며 기존 두 항로 열·선택/관찰의 분리는 유지한다.
- 출현 예정/출현 중의 기존 상태 줄에만 파랑/청록이 옅게 사라지는 배경과 얇은 왼쪽 선을 추가했다. 새 카드/패딩/추가 높이 없이 기존 글자 높이와 줄바꿈을 사용한다. 상시·예측 미확인·검색 기간 내 없음은 중성색으로 두고 상태 면을 칠하지 않는다.
- 수집 막대는 기존 외곽 높이 안에서 숫자와 하단 채움선을 나눠 글자가 채움색 위에 겹치지 않게 했다. 부분 수집은 파랑, 완료는 초록과 체크 표시다. 전체 수·비율·미확인 계산, 클릭과 툴팁은 유지한다.
- 일정표는 출현 중을 채운 막대, 예정은 윤곽선 막대, 선택은 밝은 외곽/왼쪽 선, 중첩은 주황 빗금으로 구분한다. 배경·격자·현재 시각선의 강도를 나누며 동일한 UTC 좌표/출현 조건을 사용한다. 타이머 본문은 기존 상태·경과 한 줄이며 유지 기록/활성 버프에는 역할별 색을 쓴다.

### 그라파이트 목록·상세 내부 재배치 (2026-11-06)

사용자는 내부 재배치 개발본을 캡처한 뒤 기존 디자인이 더 안정적이며 상태 줄바꿈·정렬·청회색 톤·클릭 구분이 나빠졌다고 보고했다. 이에 처음40:60·큰 요약 면·조건 네 구획을 철회하고 아래 표시 규칙으로 수정했다. [이전 배치 비교안](mockups/graphite-layouts.html)과 [일반 브라우저용 비교안](mockups/graphite-layouts-preview.html)은 현재 구현의 미리보기가 아니다. 좌우 동선은 유지한다.

- 어종 목록과 즐겨찾기는 기존 분할 표 ID·초기1.15:1 비율·저장된 폭과 드래그 조절을 사용한다. 처음40:60으로 목록을 좁히지 않는다.
- 일반 목록 행은 큰 채움 면 대신 얇은 아래 선으로 구분한다. 선택/호버에만 면을 표시하며 선택은 안쪽의 짧은 강조선 하나다. 즐겨찾기는 어종 정보와 개별 알림 입력을 같은 선택 범위로 그리되 입력은 독립 조작이다. Selectable의 확장된 클릭 사각형 대신 실제 행 원점/높이를 사용한다.
- 목록 아이콘은2줄 높이를 유지한다. 그라파이트의3/4줄 전환 폭은 글자 크기×21로 줄여 보통 폭의 조건을 같은 줄에 담고 좁으면4줄로 표시한다. 넘치는 토큰의 툴팁과 전체 조건은 유지한다. 알림 입력은 한영 라벨의 실제 폭으로1/2줄을 결정한다.
- 상세 상단은 기존 이름/조작·출현·위치의 읽는 순서를 사용하며 큰 요약 면을 두지 않는다. 구역 제목은 보조 글자와 옆의 얇은 선이다. 출현 상태는 좁은 열 없이 전폭에 표시하고 남은 시간은 실측해 옆 또는 다음 줄, 날짜/구간은 별도 보조 줄로 둔다. 일반/물고기의 눈 비교·미확인과 직감 예측 안내는 생략하지 않는다.
- 조건은 미끼 경로/찾기 아래 라벨·값을 같은 축에 정렬한다. 라벨 너비와 값8글자 공간을 확보할 수 없으면 한 열에서 라벨 위/값 아래로 바꾼다. 낚아채기는 아이콘 옆에 기술 이름도 표시하고 필수 기술은 해당할 때만 표시한다. 직감의 보라색 채움·외곽선은 없애며 고정 선행 조건·전승록·하단 메모/관리는 유지한다.
- 버튼·아이콘 버튼·체크/입력·콤보는 프레임 윤곽과 구분된 바탕을 사용한다. 프리셋 적용 행은 윤곽/적용 화살표를 가진 버튼이며 삭제는 별도 버튼이다. 클릭 가능한 미끼·관련 어종 이름에는 강조색과 밑줄을 표시한다. 명시 클릭의 지도/미끼 찾기/상세 열기 범위는 유지한다.
- 이중/삼중은 둘 다 미확인이면 반복하지 않고 한 번만 표시한다. 수량이 있는 기술에만 단위를 붙여 `2마리 이상`·범위·미확인을 구분한다. 이 문구 수정은 모든 테마에 적용한다.
- 후속 요청으로 **최소 획득력350종·소장품 납품원77종·단골거래12명/54개 NPC-어종 구간**을 개발본에 연결했다. 최소 획득력은 조건의 한 행이며 상세 조건이 없는29종도 독립 표시한다. 납품은 `소장품 납품원 · 소장가치 …` 또는 `NPC 이름 · 소장가치 …` 한 행이고 좁으면 자연스럽게 줄바꿈한다. 도시/마을·보상표·직접 입력은 두지 않는다. 공개된 어획 최소 획득력과 복수 수량 보장 임계값을 혼동하지 않는다.
- 즐겨찾기/출현 알림 설정/발송 기록의 내부 탭은 활성 면과 강조색 밑줄로 현재 선택을 표시한다. 기존 탭 ID·발송 기록/설정 동작은 유지한다. 수량은 일반26종에 먼바다259종을 보강했으며 좁은 폭에서는 기술명과 수량을 묶어 이중/삼중 단위로 줄바꿈한다. [자료 근거·잔여](../development/DATA-SOURCES.md#최소-획득력납품-구간수량-확장-2026-11-06)를 따른다.
- 표시 재설계는 그라파이트에만 적용하고 기존 테마와 타이머의 규격을 유지한다. [오프라인 렌더링 범위·실기 확인 항목](../verification/catalog/UI.md#그라파이트-목록상세-내부-재배치-개발본-2026-11-06)은 별도로 기록한다.

## 6개 화면 심층 검토 (2026-11-06)

사용자 제공 일정표·즐겨찾기·어종 목록/상세·수집 현황·먼바다·타이머 캡처와 당시 코드를 대조했다. 캡처의 정확한 DLL/테마 설정은 식별할 수 없으며 코드의 수치와 캡처 관찰을 구분한다. 시전/입질/승선 중, 호버/키보드 포커스와 언어/폭 전환은 관찰하지 않았다. 조사 자체는 제품 코드를 바꾸지 않았으며, 이후 사용자가 추천한3가지 동선과 위임한 시각 개선을 승인해 아래 범위만 개발본에 반영했다. 그 밖의 내용은 당시 검토 기록이며 현재 작업은 ROADMAP의 정리된 TODO만 따른다.

### 확인한 원인 (수정 전)

- `UiThemeScope`는 같은 `active`를 Header/HeaderActive/TabActive/TextSelectedBg에 사용한다. 선택 행·접힘 제목·메뉴가 비슷한 면적으로 강조되는 공통 원인이다. 팔레트와 별도로 선택 행/활성 메뉴/접힘 제목/보조 버튼의 표현을 구분해야 한다.
- 수정 전 그라파이트의 불투명 원본 색으로 계산한 대비는 주 글자/패널14.15:1, 보조 글자/패널7.51:1, 주 글자/선택면5.33:1, 보조 글자/선택면2.83:1이다. 당시 선택면은 Field와 Accent를30% 혼합한 RGB82/103/131이다. 캡처 픽셀 측정/접근성 인증 결과는 아니며 투명도/배경/실제 렌더링의 추가 확인이 필요하다. 일반 글자4.5:1, 의미 있는 조작/상태 단서3:1은 [W3C 글자 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)·[비문자 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)를 설계 참고로 삼는다. 장식 구분선까지 모두 강하게 만들라는 뜻은 아니다.
- `FishRowRenderer.IsWide`는 폭이 글자 크기×23 이상인지로3/4줄을 결정하고, 좁은 목록에서는 아이콘도2줄 높이에서3줄 높이로 늘린다. 패널 폭 변화가 행 높이와 아이콘/텍스트 가용 폭을 동시에 바꾼다. 캡처3의 큰 아이콘/낮은 행 밀도와 관련된 구현이며 당시 실제 배율/임계값 통과 여부는 미확인이다. 아이콘 크기를 줄 수와 분리하는 안부터 평가한다.
- `CollectionProgressPanel`은 현재 펼친 행 수와 별개로 가용 높이70%와20줄 중 작은 값을 표 높이로 잡는다. 캡처4의 지역 표 아래 빈 공간과 먼바다 구역의 하단 배치에 영향을 준다. 펼친 행 수에 맞추되 최대 높이에서 스크롤하는 안이 공간 회수 후보이다.
- `MainWindow`는 간이 목록/타이머 바로가기의 글자+아이콘 폭을 먼저 확보하고 남은 폭에 탭 스크롤을 적용한다. 캡처의 설정/메뉴 넘침을 다룰 때는 보조 바로가기의 폭별 축약을 검토할 수 있다. 전체 메뉴를 재구성할 필요가 있다는 근거는 아니다.
- `FishDetailPanel`은 개인 기록 접힘을 출현/위치/조건보다 먼저 그리고, 일반/물고기의 눈 예측이 다를 때만 두 영역을 그린다. 캡처3에서는 보조 관리 영역과 두 예측이 미끼/낚아채기보다 먼저 시선을 차지한다. 비교 정보는 유지하며 주 예측과 보조 비교의 비중을 나누는 안을 검토한다.

### 승인해 반영한 범위

- 상세의 메모·캐스팅 타이머 관리를 출현/낚시터/조건 아래로 옮겼다. 기존 상세 패널을 공유하는 메인·즐겨찾기·별도/비교 상세 모두 같으며 초안/펼침 ID/저장 동작은 유지한다. 일반/물고기의 눈 비교 정보의 구성은 바꾸지 않았다.
- 즐겨찾기 알림 시간 입력은 각 행에 유지한다. 선택이 없고 현재 검색 결과에 상세 가능한 어종이 있으면 첫 항목을 메모리에서 선택한다. 기존 선택은 검색·언어/테마 변경에 유지하며 해당 즐겨찾기를 제거하면 남은 첫 항목으로 이어간다. 캐릭터 세션이 바뀌면 이전 선택/캐시를 비우고 새 목록에서 선택한다. 빈 목록/아직 상세가 없는 행을 억지로 채우거나 선택을 설정에 저장하지 않는다.
- 선택면은 Surface/Accent10% 혼합, 메뉴는 낮은 면과 밑줄, 접힘 제목은 공통 `UiWidgets.Disclosure`의 중성 면으로 구분했다. 상단 보조 바로가기는 배경 강조를 줄였으며 이름·크기·동작은 유지한다. 기존/새5종 모두 간격/타이머 크기를 덮어쓰지 않는다.
- 당시 청회색 그라파이트의 보조 글자 대비는 불투명 코드 색 기준 선택면6.03:1·호버6.34:1이었다. 현재 무채색 팔레트는 패널6.92:1·선택5.57:1·호버5.91:1이다. 다른4종의 기존 선택/호버 조합도 계산상4.5:1 이상이다. 실제 픽셀/배경/접근성 인증 결과가 아니다.
- 목록 아이콘은 폭과 줄 수에 무관하게2줄 높이를 사용한다. 좁은 목록의4줄 정보 표시는 유지해 조건을 임의로 숨기지 않는다. 수집 표는 표시 범위별 펼침 상태와 이미 집계한 행/미확인 수로 높이를 추정하고 기존 최대 높이에서 스크롤한다. 펼침/접힘 후 다음 프레임에 높이가 맞춰지며 긴 이름 줄바꿈은 스크롤로 처리한다. 전체 어종을 Draw에서 재검색하지 않는다.

### 남은 검토와 판단 기준

1. 그라파이트에서 승인 범위의 순서/선택/강조와 수집 표 높이를 실제 확인한다. 기존 폭·높이·배율에서 첫/마지막 행과 미끼/조건의 읽기 공간을 비교한다.
2. 추가 전면 재배치·새 배치 시안은 현재 TODO에서 제외한다. 실제 보고된 잘림·정렬·클릭 구분 문제만 기존 동선 안에서 마감한다. 먼바다 목표/업적/점수 최적화와 작살/특수 납품 확장도 현재 계획에 두지 않는다.
3. 동일한 데이터/선택/스크롤에서 나머지 팔레트의 기본 표시를 확인한다. 모든 테마·언어·배율의 무제한 전수 조합을 완료 조건으로 두지 않으며 대표 조합에서 읽기/조작과 스타일 복원을 확인한다.

비교 조건은 같은 화면 크기/배율/데이터/필터/선택/스크롤이다. 첫/마지막 표시 행과 타이머 기록량, 어종 이름·남은 시간·미끼를 찾는 과정, 보조 글자의 일반/선택/호버 대비, 긴 이름·한영·밝은 게임 배경을 확인한다. 현재 상태에서 개선 전후 탐색 시간이 빨라졌다는 실측 근거는 없다.

시각적 위계와 그룹별 탐색의 참고는 [NN/g 시각적 위계](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)·[제목을 따라 훑는 탐색](https://www.nngroup.com/articles/layer-cake-pattern-scanning/)다. 웹 연구의 원칙을 게임 플러그인에 적용하는 것은 설계 판단이며 동일한 사용성 결과를 보장하지 않는다. 외부 코드/에셋은 도입하지 않았다.

## 확정한 화면 구조

- 알림 설정(2026-10-24 합의): 즐겨찾기 관리의 ‘즐겨찾기 / 출현 알림 설정 / 발송 기록’ 세 탭으로 출현 알림 설정을 모으고 기존 메인 일반 설정에서는 옮긴다. 켜기 스위치는 가운데 탭 최상단의 강조 영역에 두고 바깥 스위치/톱니는 없앤다. 기본 사전 시간·채널은 각각 라벨/입력이 같은 행이다. 캐스팅 알림·프리셋 편집과 전용 채팅 채널은 기존 타이머 설정에 유지하며 공통 출력 이동 버튼을 제거한다. 입질·터주·터주왕 효과음에는 채팅 기능을 추가하지 않는다. 어종별 메모·수동 횟수·프리셋 연결은 후속 개발본의 [메모·캐스팅 타이머 관리](FISH-PERSONAL.md) 접힘 영역에 구현했다.

- 일반 설정 정리(2026-10-24 합의): 기존 구역 순서를 유지하고 입력을 두 열의 라벨/값으로 정렬한다. 배율 복원은 선택기 옆 아이콘으로, 업데이트 내역은 같은 값 열의 버튼으로 묶는다. 백업 동작은 동일 폭의 아이콘 버튼으로 정렬하고 긴 설명은 기본 접힘으로 옮긴다. 필수 오류/복원 안내는 숨기지 않는다. 캐스팅 알림의 반복 설명은 줄이고 상세는 관련 입력/버튼 툴팁에 둔다.

- 수집 현황: 2026-10-20 사용자 합의로 메인의 별도 탭이다. 확장팩→지역 펼침 표와 진행 막대를 함께 제공한다. 도감 전체 기준이며 일반 낚시는 전체/터주(왕 포함)/터주왕 보기를 전환하고 먼바다는 별도 구역에 둔다. 일반 낚시 합계는 사용자 추가 선택으로 표 위 큰 요약 블록에 분리한다. 지역별 막대는 가용 폭을 따르며 진행률별 색을 나눈다. 확장팩/지역/먼바다 막대는 독립 어종 목록1개를 재사용하고 직접 닫기 전까지 유지한다. 일반/도감 합계에는 클릭 목록을 제공하지 않는다. 먼바다는 시트의 해역 ID별 현황과 클릭 목록을 제공한다. 합계 옆 클릭 안내/하단 기본 접힘 수집 규칙을 사용한다. 메인 탭은 아이콘과 문구를 함께 표시한다.0.4 내역은 새 기능 소개·기능별 설명과 기타 개선으로 나눈다. Unknown은 미수집과 나눠 표시한다. 세부 집계 계약은 [PRODUCT](PRODUCT.md#화면과-상호작용)를 따른다.

- 메인: 어종 목록/수집 현황/즐겨찾기 관리/낚시 기록/설정. 어종 선택은 오른쪽 상세 패널을 갱신한다. 2026-10-20 사용자 선택에 따라 상세 상단의 등급·별·수집 상태와 같은 줄에 ‘별도 화면으로 보기’를 둔다. 좁은 폭에서는 툴팁을 가진 아이콘으로 축약한다. 기존 독립 상세1개를 재사용하며 이후 메인 선택과 독립적으로 유지한다.
- 간이 목록: 출현 중→예정 목록. 즐겨찾기 여부를 제외한 메인 일반 필터를 공유하며 즐겨찾기만 보기/예정 범위는 별도 저장한다. 상단 별 버튼과 옵션의 체크박스로 같은 전용 필터를 조절한다. 선택한 어종은 독립 상세 하나를 재사용한다.
- 비교 상세: 생미끼/직감 선행 어종 클릭으로 원래 상세를 유지한 채 별도1개를 연다. 비교 안에서 이동/뒤로(최대32단계)가 가능하다. 2026-10-19 사용자 선택으로 합의했으며 어종별 다중 생성은 하지 않는다.
- 캐스팅 타이머: 현재 낚시와 최근 시전 기록. 낚시터 이름 옆 어종 보기에서 독립 수집 필터 목록을 연다.
- 미끼 준비: 직접 닫기 전까지 유지되는 독립 보조 화면. 메인을 닫아도 유지한다. 상세 제목의 미끼 찾기와 역할을 구분한다.
- 기존 세 화면 합의 이후 타이머·준비 화면이 별도로 승인됐다. 추가 분리/주요 배치 변경은 사용자에게 차이와 동선을 설명하고 합의 후 구현한다.

## 표시와 상호작용 기준

- 목록/즐겨찾기 탐색을 중심에 두고 진단은 개발자 옵션 뒤로 둔다. 개발자 옵션을 정상 수집/예측/알림의 동작 조건으로 사용하지 않는다.
- 도감 미조회와 호환성 차단은 구분한다. 중요한 상태·필요 동작은 눈에 보이게 두고 보조 설명만 툴팁에 넣는다.
- 미끼·날씨·스킬은 게임 아이콘을 사용하고 이름/의미/대체 표시를 제공한다. 단계 순서·현재/직전·AND/OR 의미를 아이콘 축약으로 잃지 않는다.
- 어종 아이콘 크기를 유지하고 오른쪽 정보 묶음과 세로 중앙 정렬한다. 넓은 폭은 가로 묶음, 좁은 폭은 줄바꿈과 보조 툴팁으로 정보 접근을 유지한다.
- 이름 바로 아래 등급·별·수집 선택을 묶는다. 수동 지정은 명시하고 자동이라는 기본 표시는 반복하지 않는다. Unknown을 체크 해제=미수집으로 바꾸지 않는다.
- 출현 중/예정은 짧은 문구·아이콘·색상을 함께 쓴다. 시간과 실제 시각 범위를 가까이 두고 개인 준비 완료를 확정하지 않는다.
- 필터 기본값 복원은 정렬이 보이는 위치에서 접근한다. 초기화/전체 보기/프리셋 불러오기의 의미를 구분한다.
- 전승록은 상세에서만 표시한다. 0.3.4.0부터 필터 줄에 물고기의 눈 아이콘 ON/OFF를 두고 기본 OFF·선택 기준 시간순 정렬을 제공한다. 고정 미사용 안내는 삭제하며 상세의 두 예측은 달라질 때만 표시한다. 직감 계산 구역은 대상/선행 어종 시간과 최종 결과를 구분한다.
- 0.3.5.0부터 직감 계산은 기본 접힘이다. 펼친 표에는 어종 아이콘·대상/선행 역할·각 구간을 나누고 최종 출현은 색과 시계 아이콘으로 강조한다. 반복 준비 상태 문장은 없애고 보조 문구 하나만 둔다. 지속 시간 미확인은175초 가정으로 예측하며 상세의 짧은 경고는 접어도 보인다. 하루 이상 시간도 `일:시:분:초`를 사용한다.
- 한국어/영어·좁은 폭·재로드·선택/스크롤 유지·게임 테마별 가독성은 관련 변경의 실제 확인 항목이다. 대표 확인과 전수 확인은 구분한다.

## 어종 데이터 확장 상세보기 시안 (2026-11-05 · 구조 미승인)

사용자는 기존 상세에 꼭 필요한 정보만 추가하는 방향을 선택했다. [상세9개 상황 시안](mockups/fish-detail-data.html)은 가상 어종/수치이며 실제 Plugin UI·내장 자료는 변경하지 않았다. 직감 진행도를 상세에서 제외하는 부분은 아래 권고안으로 검토한다.

- **이중·삼중:** `이중 2마리 · 삼중 3마리`처럼 한 정보행으로 묶는다. 비해당·1마리·범위·미확인은 원본 의미대로 구분한다. 최소 어획 획득력과 복수 어획 보장 임계값을 혼동하지 않는다.
- **소장품:** `소장품 납품원 · 소장가치 300 / 450 / 600+` 또는 `단골 NPC A · 소장가치 300 / 450 / 600+` 한 정보행만 추가한다. 숫자는 구간 시작값의 가상 예시다. 도시/마을명·좌표·별도 지도 버튼은 표시하지 않는다. 좁은 폭에서는 자연스럽게 줄바꿈한다.
- **제외:** 구체적 화폐·길·경험치·만족도 보상, 보상표, 소장가치 직접 입력, 기본/보너스 선택, 주간 요청 상태, 납품·보상 전환을 제거했다. 준비·재준비 설명은 접힘 영역까지 제거했다.
- **직감 권고안:** 상세는 선행 어종/필요 마릿수/지속 시간의 고정 조건만 둔다. 현재 `2/3마리` 같은 진행도와 진행 막대는 기존 캐스팅 타이머에서만 본다. 상세에서 준비 조건을 확인하고 낚시 중에는 타이머를 보는 역할 구분이다. 지속 시간 미확인과 예측 가정 경고는 유지한다. 앞 시안의 진행도는 가상 제안이었으며 실제 추가된 기능이 아니다.
- **나머지:** 생미끼는 기존 가로 경로/줄바꿈·관련 어종 비교를 유지한다. 작살은 크기/속도와 숨은 어장의 선행 조건을 짧게 묶는다. 최소 획득력은 한 행이며 내 능력치 비교 영역은 추가하지 않는다.
- 먼바다 메인 시안은 아래 [Beta 범위](#먼바다-beta-범위와-항해-상태-배치-2026-11-06--동선-제안)에 맞춰 교체했고 사용자 승인 후 개발본에 구현했다. 어종 상세 간소화는 이 구현에 포함하지 않았다.

소장품의 구간 구조는 [공식 납품원 DB](https://na.finalfantasyxiv.com/lodestone/playguide/db/shop/a78fc483b4c/), 단골거래의 보상/주간 구분은 [공식6.3 안내](https://na.finalfantasyxiv.com/lodestone/topics/detail/764840557caa22a8f77550b480aa3c79b2e733d2)에서 확인한 조사 근거다. 구체 보상과 주간 상태는 이번 표시 범위에서 제외하며, 실제 KR/글로벌 어종별 대상·구간 연결은 후속 자료 검사 대상이다.

시안은 일반/생미끼/직감/납품원/단골/작살/먼바다 일반/먼바다 직감/복합9개 케이스를 유지한다. 이전 큰 시안과 입력·진행도 검사의 이력은 Git에 남긴다. 수정본은9개 전환·320/420px 배치의 가로 넘침 없음·밝은/어두운 대표 렌더링·문서 검사·diff 공백 검사를 확인했다. 제품 테스트·빌드·게임 실기는 실행하지 않았다.

## 먼바다의 실제 사용 목적과 지원 경계 (2026-11-05 · 합의 전)

사용자는 화면 배치보다 먼저 간단한 기본 낚시/특정 어종/특정 업적을 어떻게 도울지와 지원 한계를 정의하도록 요청했다. 아래는 초기 범위 후보이며 이후 아래 Beta 범위만 승인·구현했다. 현재 공개판에는 먼바다 전용 메인 메뉴가 없으며 `FishingTracker`는 해당 지역에서 `OceanUnsupported`를 사용한다. 새 Beta도 기존 일반 낚시의 시전/어획/직감 집계를 먼바다에서 제공하지 않는다.

### 사용자가 도움받을 판단

| 목적 | 지원할 안내 후보 | 자료만으로 해결되지 않는 부분 |
|---|---|---|
| 가볍게 점수/경험치 얻기 | 출항편과 기항지를 정하면 일반/환해류별 기본 미끼와 노릴 어종1~2개를 먼저 표시한다. 전체 어종표를 읽지 않아도 되는 짧은 기본 안내다 | 기준점수 순 정렬은 기본 전략이 아니다. 항로/기항지별 검증된 전략과 미끼 적합성 자료가 필요하며 현재 입질의 어종·GP별 다음 기술을 확정하지 않는다 |
| 특정 어종 | 목표가 포함된 항로/기항 시간대, 준비할 미끼, 일반/환해류·직감·생미끼 조건을 연결한다. 대상 없는 출항편/기항지는 명시한다 | 미래 인스턴스 날씨/환해류 발생/어획 성공을 예측해 보장하지 않는다. 현재 날씨와 직감 충족은 별도 입력 또는 관찰 근거가 필요하다 |
| 이번 항해 임무 | 실제 선택한 임무의 대상 분류/별/입질 조건에 해당하는 어종과 미끼를 표시한다 | 항해 임무와 업적은 다른 목표다. 고정/변동 임무를 구분하고 변동 조건은 수동 선택 또는 검증된 게임 관찰로 확인해야 한다 |
| 특정 업적 | 업적별 정확한 조건과 대상 어종, 항로/기항지/시간대별 공략을 준비한다. 개인/파티, 한 기항지/한 항해/누적 등의 집계 범위를 구분한다 | 어종의 임무 분류만으로 개별 업적 지원을 완성할 수 없다. 업적ID↔조건↔어종/분류↔항로의 검수된 연결이 필요하며 확인한 업적만 지원 대상으로 삼는다 |
| 도감 채우기 | 기존 수집 상태를 사용해 해당 항로의 미수집 대상과 준비 미끼를 좁힌다 | 미수집과 미조회를 나누며 해당 항해의 신규 어획 자동 반영은 별도 계약 검증을 거친다 |

기본 안내는 점수 목적의 기본 방침을 사용하고, 특정 어종/업적을 선택하면 그 목표에 맞는 미끼와 환해류 방침을 우선해야 한다. 모든 목적에 일률적인 환해류 유발/고득점 어종 전략을 적용하지 않는다. 공략 문장은 화면에 긴 설명을 새로 늘리는 대신 현재 기항지의 미끼·목표·필수 조건으로 요약한다.

## 먼바다 Beta 범위와 항해 상태 배치 (2026-11-06 · 동선 제안)

사용자가 먼바다를 Beta로 제공하고 현재 목적지와 간단한 기본 낚시 안내에 한정하도록 요청했다. 이어 출항 일정·실제 승선 항로/다음 기항지·남은 시간의 메인 시안을 승인해 개발본에 구현했다(2026-11-06). 아래 화면 구조는 승인 범위이며 자동 관찰과 실제 편성표·미끼 찾기의 인게임 확인은 대기다.

- 메인에 `먼바다 · Beta` 탭을 두었다. 일정/전체 항로/해역 남은 시간/기본 미끼는 이곳에 모으며 캐스팅 타이머에 항해 정보를 추가하지 않는다.
- **미승선:** 접수 중/다음 출항편과 로컬 시각·접수까지/접수 종료까지 남은 시간을 표시한다. 편을 선택하면 기항지3곳의 순서/낮·저녁·밤과 준비할 기본 미끼를 미리 본다. 실제 편성표를 KR·글로벌 표시와 대조한 뒤 UTC 계산을 도입한다. 시각만으로 승선편을 확정하지 않는다.
- **승선 중:** 관찰한 실제 항로와 현재/다음 기항지를 항로3단계에 표시하고 기본 안내는 현재 기항지·일반/환해류 상태를 따른다. 일정의 미리보기와 실제 승선 상태를 구분한다. 자동 관찰이 실패하면 해당 상태를 확인 불가로 두고 명시적인 수동 미리보기를 제공한다.
- **시간:** 접수 카운트다운과 현재 해역의 낚시 종료까지 남은 시간을 구분한다. 해역 이동/대기/종료 상태는 문구로 표시하고 지난 해역 시간을 계속 세지 않는다. 정확한 귀항 시각/귀항까지, 환해류 자체의 종료 카운트다운은 첫 Beta에 포함하지 않는다.
- **기본 안내:** 전체 어종표 대신 현재 사용할 미끼, 환해류 때 사용할 미끼, 필요하면 점수용 목표1~2종과 입질·이중/삼중 한 행을 보여 준다. 목표가 걸렸다고 확정하거나 지금 눌러야 할 기술을 판정하지 않는다. 검수된 항로/기항지 전략만 제공하고 미확인 구간은 안내 자료 미확인으로 남긴다. 긴 공략·직감 준비·특정 업적 선택·점수 최적화는 추가하지 않는다.
- 자동 승선 상태의 구조 근거는 [KR·글로벌 조사와 개발본 구현](../verification/native/GLOBAL-COMPAT.md#먼바다-beta-개발본-구현-2026-11-06)을 따른다. 양쪽 빌드·사용 멤버 대조는 완료했으며 주소 해석/게임 UI 대조/전이·수명 실기는 하지 않았다. 개발본 구현과 자동 인식 실기 확인을 구분한다.

[Beta 화면 시안](mockups/ocean-data-view.html)은 승선 전/접수 중/일반 해역/환해류/이동 중/승선 정보 확인 불가의6가지 상황을 전환한다. 승선 전에는 출항편 선택과 준비 미끼를 펼치고, 승선 후에는 실제 항로·현재/다음 해역·해역 낚시 종료까지 남은 시간과 추천 미끼를 우선한다. 출항 일정은 접어 두며 펼친 뒤 다른 편을 선택해도 상단의 승선 항로는 바뀌지 않는다. 미끼 찾기는 기존 게임 미끼 선택 화면의 페이지/칸 강조를 재사용하는 동선 제안으로, 시안에서는 안내만 표시한다. 미소지 상태에서는 찾기를 비활성화한다. 시안 자체의 일정·항로·어종·미끼·수치는 가상으로 유지하며 개발본의 실제 연결은 아래와 구분한다.

개발본은 가상 자료를 [내장52행 기본 안내와 클라이언트 편성표](../development/DATA-SOURCES.md#먼바다-beta-기본-안내와-일정-2026-11-06)로 교체하고 기존 미끼 소지 수량/찾기를 연결했다. 사용자 요청에 따라 같은 접수 시각은 한 행으로 묶고, 시간/접수 상태 오른쪽에 남색·홍옥 두 열을 같은 폭으로 나란히 둔다.3회분을 표시하고 각 항로 셀을 독립 선택하며 긴 이름은 줄바꿈한다. 사용자 선택으로 선택한 편의 제목은 ‘출항편 상세’, 접힘 제목은 ‘출항 일정’으로 표시한다. 승선 정보 확인 불가 안내에서도 ‘미리보기’ 표현을 제거했다. 승선 관찰은200ms 간격이며3초 이상 지난 표본·세션 전환·지역 이동 시 현재 정보를 확인 불가로 둔다. 이동/도착 전이의 CurrentZone 의미는 실기 미확인이므로 항로와 이동 상태만 표시하고 다음 미끼/지난 해역 시간은 추정하지 않는다. 낚시 중에만 현재/다음 표시와 미끼 안내를 제공한다. 개발자 모드의 접힌 ‘먼바다 진단’은 필요한 짧은 상태/원시 시간만 복사한다. 기존 일반 캐스팅 타이머의 먼바다 지원은 바꾸지 않았다.

시안 단계에서6가지 전환·출항편 선택·찾기 안내·미소지 비활성화,320px/넓은 폭의 가로 넘침 없음, 밝은/어두운 대표 렌더링과 JavaScript 오류 없음을 확인했다. 이후 개발본은 KR/글로벌 빌드·문서/리소스·공백 검사를 완료했다. 시안 렌더링을 제품 ImGui의 테마/폭 실기 확인으로 확대하지 않으며 제품 테스트·게임 실기는 실행하지 않았다.

사용자 승인 후 기존 ‘어종 보기’를 현재 해역의 일반/환해류 어종 목록에 연결했다. 메인 항로의 현재 해역 옆 버튼과 캐스팅의 기존 버튼은 같은 목록 하나를 토글한다. 열어 둔 목록은200ms 승선 관찰에 맞춰 환해류 시작/종료·해역 변경을 따라 바뀌며 ‘해역명 · 일반 해역/환해류’를 제목에 표시한다. 자동으로 열지 않고, 기존 수집 숨김/전체 선택과 어종 상세 접근을 유지한다. 메인/타이머/목록은 각각 관찰 사용 여부를 보유해 메인이나 타이머를 닫아도 목록만 열려 있으면 갱신한다. 이동/대기/종료/관찰 실패·오래된 표본에서는 이전 목록을 비우며 상태를 표시한다. 해역이나 상태가 바뀌면 목록 스크롤도 처음으로 돌린다.

어종 목록은 현재 IKDSpot.SpotMain/SpotSub와 게임 낚시수첩 Item 슬롯을 연결한다. 주 FishingSpot만으로 양쪽 해역 소속을 빠뜨리지 않는다. Framework에서 카탈로그 행이 바뀔 때26개 일반/환해류 낚시터로 색인하며 Draw에서 전체 어종을 다시 검색하거나 시트를 읽지 않는다. 수집 숨김은 현재 해역의 최대10종에만 적용하고 미확인을 미수집으로 확정하지 않는다. 일반 낚시 목록은 기존 데이터 경로를 유지하며, 먼바다 타이머·어획 기록·직감 진행도는 지원 범위를 확장하지 않았다. 목록은 현재 해역 상태의 후보이며 이번 시전에 걸린 어종의 판정이 아니다. 후속 작업으로 같은 화면의 체크에서 전체/조건 후보를 전환하도록 구현했다. 시간대·현재 날씨·직감 부재만 비교하며 미확인·직감 활성의 대상은 확정하지 않는다. 미끼/장비·특수 어획표·업적/점수는 판정하지 않는다. [자료와 경계](../development/DATA-SOURCES.md#필요한-어종-보완과-먼바다-조건-2026-11-06). [실시간 전환·단독 목록·양쪽 버튼·수집 필터의 인게임 확인](../verification/catalog/UI.md#먼바다-일반환해류-어종-목록-연결-개발본-2026-11-06)은 대기다.

## 사진 기반 개선 근거

0.1.32.0 사용자 사진에서 다음 7개 개선을 제안하고 승인 후 0.1.34.0에 반영했다. 기존 UI-UX-SCREENSHOT-REVIEW의 제안은 이 구역으로 통합했다. 상세 결과는 [사진 개선 기록](../archive/ui/CHANGES.md#mvp-01-ui-screenshot-polish)을 따른다.

| 관찰 | 적용 방향 |
|---|---|
| 상세 생미끼 경로가 세로 공간을 많이 차지함 | 가로 경로/줄바꿈, 단계 옆 낚아채기·입질·정보 |
| 직전/현재 날씨의 반복 설명 | 후보 / 후보 → 후보 / 후보 묶음과 툴팁 |
| 수집 선택 상자가 남는 폭 전체를 차지함 | 이름 아래 조작 줄 유지, 내용에 맞춘 폭 |
| 목록의 반복 정보 아이콘이 과도함 | 아이콘/묶음 툴팁, 생략 정보가 있을 때만 추가 표식 |
| 메인 상단이 여러 줄로 분산됨 | 검색·도구 모음·결과/이동을 묶고 폭에 따라 줄바꿈 |
| 목록/상세의 여유 공간 불균형 | 넓은 목록의 조건 묶음 정리, 기존 조절 테이블 유지 |
| 녹색 면적/배경 게임 텍스트가 과도함 | 채도·시간 강조·대비 조정 |

사진의 여러 행에서 종료 00:00:01이 보였다는 사실만으로 타이머 오류를 확정하지 않았다. 이 기록으로 예측 재조사를 자동 재개하지 않는다. 초기 구조·후속 세부 조정은 [화면 검증 색인](../verification/README.md#목록필터화면)에 있다.

## 조회한 UX 근거

2026-10-16~17에 확인한 자료이며 이번 문서 통합에서 재조회한 것은 아니다. 외부 코드/에셋은 도입하지 않았다.

- [NN/g 사용성 원칙](https://www.nngroup.com/articles/ten-usability-heuristics/): 상태 가시성·일관성·불필요한 정보 축소. 도감 안내/공통 행/조작 묶음에 적용했다.
- [Fluent 툴팁](https://fluent2.microsoft.design/components/web/react/core/tooltip/usage): 비필수 보조 정보는 툴팁, 필수 피드백은 화면에 유지한다.
- [W3C 색상 사용](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): 색상만으로 상태를 전달하지 않는다. ImGui 접근성 인증을 주장하지 않는다.
- [FFXIV Fish Tracker](https://ff14fish.carbuncleplushy.com/): 상시 숨김·출현 정렬·미끼/낚아채기·지도 접근의 비교 사례다. 코드 복제나 예측 공식 변경 근거로 사용하지 않는다.
