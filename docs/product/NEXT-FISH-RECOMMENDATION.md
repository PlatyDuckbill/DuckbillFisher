- 현재 목표 유지/전환, 준비 진행도 입력, 실제 직감/생미끼 관찰, 여러 어종의 순회 동선 최적화는 이번 추천 범위에 넣지 않는다. 기존 수량/입질 통계 보류도 유지한다.

첫 대상은 **일반 필드의 미수집 터주·터주왕**으로 제안한다. 수집 Unknown은 미수집으로 확정하지 않으며 ‘수집 상태 미확인 포함’으로 명시적으로 넓힐 수 있다. 준비용 일반 어종과 이미 수집한 선행 어종에는 목표 수집 필터를 적용하지 않는다. 먼바다·작살·우주개척 등 별도 규칙의 콘텐츠는 첫 범위에서 제외한다. 장비·레벨·전승록·미끼 소지 여부는 이번 점수에서 개인별로 추정하지 않고 필요한 조건을 안내한다.

## 조사로 확인한 설계 요건

| 특성 | 추천에서 반영할 내용 |
|---|---|
| 드물게 출현 / 짧게 출현 / 잘 안 물거나 놓침 | 서로 다른 개념이다. 시간표의 빈도와 총 출현 시간을 계산하며, 입질률·놓침률을 그 값에서 유추하지 않는다. |
| 생미끼 단계 | 단계 수는 준비 부담의 기본 자료다. 중간 어종이 시간/날씨 제한이나 터주 등급이면 별도로 고려한다. 첫 미끼 대안은 생미끼 단계 수를 늘리지 않는다. |
| 생미끼 반복·보관 | 보관으로 출현 중 작업을 미리 수행하고 재시도 비용을 줄일 수 있다. 보관량은 한정되고 같은 장소 유지/기술 조건이 있다. 내장 BaitSteps만으로 보관 적격성·반복·모든 대안 경로를 복원하지 않는다. |
| 직감 수량 | 요구 마릿수는 시전 횟수가 아니다. 이중/삼중 낚아채기 효과와 수량이 어종별로 달라 ‘마릿수×고정 초’는 실제 준비 시간으로 사용할 수 없다. |
| 직감 발동 | 선행작과 마지막 발동 어획을 구분한다. 일반 선행 어종은 발동 직전까지 준비하는 전략이 가능하지만, 터주 선행 어종도 동일하게 확보할 수 있다고 가정하면 안 된다. |
| 시간 제한 선행작 | 선행 어종들이 동시에 출현할 필요는 없다. 서로 다른 시기에 잡아 누적하는 경우가 있으므로 모든 시간 구간의 단순 교집합은 잘못된 제외를 만들 수 있다. |
| 직감+생미끼 | 마지막 선행 어획이 생미끼 역할도 겸하는 경우가 있다. 확인한 중복 작업만 한 번 계산하며, 같은 ItemId라는 이유만으로 역할·수량을 무조건 합치지 않는다. |
| 출현 중 도전 시간 | 표시하는 출현 잔여는 대상 조건의 시간이다. 직감 어종이 그 시간 내내 낚시 가능하다는 뜻은 아니다. 직감 지속·재발동은 별도이며 누락값은 확정하지 않는다. |
| 기술/전략 차이 | 인내·월척 확보, GP 운용, 루어 등은 실제 효율에 영향을 주지만 첫 버전에서 최적 기술 순서를 시뮬레이션하지 않는다. 필수 루어 등 확인된 조건은 상세에 제공한다. |

공식 기술 설명에서 복수 어획의 어종별 차이와 보관 생미끼의 유지/사용 조건을 확인했다.[한국 공식 가이드](https://guide.ff14.co.kr/job/Fisher/31?type=L) 일반 직감과 터주 선행 직감의 준비를 구분하는 이유, 생미끼 반복의 존재는 [Fruity Snacks의 가이드](https://docs.google.com/document/d/1B7wjAtw5uCiARS9tXsozYAX8l6JZOzl2YtJSjejqchk/edit)를 참고했다. 해당 경험적 전략을 어종별 소요 시간의 실측 평균으로 전환하지 않는다.

## 계산 흐름

### 1. 후보 회차를 만든다

- 기본 탐색 기간은 **앞으로3시간**, 선택은1·3·6·12·24시간으로 제안한다. 이는 ‘그 안에 출현하거나 도전할 후보’의 범위이며 사용자가 그만큼 계속 플레이한다는 뜻은 아니다. 알림의120분 상한 및 빈도 분석의30일과 독립이다.
- 대상 자체의 시간/날씨 구간과 선행 어종의 구간을 분리해 보관한다. 기존 `FishingForecast`의 직감 반영 결과는 참고하되 실제 준비 완료나 모든 어종의 완전한 준비 계획으로 간주하지 않는다.
- 단위는 내부적으로 `어종 × 지원 낚시터 × 출현 회차 × 준비 전략`이다. 현재 자료의 연결된 낚시터를 기준으로 하며 검증되지 않은 다른 낚시터로 확대하지 않는다.
- 각 회차를 평가한 뒤 **어종당 가장 적절한 회차 하나**를 목록에 남긴다. 같은 어종의 여러 회차가 추천 목록을 채우지 않게 한다. 나머지 회차는 상세/일정표에서 확인한다.
- 항상 조건이 열려 있는 어종은 가짜 출현 시작을 만들지 않는다. 직감만 필요한 어종은 ‘선행작 후 도전’으로 표현한다.
- 첫 화면의 기간은 ‘대상 출현 기준3시간’처럼 뜻을 명시하고 자동으로24시간까지 확장하지 않는다. 그 밖의 필수 선행작을 보고 싶다면 기간을 넓히거나 향후 명시적인 장기 준비 옵션으로 제공한다. 자동 범위 확대와 임의24시간 상한을 첫 구현에서 제거한다. 따라서 첫 범위 밖의 장기 준비 기회까지 모두 찾아준다고 보고하지 않는다.

### 2. 어종마다 준비 전략을 만든다

추천의 내부 단위를 **어종 × 회차 × 준비 전략**으로 확장한다. 목록에는 여전히 어종당1행만 보여준다. 기본 경로1개와 근거가 있는 보관/발동 전략1개 정도로 제한하며, 모든 기술 순서를 자동 탐색하지 않는다. 보관은 먼 후속 예외가 아니라 첫 준비 모델에 포함한다.

| 구분 | 내용 | 시간 계산에서의 의미 |
|---|---|---|
| 출현 전에 반드시 끝낼 작업 | 먼저 닫히는 선행 어종 확보 등 | 놓치면 해당 전략이 성립하지 않는다. 다른 전략까지 불가능한지 확인 후 회차를 제외한다. |
| 출현 전으로 옮길 수 있는 작업 | 일반 중간 생미끼 확보, 일부 직감 선행작 | 미리 하면 출현 중 작업이 줄어든다. 미리 못 했어도 출현 중 수행 가능한지 따로 평가한다. |
| 출현 중에만 가능한 작업 | 같은 시각에 열리는 중간 터주, 그 이후 최종 연쇄 | 전부 출현 시작 전까지 끝내야 한다고 계산하지 않는다. |
| 발동 시점을 맞출 작업 | 마지막 직감 어획 | 출현 직전 발동도 지속 시간이 겹치면 가능하며 무조건 출현 후 작업으로 고정하지 않는다. |
| 선택적인 추가 준비 | 재시도용 보관 생미끼 추가 확보 | 필수가 아니다. 준비 기간/자원 비용과 재준비 감소를 함께 안내한다. |
| 반복 비용 | 실패·소모 후 다시 확보할 미끼/직감 | 최초 준비와 분리한다. 보관 수량을 최종 목표 시도 수/성공 확률로 환산하지 않는다. |
| 유지 제약 | 보관/생미끼 기회·직감 누적/활성의 유지 조건 | 다른 낚시터에서 기다릴 수 있는 것처럼 계획하지 않는다. 해당 전략의 현장 체류를 안내한다. |

기존 ‘일반 생미끼 단계마다2~5분을 더한다’는 안은 전체 경로를 모두 사전 준비로 취급할 수 있어 폐기한다. 단계별 대략적인 작업 시간은 사용할 수 있지만, **어느 단계가 언제 가능하며 무엇을 남기는지**를 먼저 구분해야 한다. 준비 범위는 성공 보장·실측 평균·확률 구간이 아닌 추천용 여유다. 과거 초안의 일반 직감5~15분/터주 선행20~60분도 검증된 사실이 아니며 전략별 근거 검토 없이 전수 적용하지 않는다.

첫 구현의 준비 자료는 다음 정도로 제한한다.

- 전략 식별자와 조건: 사용할 기술/최소 레벨, 일반 조건/물고기의 눈 사용 여부, 적용 KR 자료 버전.
- 단계: 어떤 어종을 어느 선행 단계 후에 확보하는지, 필수/선택 여부, 대표 계획 여유와 짧은/넉넉한 범위 또는 시간 미확인, 가능한 시간/날씨 구간. 대표 여유는 실측 평균이 아닌 별도 설계 가정으로 기록한다.
- 결과: 직감 누적, 보통 생미끼 기회, 보관 생미끼를 구별한다. 보관 대상/목표 수량/유지 제약, 소모 후 어느 단계부터 재개하는지 기록한다.
- 발동: 마지막 직감 어획/특수 수령 보류, 공유 어획 여부, 유효 시간과 근거 수준을 별도로 둔다.
- 출처: 원본 조건/공식 기술/사용자 제시 전략/커뮤니티 경험/설계 추정을 구별하고 URL·revision/해시·열람일을 기록한다. 실제 KR 실기 확인 상태도 별도다.

보관 가능 여부를 BaitSteps의 모든 어종에 자동 부여하지 않는다. 공식 기술은 특정 물고기의 보관을 설명하며, 현재 내장 조건에는 어종별 보관 적격성과 완전한 대안 경로가 없다. 확인한 대상/분기만 전략에 넣고, 자료가 부족하면 일반 경로와 ‘보관 전략 미확인’을 제공한다. 지금 가진 생미끼를 읽거나 사용자에게 진행 수량을 입력받는 기능은 추가하지 않는다.

### 3. 롱카의 물뱀 사례로 계산 경계를 정한다

내장 `Greater Serpent of Ronka`(Item33243)의 경로는 다음과 같다. 한국어 UI 이름은 클라이언트 시트로 연결하며 원본 영문명으로 임의 번역하지 않는다.

미끼27587 → Clown Tetra(27490) → Eryops(27491)

[Fruity Snacks의 해당 공략](https://na.finalfantasyxiv.com/lodestone/character/12300440/blog/4770466)은 두 번째 단계의 생미끼 기회를 확보해 기다리는 방법을 설명한다. 이는 보관 기술 도입 전 설명/HQ 용어를 포함하므로 ‘현재 보관 여러 마리 전략의 실기 검증’으로 확대하지 않는다. 사용자가 제시한 두 번째 단계 보관 전략은 이 경로와 [공식 보관 기술](https://guide.ff14.co.kr/job/Fisher/31?type=L)을 조합한 첫 검토 대상으로 둔다. 이 어종의 보관 수량·소요 시간·성공률은 이번에 실측하지 않았다.

| 전략 | 출현 전 | 출현 중 | 판단 |
|---|---|---|---|
| 기본 준비 | 두 번째 단계까지 생미끼 기회를 확보/유지 | Priest에 도전하고 성공하면 목표로 이어감 | 남은 연쇄가 있으므로 목표에 바로 시전 가능하다고 표시하지 않음 |
| 보관 준비 | 확인된 중간 생미끼를 미리 확보·보관 | 보관한 단계부터 연쇄 진행 | 앞 단계 재확보 부담을 줄일 수 있으며 현장 유지/기술 조건 필요 |
| 추가 보관 | 검토한 한도/목표량까지 재시도용을 더 확보 | 소모할 때마다 보관분 사용, 소진하면 일반 경로로 복귀 | 더 일찍 시작할 선택지지만 모든 보관분이 최종 목표 시도로 이어지지는 않음 |

여기서 보관은 Priest의 제한이나 어획 난도를 없애지 않는다. ‘전체 생미끼3단계 준비 완료’가 아니라 ‘앞의2단계를 미리 준비하고, 출현 중 남은 연쇄에 집중’으로 설명한다. 출현이 이미 시작했다면 추가 보관을 끝낼 때까지 기다리는 것보다 기본 준비로 진행하는 전략이 선택될 수 있어야 한다. 보관을 하지 않으면 낚을 수 없다는 식으로 제외하지 않는다.

### 4. 단계별 시간과 지금 시작할 이유를 계산한다

대상 자체 조건을 `[S,E)`로 두고, 준비 결과를 네 가지로 구분한다.

1. **사전 작업 시간 범위:** 출현 전에 수행할 수 있는 필수/선택 작업의 실제 낚시 시간 추정.
2. **조건 때문에 기다리는 시간:** 다음 선행 구간까지의 대기와 보관/누적을 유지하며 현장에 남아야 하는 대기. 작업 시간과 구분한다.
3. **출현 중에 남는 작업:** 선행 터주·직감 발동·최종 생미끼 등. 근거가 있을 때만 소요 범위를 만들고, 없으면 남는 단계 자체를 보여준다.
4. **재시도 준비:** 추가 보관/반복 경로로 줄일 수 있는 작업과 소진 후 재개 위치. 입질률/성공률 없이 목표 시도 횟수를 계산하지 않는다.

단순한 사전 준비의 시작 범위는 `[S-M-P넉넉함, S-M-P짧음]`으로 안내할 수 있다. 순위의 착수 시점 T에는 별도로 검토한 대표 계획 여유를 사용하며 이 범위의 상한을 자동 적용하지 않는다. 여기서 `P`는 **선택한 전략의 출현 전 작업만**이다. `M`은 실제 이동 관찰값이 아닌 공통 이동·정비 여유로 초기2분을 제안한다. 출현 중에만 가능한 작업은 P에 넣어 과도하게 일찍 도착시키지 않는다.

계산은 다음 순서로 제한한다.

- 지금부터 처음 준비한다고 가정하고 선행 조건별 구간을 구한다. 각 단계의 선후관계, 소모/유지 조건을 적용한다. 서로 다른 직감 선행 어종의 구간을 무조건 교집합으로 만들지 않는다.
- 목표 회차에서 역으로 준비 마감/권장 시작을 계산하고, 현재 시각부터 실제 배치 가능한지 앞으로 한 번 대조한다. 같은 캐릭터의 낚시 작업 두 개를 동시에 수행하거나 그 사이 대기를 생략하지 않는다.
- 출현 전으로 옮길 수 있는 작업을 못 끝냈다면 출현 중 수행하는 대안을 검토한다. 이미 끝난 필수 기회, 명백한 선후관계/유지 조건 충돌만 조건상 불가로 판정한다. 추정 작업 시간이 길다는 이유만으로 확정 불가 처리하지 않는다.
- 직감 마지막 발동은 대상 조건과 유효 시간이 겹치도록 둔다. 선행 마릿수를 미리 모두 채운 뒤 직감이 무한 유지되는 계획은 금지한다. 갱신/재발동은 별도 전략이며 확률적 갱신을 기본으로 보장하지 않는다.
- **생미끼 보관과 직감의 공유 어획을 주의한다.** 같은 어획이 누적 조건을 채우면서 생미끼를 제공할 수 있지만, 추가 보관을 위해 잡다가 직감을 일찍 발동시키는 경우도 있다. 단순 수량 합산/중복 제거 대신 확인한 순서를 전략에 기록한다. GP·월척 낚시꾼 준비도 같은 어획에서 생기는 효과면 무조건 별도 시간을 더하지 않는다.
- 보통 생미끼 유지와 보관 생미끼를 같은 상태로 보지 않는다. 이동·낚시 종료·교환 방생/한결같은 챔질 등 상호작용은 기술/전략의 근거가 있을 때만 적용한다. 보관 상태로 다른 터주를 순회할 수 있다고 안내하지 않는다.
- 알려진 직감 시간과 출현 구간은 각각 유지한다. 누락 지속 시간의 기존175초 가정을 실제 버프 시간으로 승격하지 않는다. 기존 루어 조사처럼 시전 중 조건 재판정이 있을 수 있으므로 출현 종료를 어획 완료 마감이라고 설명하지 않는다.

첫 버전은 선형 생미끼와 확인된 직감/보관 템플릿만 처리한다. 복잡한 교차 작업은 검토된 어종별 순서로 연결한다. 일반 경로조차 판정할 근거가 부족하면 ‘준비 확인 필요’로 남기며 범용 탐색/확률 시뮬레이터를 만들지 않는다.

현재 `FishingForecast.Constrain`은 직감 수량·소요 시간·생미끼 준비를 입력받지 않으며 특정 인접 기간/원본 선행 순서를 사용한다. 추천의 완전한 개인 준비 판정기로 재사용하지 않는다. 대상/선행 자체 구간을 출발점으로 유지하며 기존 알림/일정표의 예측 의미를 조용히 변경하지 않는다.

### 5. 희소성과 다음 기회를 계산한다

희소성은 **조건상 출현 기회의 빈도**로 평가한다. 앞선 ‘빈도70% + 출현 시간 비율30%’ 안은 폐기한다. 직감 지속 시간이 짧다는 이유로 더 희귀해지거나, 같은 짧은 구간을 희소성과 도전 여유에서 중복 반영할 수 있기 때문이다. 출현 시간 비율은 참고 정보로 제공할 수 있지만 첫 점수에는 넣지 않는다. [Fish Tracker](https://ff14fish.carbuncleplushy.com/)의 uptime은 비교 참고이며 우리의 빈도와 같은 지표라고 표현하지 않는다.

- 같은 분석 기준부터30일 동안의 **독립적인 조건 기회**를 센다. 후보 전략 수, 보관 개수, 직감 재발동 횟수는 기회 수에 추가하지 않는다. 연속 구간·분할 구간·기간 경계의 집계 정책을 고정하고 분석 기간을 저장한다.
- 대상 자체의 시간/날씨 기회와 선행 조건을 포함한 기회를 구별한다. 선행 조건이 병목인 어종을 ‘대상 자체 상시’만으로 빈번하다고 판정하지 않는다. 순수 직감형도 선행 조건에 따라 판단하며 조건이 모두 상시면 일정상 희소성0이다. 이것이 쉽게 낚인다는 뜻은 아니다.
- 직감 버프 지속·175초 가정 때문에 생기는 구간 연장/분할을 독립 출현으로 세지 않는다. 같은 시간/날씨 기회에서 유래한 구간은 기회 식별자로 묶는다. 현 `FishingForecast.Enumerate`의 구간 개수를 모든 직감형의 완성된 빈도로 그대로 사용하지 않는다.
- 지표에는 `대상 자체 조건 / 선행 조건 포함 / 일부 조건 미반영`의 계산 근거를 붙인다. 마지막 경우에는 누락한 생미끼/직감 조건을 명시하고 완전한 희소성으로 확정하지 않는다. 이 정책을 구현하려면 지원하는 조건 기회의 정규화와 대표 어종 대조가 먼저다.
- 빈도 초깃값은 `f=독립 기회 수/분석 일수`, `R=clamp(log10(1+1/max(f,1/30))/log10(31),0,1)`로 제안한다. 로그는 극단값의 지배를 줄이는 설계 선택이며 검증된 어획 모형이 아니다. 빈 결과/누락/계산 실패에 이 식을 적용해 최대 희소성을 주지 않는다.
- 다음 기회는 같은 계산 기준으로 선택 회차 다음 기회를 찾는다. ‘다음 조건 출현’과 ‘다음 선행 준비 기회’를 구별하며 개인이 실제로 낚을 수 있다는 뜻으로 표시하지 않는다.30일 내 미발견은 검색 범위 표시와 함께 다루며 계산 실패와 구분한다.
- `N`은 이번 회차 종료에서 다음 조건 기회 시작까지의 간격을 완만하게 반영하는 보조값이다. 로그 변환/72시간 상한은 임시 튜닝값으로 둔다. R과 중복되는 영향은 대표 비교에서 확인하며 10점보다 확대하지 않는 첫 범위를 제안한다.

기회 계산이 아직 준비되지 않았을 때0점/가짜100점으로 순위를 확정하지 않는다. 상시·기간 내 없음·자료 부족·취소를 구분하고 사용자에게 계산 근거/누락을 보인다.

### 6. 첫 목표 도전 계획을 평가하고 추가 준비는 선택지로 제공한다

자가 점검 결과 **전체 점수에 곱하던 V와 선택 준비의 +10점 상한을 삭제**한다. V는 Q와 준비 부족을 중복 반영하며, +10 상한은 기본 전략을 무엇으로 정의하느냐에 따라 달라지는 임의 규칙이었다. 점수는 아래 네 요소의 가중합을 초기안으로 남기되, 실제 대표 순위가 타당하다고 검증된 값은 아니다.

```text
초기 비교식 = 40 × T + 30 × R + 20 × Q + 10 × N
T: 지금 첫 목표 도전을 위한 준비를 시작할 적절성
R: 독립 조건 기회의 희소성
Q: 남은 필수 작업을 거쳐 목표 어종에 시전할 시간 여유
N: 이번 회차 뒤 다음 조건 기회까지의 간격
```

**평가 순서**

1. 시간표/선후관계/유지 조건상 확실히 성립하지 않는 전략을 제외한다. 한 전략의 실패를 곧바로 어종 전체 불가로 만들지 않는다. 추정상 늦는 경우는 조건상 불가와 구별한다.
2. 일반 경로와 검토된 보관/직감 경로에서 **첫 목표 어종 시전 기회에 필요한 작업과 수량**을 찾는다. 서로 떨어진 필수 구간을 연결하는 보관, 직감 수량을 채우기 위한 여러 어획은 이 계획에 들어간다.
3. 실패 대비 추가 보관은 첫 계획의 준비 마감을 앞당기거나 T/Q를 올리는 데 사용하지 않는다. 추가 보관의 작업량·유지 부담·재준비 감소는 대안 정보로 함께 제공한다. 어획 확률/재시도 편익의 근거가 부족한 첫 버전에서는 선택적 추가 수량을 수치 보너스로 바꾸지 않는다.
4. 처음부터 한 번의 목표 시전으로 연결되는 경로 자체를 바꾸는 보관은 정규 전략으로 평가한다. ‘보관은 점수에 전혀 반영하지 않는다’는 뜻이 아니다. 이후 반복 시도를 위한 여분만 분리한다.
5. 어종/회차마다 대표 전략을 정하고 어종당1행으로 합친다. 다른 전략과 추가 준비는 펼치기에서 제공한다. 비슷한 특성의 상위 후보를 그대로 보여주며 유형별 할당은 하지 않는다.

**T: 지금 시작해야 하는 이유**

- 선행 구간 마감과 목표 시각에서 첫 도전 준비의 권장 시작을 역산한다. 항상 가능한5분 준비를55분 일찍 시작하는 것을 ‘지금 필요한 준비’로 만들지 않는다.
- 반대로 선행 기회가 지금뿐이라면 이후 현장 대기가 길어도 착수 필요성은 높다. 불가피한 현장 대기를 T에서 다시 크게 감점하던 식은 폐기한다. 작업 시간·자유 대기·유지하며 대기를 별도로 보여주고 비슷한 후보의 판단 보조로 사용한다.
- 준비 시간 자료는 `대표 계획 여유`와 `짧은/넉넉한 추정 범위`를 구분한다. 대표값은 검토한 설계 추정이며 실측 평균이 아니다. 상한만 늘렸다고 T가 자동 상승하지 않게 한다. 범위는 Q와 불확실성 표시에 사용한다. 대표값조차 정할 근거가 없으면 시간을 확정하지 않는다.
- 기본 완화식은 `T=1/(1+권장 시작까지 남은 분/20)`으로 제안한다. 이미 시작할 시점이면1이며 지나치게 늦었는지는 Q/조건 판정이 담당한다. 기술이 가능한 시간에 실제로 배치되는지 대조하고 고정 분 수만으로 판단하지 않는다.

**Q: 목표 시전까지 남는 시간**

- 앞선 ‘출현 중 첫 선행 단계에 들어가면 준비 여유가 충분하다’는 정의를 수정한다. 롱카의 물뱀이라면 Priest를 노리기 시작하는 시점과 실제 목표로 생미끼를 이어갈 수 있는 시점이 다르다. 출현 중 필수 연쇄/직감 발동까지 포함하고, 마지막 목표 시전이 대상 조건·직감 조건 안에 들어가는지 검토한다. 어획 완료를 출현 종료 전에 끝내야 한다고 계산하지 않는다.
- `남은 시간/원래 회차 길이`만 쓰는 식도 폐기한다. 길게 열렸던 어종의 남은2분이 원래90초 출현인 어종보다 자동으로 불리해지는 문제를 막는다. 절대 잔여와 목표 진입 추정 범위를 사용한다.
- 구현값은 기준/긴 준비 추정이 모두 가능하면1, 기준만 가능하면0.75, 짧은/긴 추정 중 하나만 가능하면0.5, 모든 추정이 늦으면0이다. 이는 거친 준비 시간 비교이며 성공 확률이 아니다. 일부 가정만 가능한 경우와 모든 가정이 늦는 경우를 명시하고 준비 범위·남은 시간을 제공한다.
- 상시 대상도 직감 유효 시간/중간 단계 제한을 먼저 확인한다. 조건상 종료 제한이 모두 없는 경우는 충분한 시간 여유로 처리한다. 종료 미확인이나 필수 단계 시간 미확인을 상시/Q=1로 바꾸지 않는다.
- 핵심 단계의 시간은 확인되지 않았는데 Q만1로 두거나 근거 없는 빠른 시나리오를 만들지 않는다. 일반 추정으로 계산할 수 있으면 근거를 붙이고, 시간 비교 자체가 불가능하면 순위 미정 후보로 제공한다.

**대표 선택과 불확실성**

- 깊이/직감 여부/터주왕 등급 자체에는 가감점을 주지 않는다. 한 준비의 불확실성을 전체 희소성 점수까지 곱해 낮추지 않는다. 준비 추정이 모두 늦는 어종은 지금/미리 준비에서 제외하고 희귀 어종에서 ‘준비 추정상 이번 출현 내 첫 투척 불가’로 표시한다.
- 어종 내 비슷한 전략을 선택할 때는 최고점 기준의 고정 범위(임시3점 이내)를 먼저 구한 뒤 선택 작업/현장 체류가 적은 전략을 택한다. ‘둘 차이가3점 이하면 동점’인 쌍별 정렬 비교는 비추이적 결과를 만들 수 있으므로 사용하지 않는다.
- 일반 추정 후보는 근거 수준과 함께 순위에 포함한다. 필수 규칙/시간이 없어 총점 비교가 불가능한 후보는 순위 미정으로 남기되, 그 개수와 접근 경로를 항상 표시한다. 미수집 후보가 모두 계산 보류여도 ‘추천할 어종 없음’으로 숨기지 않는다.
- 점수표의40/30/20/10, 완화20분, Q 등급, 근접3점과 지금 행동 기준5분은 설계 상수다. 고정 입력 회귀 검사는 통과했지만 실제 준비 시간·추천 품질을 실측한 것은 아니다. 미리 준비/희귀 어종은 각각 별도 정렬을 적용한다.

## 정보 제공 방식

메인의 ‘추천’에서 **지금 노릴 어종 / 밑작업 / 출현 드문 순**을 전환한다. 기본 미수집 터주·터주왕이며 한 탭에 어종당 한 행을 제공한다. 같은 어종이 서로 다른 목적의 탭에 나올 수 있다. 세 탭은 선택한 기간과 필터를 공유한다.

- 상단은 왼쪽 세 탭/개수와 오른쪽 갱신·앞으로1/3/6/12/24시간·필터·도움말을 한 줄에 배치한다. 조작부는 실제 번역 문구 폭으로 예약하고 탭은 남은 폭에서 기본 가로 넘김을 사용한다. 기간 선택 툴팁/도움말에서 현재 출현도 포함함을 설명한다. 도움말은 조회 범위/준비 가정을 구분하고 폭/높이를 화면 안으로 제한한다.
- 탭 이름 옆에 개수를 표시하고 정렬 설명은 탭 툴팁으로 옮긴다. 조회 시각/갱신 가능 안내는 하단의 추천 제외 버튼 옆에 표시한다. 순위는 자동 갱신하지 않는다.
- 전체 폭 목록을 사용하며 고정 선택 상세 영역은 없다. 행을 누르거나 ‘상세 보기’로 기존 어종 상세를 바로 열고, ‘추천 근거’로 준비 어종별 일정·이유·계산값 팝업을 연다. 지도/버튼 클릭은 행 클릭과 분리한다. 팝업은 조회 세대/캐릭터가 바뀌면 폐기한다.
- 목록은 기존 FishRowRenderer의 아이콘/등급·미끼 연결·직감 배지·지도 핀을 공유하고 날씨·ET는 표시하지 않는다. 지원 최소 폭에서도 세 열/세 줄을 유지한다. 첫 줄은 이름/등급·출현 횟수, 출현 상태, 오른쪽 끝 상세·근거 버튼이다. 둘째 줄은 지도/낚시터, 구간/준비 어종 이름·수량, 다음 회차이며 셋째 줄은 미끼와 나머지 폭의 짧은 추천 이유다. 두 열/다섯 줄 전환을 제거했다. 긴 값은 잘림 툴팁으로 확인한다. 세로 간격은 글꼴0.18배 이하로 제한하고 가상 목록도 같은 높이를 사용한다.
- 출현 구간은 오늘/내일/날짜와 자정 통과를 구분한다. 고정 시간·날씨 조건이 없는 직감 대상은 ‘직감 준비 어종 · 오늘 HH:mm 출현/출현 중 · N분 남음’을 표시하고 이름·필요 수량을 연결한다. 다음 회차는 목록의 구간이 끝난 뒤의 출현이며, 빈도가 준비 어종 기준이면 이름을 붙인다. 준비 시작 추정값을 출현 시각으로 사용하지 않는다.
- 직감 준비 어종의 일정은 선택한 계획의 직감 어획 단계가 속한 각 어종 자체 달력에서 작업자가 캡처한다. 여러 구간에 나뉘면 구간별 계획 마릿수를 따로 표시한다. 목록 대표는 필요한 직감 어종 중30일 출현 횟수가 가장 적은 어종이며, 상세에는 다른 준비 어종도 이름/마릿수/실제 구간을 표시한다. 고정 구간이 없는 경우는 제한 없음, 지난 구간은 종료/재추천, 확인 불가는 미확인으로 남긴다. 준비 시작 추정은 계산 근거에만 둔다. 선별/정렬은 revision4를 유지한다.
- 준비 예상 요약·시간축·단계별 작업 목록·기본/보관 경로 선택·일정표 버튼은 제공하지 않는다. 추천 이유는 실제 확보할 어종 이름·먼저 닫히는 시각·사전 확보·다음 출현까지 공백을 사용한다. 희귀 탭은 현재 기간/필터 후보 안의 빈도 순위와 횟수(동률 공동 순위)를 설명한다. 보관 경로가 있는 롱카는 미리 확보할 생미끼 이름과 기술 조건을 안내한다. 원래 미끼·직감 조건은 기존 어종 상세에서 확인한다.
- 추천 이유는 ‘출현 전에 잡아둘 직감용 어종: …’, ‘이번 출현이 끝나면 … 뒤에 다시 나타납니다’ 등 이름/마감/간격의 사실로 표시한다. 빈도가 이미 보이므로 희귀 탭과 별도 어종 준비 없는 후보는 가능하면 다음 기회까지의 간격을 이유로 쓴다. 팝업의 ‘계산 근거’는 실제 준비 시작 예상·사전 확보 어종·필요시 첫 투척 예상·빈도를 보여준다. 값은 조회 시점의 고정 추정이며 점수 합산식은 노출하지 않는다.
- 일반 생미끼 경로는 ‘보관 없이 진행 · 미끼용 …부터 확보’, 실제 선택된 계획에 보관 단계가 있으면 ‘생미끼 보관 사용 · 보관할 어종: …’로 구분한다. 다른 대안 경로에 보관이 있다는 이유만으로 보관 사용을 표시하지 않는다. 임시 준비 예산에 따른 첫 투척 추정을 확정적인 도전 가능 문장으로 바꾸지 않는다.
- 하단은 높이를 미리 확보한 한 줄 고정 영역이다. 조회 시각/갱신 가능 문구는 줄바꿈하지 않으며 폭이 부족하면 조회 시각만 표시한다. 추천 제외 버튼은 가용 폭60% 이내로 제한하고, 긴 설명은 툴팁/팝업으로 제공한다. 추천 내용 전체의 바깥 스크롤은 막고 목록만 스크롤한다.
- 시간·날씨 제한이 있는 목표는 빈도 기준 어종과 별개로 목표 자체의 다음 출현을 표시한다. 고정 출현 시각이 없는 대상만 준비 어종의 다음 출현을 이름과 함께 보여준다. 이 표시를 위해 기존 달력에서 목표 다음 출현을 별도 보관하며 점수/선별/정렬은 변경하지 않는다. 기간·추정 가정·유지 조건·복합 빈도의 한계는 도움말/툴팁에 둔다.
- ‘추천 제외·확인 필요’로 범위 밖·자료 부족·연결 불가·추정상 늦음의 사유와 어종 상세를 볼 수 있다. 지금 후보가 없다고 먼 미래 어종으로 몰래 채우지 않는다.
- 수동 갱신 전 출현이 시작된 밑작업 행은 순서를 바꾸거나 자동 제거하지 않고 ‘출현 시작 · 갱신 필요’와 재조회 안내로 사전 준비 가능 안내를 대체한다. 고정 출현 시각 없는 직감 대상도 대표 준비 어종의 구간이 끝나면 종료/갱신 안내를 표시한다.

시각은 PC 현지 시각, 원래 게임 조건은 기존 상세의 ET를 따른다. 준비 시간은 실측 평균이나 성공 약속이 아닌 설계 추정이다. 후보 선택은 게임 이동·미끼 변경·알림 등록을 실행하지 않는다.

### 출현 알림과의 관계

알림0~120분/새 설정 기본0분은 이미 구현됐으며 [현재 낚시터 알림의 로컬 채팅 형식](TROPHY-FISHING-PROPOSALS.md#현재-낚시터-출현-알림-논의-2026-10-24)은 합의됐지만 신규 낚시터 알림은 미구현이다.

- 추천 순위 변화는 채팅으로 자동 발송하지 않는다. 추천은 사용자가 열어 보는 선택 화면이다.
- 합의한 로컬 채팅 형식은 `{어종 링크} 출현 시작 - {상세 보기 링크} - 남은 시간`이다. 현재 낚시터 인식/중복 방지는 별도 알림 구현 작업에서 다룬다.
- 대상 자체 시간/날씨 출현, 선행작 가능 시점, 개인 직감 발동은 서로 다른 사건이다. 직감형 출현 메시지는 개인 준비 완료를 뜻하지 않으며 ‘직감 필요’를 명시하는 방안을 제안한다. 순수 직감형에 공통 출현 시작 사건을 임의로 만들지 않는다.
- 준비 시작 알림은 이 추천의 첫 범위에 추가하지 않는다. 자동 추천과 기존 사전 알림 시간을 연결하면 기존0분 기본값/120분 상한의 뜻이 바뀌므로 별도 결정이 필요하다.

## 구현 계획과 기존 코드 연결

### 1단계: 순위 계산과 이유를 검토할 수 있는 Core

- `Core/Recommendations`에 작은 준비 단계/전략 자료형, 단계별 시간 배치, 빈도 지표, 점수 계산을 둔다. 사실 조건과 전략 추정을 분리한다. Dalamud/Lumina/ImGui 의존성과 게임 관찰은 추가하지 않으며 범용 계획 프레임워크를 만들지 않는다.
- 입력: UTC 평가 시각, 탐색 기간, 읽기 전용 조건/날씨 자료, 대상 ItemId/수집 판정, 버전 있는 전략/시간 추정, 보관 전략 포함 등 기술 사용 가정. 현재 도전 상태·실제 버프·직감 누적·보관 생미끼를 받지 않는다.
- 결과: 어종/회차/전략 식별자, 자체 조건 구간, 출현 전 작업/권장 시작, 필수 선행 기회, 출현 중 남은 단계, 선택 보관/소진 후 경로, 현장 유지/대기, 대안 전략, 다음 기회, 빈도·점수 구성, 이유/근거/누락 코드. 표시 문장 대신 안정적인 코드와 인자를 반환한다.
- `FishingAvailability`의 시간/날씨 열거를 같은 Core 안에서 재사용한다. 기존 `FishingForecast`는 참고하되 빈도에서는 버프 시간 때문에 분할/연장된 구간의 독립 기회 여부를 별도로 정규화해야 한다. 이 보완이 없는 중간 결과를 완전한 직감 기회 빈도로 보고하지 않는다. 기존 알림/일정표 소비자의 예측 계약은 변경하지 않는다.
- 일반 직접/생미끼/상시 선행 직감의 템플릿부터 만든다. 동시에 롱카의 물뱀(중간 보관·출현 중 연쇄), 홍룡(제한 생미끼·반복), Charibenet(직감 요구와 미끼 공유), 칠채천주(선행 시간대 분리), 스테타칸투스(선행 터주·발동 전략)를 기준으로 모델을 검토한다. 보관을 나중에 문자열 설명만 덧붙이는 구조로 만들지 않는다.
- 코드 확장 전에 위 대표 어종의 실제 전략 자료를 작성할 수 있는지 확인한다. 현재 내장 자료로 아는 조건과 추가 확인이 필요한 보관/발동/시간 가정을 목록화한다. 초 단위 입질·어획 확률·GP 최적화 전체를 이번 기능의 필수 전제로 만들지 않는다. 대표 자료를 만들 수 없는 상태에서 단계 모델만 복잡하게 늘리지 않는다.
- 시간 제한 직감13종·깊은 생미끼·공유 어획8종을 집중 보완하고, 자동으로 결정할 근거가 없는 사례에는 기본 경로/미확인 사유를 남긴다. 단순 경로만 구현한 중간 결과를 사용자 요구 전체의 완료로 보고하지 않는다.

### 2단계: Plugin의 비동기 후보 계산

- `FishCatalogView`의 자료/Forecast와 수집 snapshot을 관리 값으로 복사해 사용한다. `SpawnSchedule`의 취소·session/revision 검사·오래된 결과 폐기 패턴을 참고한다.
- 30일 빈도는 자료 버전·날씨 자료·계산 모드·분석 기준일별 캐시로 둔다. 지역/수집 필터나 보관 준비량만 바뀌었다고 장기 빈도를 다시 돌리지 않는다. 전략 계산 캐시는 별도로 전략 revision/기술 가정/평가 시각을 포함한다. 분석 기간을 표시하며 UTC 날짜 경계에 백그라운드 갱신한다.
- 사용자 후속 결정으로 자동 순위 갱신안을 수동 재추천으로 바꿨다. 탭 진입·필터 변경·갱신 때 계산하고 카운트다운/변경 안내만 계속 갱신한다. Draw에서 파일 읽기/전체 검색/장기 예측을 하지 않는다.
- 계산 시각은 주입 가능한 TimeProvider와 UTC를 사용한다. 화면 활성 유지 감시는 단조 시계로 관리하고 시스템 시각 점프는 갱신 안내만 한다. 화면 종료/플러그인 종료/캐릭터 전환에서 취소하고 이전 세션 결과를 표시하지 않는다.
- 첫 버전은 물고기의 눈 OFF의 일반 조건으로 제안하며 화면에 명시한다. 기존 공통 Fish Eyes ON을 조용히 따라가거나 ON인데 일반 추천인 것처럼 혼용하지 않는다. 지원 어종/선행 조건을 함께 바꾸는 추천 모드는 후속으로 다룬다.

### 3단계: 합의한 화면 연결과 어종 보완

- 추천 진입 위치와 목록 구조를 합의한 뒤 실제 UI를 구현한다. 기존 상세·지도·일정표의 사용자 클릭 경로를 연결한다.
- 한영 TextKey/.resx 전체 문장, 번역과 독립인 ImGui ID를 사용한다. 캐시에 번역된 문장을 저장하지 않는다.
- 새로운 저장 설정을 도입할 경우 기존 값/백업 계약과 캐릭터 수집 분리를 함께 확인한다. 첫 작업에서 사용자별 학습이나 원격 통계 수집을 추가하지 않는다.
- 검증한 복잡한 어종 보완을 순차 적용한다. 원본 조건 ID/수량/시간을 준비 추정값으로 덮어쓰지 않는다. 외부 자료 도입은 URL·고정 revision/해시·라이선스·가공 내역을 먼저 기록한다.

### 자가 점검에서 수정한 허점과 남은 불확실성

2026-10-25 후속 요청으로 문서와 현재 `FishingForecast` 계약을 읽고 반례를 검토했다. 아래는 설계 논리의 검토이며 제품 테스트·게임 실기·추천 결과의 성능 측정이 아니다. 새로운 게임 규칙을 확인했다는 보고도 아니다.

| 기존 허점 | 반례/영향 | 수정 |
|---|---|---|
| Q와 V가 같은 준비 부족을 중복 반영 | Q가 낮아져 원점수90이 된 뒤 V=0.7을 곱하면63으로 떨어져 희소성까지 일괄 감점 | V 삭제, 시간 여유는 Q에서 한 번 반영 |
| 선행 단계 진입만으로 도전 여유 판단 | Priest를 노릴 수 있어도 목표에 시전할 준비/시간은 아직 확보되지 않음 | 남은 연쇄와 직감 발동까지 포함해 첫 목표 시전 검토 |
| 선택 준비 +10 상한 | 무엇을 기본 전략으로 이름 붙였는지에 따라 상한이 바뀜 | 상한 삭제, 첫 도전 계획과 추가 재시도 준비 분리 |
| 대기를 T에서 크게 감점 | 지금뿐인 선행작 뒤 대기가 길면 필수 착수 후보를 밀어냄 | 착수 필요성과 체류 부담 분리 |
| 넉넉한 시간 상한으로 착수 시점을 정함 | 더 불확실한 추정일수록 일찍 추천되는 역효과 | 대표 계획 여유와 범위/근거 수준 분리 |
| uptime을 희소성에 혼합 | 출현 빈도와 무관한 직감 지속/가정값이 희소성에 영향을 줌 | 독립 조건 기회 빈도로 단순화, 조건 근거 표시 |
| 준비 미확인 후보를 보류만 함 | 사용자에게 중요한 복합 어종이 목록에서 사라질 수 있음 | 순위 미정 수/접근 경로를 항상 제공 |
| 기간 밖 조회/긴 후보 행/모호한 근접 정렬 | 사용자가 고른 범위와 화면 기대를 어기고 정렬 결과가 흔들릴 수 있음 | 범위 준수,2~3줄 요약, 최고점 기준 근접 집합 선택 |

가장 큰 잔여는 **준비 시간·전략별 효과의 실제 자료가 부족하다는 점**이다. 상수를 더 늘리는 것으로 해결되지 않는다. 다음 구현 전 작업은 대표5종의 전략/필수 조건/시간 가정을 실제로 작성하고, 일반 어종의 기본 추정과 미확인 처리의 경계를 정하는 것이다. 이후 후보 결과를 보고40/30/20/10을 조정한다. 현재 단계에서 최적 전략·안정된 순위·모든 어종의 정확한 준비 시간을 약속하지 않는다.
