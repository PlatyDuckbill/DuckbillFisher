# 다음 도전 추천과 현재 목표 지원 — 논의 초안

2026-10-25. 사용자가 터주작·생미끼·직감의 특성과 정보 제공 방식/범위를 함께 재검토하도록 요청했다. 이 문서는 조사에 따른 제안이며 추천 기능·화면·수동 준비 입력·새 관찰 기능의 구현 승인은 아니다. 알림0~120분/기본0분은 구현됐고 [현재 낚시터 알림의 로컬 채팅 형식](TROPHY-FISHING-PROPOSALS.md#현재-낚시터-출현-알림-논의-2026-10-24)은 합의됐지만 해당 신규 알림은 미구현이다.

## 추천의 목적과 단위

- 추천 단위는 **어종 × 낚시터 × 특정 출현 회차 × 남은 준비 계획**이다. 같은 어종도 지금 보유한 생미끼/직감 진행에 따라 도전 가치가 달라진다. 현재 목표를 유지하거나, 준비하거나, 다음 목표로 이동할지를 설명한다.
- 기본 목표 제안은 일반 필드 낚시의 미수집 터주·터주왕이다. 즐겨찾기만/현재 필터 결과는 선택 범위로 둔다. 선행 일반 어종·이미 수집한 어종도 준비 경로에 필요하면 표시한다. 목표 수집 필터를 준비 어종에 적용하지 않는다.
- 사용자가 정한 플레이 종료 시각 안의 기회를 우선한다. 장시간 대기가 필요한 밑작은 별도 장기 목표로 선택할 수 있게 제안한다. 추천 탐색 기간과 사전 알림의120분 상한은 서로 다른 설정이다.
- 첫 목표는 준비 조건과 다음 행동을 설명하는 것이다. 어획 성공률·최적 동선·준비 완료 시각을 근거 없이 확정하지 않는다. 장기 전체 경로 최적화나 자동 게임 조작은 범위에 넣지 않는다.

## 낚시 특성에서 필요한 구분

| 요소 | 알고리즘에 미치는 영향 |
|---|---|
| 시간·현재/직전 날씨 | 대상 자체의 조건 구간과 선행 어종의 조건 구간을 각각 유지한다. 직전 날씨 조건만으로 플레이어가 이전 날씨부터 현장에 있었어야 한다고 판단하지 않는다. |
| 생미끼 연쇄 | 깊이는 경로의 길이일 뿐이다. 중간 어종의 제한·입질/어획 부담과 현재 남은 단계가 필요하다. 일반 가방의 물고기를 생미끼 준비 완료로 세지 않는다. |
| 생미끼 반복 | 같은 어종을 다시 생미끼로 쓰는 반복 경로가 있다. 무조건 순환 오류로 처리하지 않고, 검증한 반복 규칙을 제한된 탐색으로 다룬다. 내장 권장 BaitSteps만으로 모든 반복/대안 경로를 복원하지 않는다. |
| 월척·생미끼 기술 | 인내/월척은 월척 확보와 생미끼 자원에 관련된다. 터주 입질 확률과 같은 뜻으로 점수를 주지 않는다. 생미끼II·활용 기술·보관 생미끼는 사용 가능 조건과 소모 자원이 다르다. |
| 직감 선행작 | 선행 어종별 수량과 누적 상태를 관리한다. 각 선행 어종의 출현 시간이 동시에 겹칠 필요는 없고, 유지 조건 안에서 여러 시기에 나눠 준비할 수 있다. 원본 배열 순서를 모든 어종의 필수 어획 순서로 해석하지 않는다. |
| 직감 발동 시점 | 마지막 조건을 일찍 채우면 대상 조건이 열리기 전에 버프 시간이 소모될 수 있다. 선행작 완료와 마지막 발동 어획을 구분한다. 특정 소장품의 수령 보류 같은 예외는 검증한 어종별 전략으로만 다룬다. |
| 복합 조건 | 마지막 직감용 어획이 생미끼로도 쓸 수 있다면 같은 어획이 두 조건을 충족할 수 있다. 모든 준비량을 독립으로 단순 합산하지 않는다. 반대로 필요한 수량을 공유 조건이라는 이유로 삭제하지 않는다. |
| 복수 어획 | 요구 마릿수와 필요한 시전 횟수는 다르다. 이중/삼중 낚아채기 적용·수량·GP가 영향을 준다. 현 프로젝트의 자동 수량 관찰 보류를 이번 논의로 해제하지 않는다. |
| 진행 중 시전 | 출현/직감 종료 시점 이후에도 그 전에 시작한 시전이 남아 있을 수 있다. 남은 시각0만으로 실패나 즉시 이동을 권하지 않는다. 루어 재추첨의 시간 경계는 별도 고려한다. |
| 루어·교환 방생 등 | 후보 어종군과 시도 효율이 달라지고 일부 어종은 루어가 조건이다. 필수 조건과 효율 전략을 구분한다. 입질 강도만으로 낚아채기나 루어 종류를 추측하지 않는다. |
| 물고기의 눈 | 확인된 어종의 시간 제한을 다루며 날씨·직감 전체를 없애는 모드가 아니다. 대상이 미지원이어도 지원 선행 어종의 준비에는 영향을 줄 수 있다. 가정 모드와 실제 효과 관찰을 분리한다. |

상태는 **현재 낚시터 / 선행 어획 누적 / 직감 버프 / 생미끼 기회·보관**를 각각 관리해야 한다. 낚싯대를 접어 현재 낚시터 알림 감시를 끝내는 것과, 실제 게임의 직감 누적이 사라졌다는 판정은 다르다. 직감 누적의 지역/낚시터 전환, 보관 생미끼의 낚시 유지 등 상태마다 범위가 다르다. 원문 가이드는 현재 로그아웃에도 직감 누적이 유지된다고 설명하지만 오래된 가이드에는 반대 설명이 있으므로, KR 구현에서 재로드/로그아웃을 자동0으로 가정하지 않는다. 관찰 연속성이 끊기면 관측값의 확실성을 낮추고 수동 상태는 구분해 보존한다.

## 알고리즘 제안

1. **대상과 현재 상태를 확보한다.** 수집·지역/낚시터·미끼·지원 기술/전승록 등에서 확인된 값과 Unknown을 구분한다. 수집 Unknown을 미수집으로 넣지 않는다. 장비/전승록 등의 확인되지 않은 개인 조건은 준비 완료로 간주하지 않는다.
2. **출현 회차와 준비 경로를 만든다.** 대상 자체 시간/날씨, 선행 어종별 기회, 직감 발동/유효 시간, 생미끼 소모·재확보·반복을 연결한다. 선택 가능한 미끼는 대안이며 직감 요구 목록은 모두 필요한 조건이다. 특수 전략은 출처가 고정된 어종별 규칙이 있을 때만 연결한다.
3. **현재 남은 준비를 계산한다.** 관찰 또는 사용자 확인이 있는 누적량/생미끼는 반영한다. 관찰이 시작되기 전의 어획을0으로 두지 않는다. 현재 직감 버프가 어느 목표에 해당하는지 확인되지 않으면 모든 직감 어종을 준비 완료로 만들지 않는다.
4. **도전 시간과 준비 시간을 구분한다.** 대상 자체 구간을 `[S,E)`로 두고 현재 유효한 직감 종료가 확인되면 새로운 도전을 시작할 끝 시각은 `min(E, 직감 종료)`다. 이동·준비 완료의 근거 있는 범위가 있을 때만 도전 시작 범위를 추정한다. `종료-max(현재+이동+준비, 시작)`는 단순한 경우의 요약이며 여러 차례 선행작/소모/재발동을 대표하는 만능 공식이 아니다.
5. **가능성별로 표시한다.** 조건상 도전 후보, 선행 준비 필요, 준비를 유지하며 대기, 이번 회차 준비 어려움, 확인 필요를 구분한다. 확실한 불가와 추정 시간이 빠듯한 경우를 동일하게 제외하지 않는다. 항상 출현 어종은 가짜 시작 시각을 만들지 않는다.
6. **우선순위를 정한다.** 사용자 선택 목표 → 현재 활용 가능한 준비/진행 중 시전 → 이번 회차를 놓쳤을 때 다음 유효 기회 → 이번 플레이 시간 내 도전 여유 → 남은 준비 부담·이동 순서를 기본 제안으로 둔다. 현재 목표의 준비를 버리고 이동할 때는 손실 이유를 표시한다. 과거에 쓴 시간 자체가 아닌, 앞으로 활용/재준비할 상태의 가치를 비교한다.
7. **다음 행동과 이유를 제시한다.** ‘현재 목표 유지’, ‘선행 어종 준비’, ‘다음 목표로 이동 검토’, ‘준비 상태 확인’처럼 표현한다. 목표 선택을 자동 교체하지 않고 출현 경계·준비 변경·수집·대상 변경에서 재평가한다. 카운트다운만 변했다고 순위를 매초 흔들지 않는다.

‘기회 우선’을 기본으로, 준비 부담/이동을 앞세운 ‘가벼운 도전’을 선택할 수 있게 제안한다. 낮은 입질률, 높은 놓침률, 드문 시간표는 다른 정보다. 첫 버전은 확인된 시간표와 준비 부담으로 비교하며 알 수 없는 확률을 숫자로 채우지 않는다. 다음 회차를 제한된 검색 기간 안에서 찾지 못하면 해당 범위를 표시하고 무한 희귀도로 취급하지 않는다.

## 현재 자료와 관찰로 가능한 범위

- 내장 조건에는 시간/날씨·미끼 단계·직감 어종/수량·일부 지속 시간·루어/전승록/물고기의 눈 지원 여부가 있다. 모든 전략/생미끼 반복 경로·개인 능력·입질 확률·준비 시간 분포가 들어 있는 것은 아니다.
- 기존 `FishingForecast`의 직감 계산은 출현 준비 기회를 제한하는 계산이다. 실제 선행 수량·준비 소요·이미 확보한 누적을 입력받지 않고 생미끼 연쇄의 준비 시간도 계산하지 않는다. 새 추천의 개인 준비 판정으로 그대로 사용할 수 없다. 과거에 준비한 어종의 구간이 이미 끝났다고 실제 준비를 무효로 처리하지 않는다.
- 직감 지속 시간 미확인9종에 대한175초 가정은 기존 예측 표시의 정책이다. 이를 실제 버프/확정 가능한 도전 시간으로 승격하지 않는다.
- `FishingBuffObserver`는 실제 직감 종료 시각을 읽지만 현재 `CastingTimerWindow.OnOpen/OnClose`가 관찰을 켜고 끈다. 추천/알림에서 사용하려면 화면을 닫았을 때의 구독 수명과 표본 신선도를 별도로 설계한다. 버프 있음만으로 대상 어종 연결이나 선행 누적 복원을 보장하지 않는다.
- `FishingTracker`는 현재/최근 낚시터·일반 생미끼 전이·보관 생미끼를 구분한다. 보관의 대표 실기 근거는 첫 칸 사용이며 나머지 칸/복수 보관의 전수 확인을 대체하지 않는다. 미끼 준비 목록은 첫 실제 미끼 중심이며 직감 선행 미끼 전체를 자동으로 준비 완료로 계산하지 않는다.
- 직감 선행 실제 마릿수와 복수 어획 수량의 자동 추적은 현재 제공하지 않는다. 첫 버전은 사용자가 목표별 준비 상태를 선택적으로 입력/확인하는 방안과, 입력 없이 준비 미확인을 표시하는 방안을 논의한다. 수동 값에는 출처와 확인 시점을 표시하고 자동 관찰값과 섞어 확정하지 않는다.

## 정보 제공 방식 제안

| 위치 | 보여줄 정보 |
|---|---|
| 추천 목록 | 현재 목표 유지 판단 + 다음 후보 약3개. 어종·낚시터·출현 시작/종료·다음 기회·현재 필요한 준비·핵심 추천 이유. 세부 수치 점수보다 이유를 우선한다. |
| 선택 어종 상세 | 생미끼 연쇄/대안, 직감 선행 어종별 요구/확인 수량·출현 구간, 마지막 발동 조건, 현재 직감 시간, 미끼/전승록 등 준비, 손실·미확인 표시. 기존 상세/메모/프리셋을 재사용한다. |
| 기존 일정표 | 대상 도전 구간과 앞서 준비할 구간을 함께 볼 수 있는 표현을 검토한다. 예측 구간·사용자 지정 준비 시간·실제 직감 구간을 구분한다. |
| 로컬 채팅 | 합의한 `{어종 링크} 출현 시작 - {상세 보기 링크} - 남은 시간`. 추천 순위 변화는 기본 채팅 대상에 넣지 않는다. 선택 목표의 준비 알림은 별도 선택 사항으로 둔다. |

화면 구조는 미합의다. 메인에 추천용 탭/진입을 두고, 기존 상세·일정표·타이머를 연결하는 구성을 우선 제안한다. 타이머에 대규모 추천 목록을 자동으로 끼워 넣거나 별도 팝업을 임의로 추가하지 않는다.

현재 낚시터 알림에서 **대상 자체의 시간/날씨 출현 시작**, **직감 선행작 기회**, **개인 직감 발동**은 서로 다른 사건이다. 직감 필요 어종의 예정 구간이 열렸다는 이유로 개인 준비 완료를 알리지 않는다. 순수 직감형 어종은 모든 플레이어에게 동일한 출현 시작이 없을 수 있다. 기본 메시지 형식은 유지하되 직감 필요 표식, 직감 발동 알림의 별도 사용 여부를 논의해야 한다. 출현 잔여와 실제 직감 잔여를 하나의 무표시 숫자로 합치지 않는다. 종료 뒤 남아 있는 시전은 별도로 유지한다.

## 첫 구현과 검토 사례

- 1차 제안: 지원 KR 자료의 일반 필드 미수집 터주·터주왕, 준비 경로/부담 설명, 제한된 기간의 기회 비교, 현재 목표 선택/유지, 기존 상세 연결. 미확인 준비는 명시하고 선택적 수동 확인을 논의한다.
- 후속: 충분히 검증된 준비 상태 관찰, 특수 어종 전략/반복 경로, 사용자별 준비 시간 범위, 보다 긴 일정 계획. 자동 수량/입질 통계는 기존 보류와 별도로 다시 합의해야 한다.
- 먼바다·작살·우주개척·이슈가르드 부흥의 독자 규칙은 첫 추천 범위에서 제외하는 것을 제안한다. 새로운 기술별 네이티브 관찰은 정확한 KR 계약 검토 후 별도 작업이다.
- 검토 사례: 홍룡의 제한된 중간 생미끼/반복·보관 준비, 칠채천주의 서로 다른 시간대 선행작, 스테타칸투스의 선행 터주/수령 보류 전략, 직감 마지막 어획과 생미끼가 겹치는 경우, 직접 낚시지만 기회가 짧은 어종, 출현 종료 후 진행 중 시전, 직감 갱신, 이미 준비한 선행 어종의 시간 종료, 미수집 목표를 위해 수집 완료 선행 어종을 다시 잡는 경우.
- 이 사례 목록은 이번에 실행한 테스트가 아니다. 구현·테스트 추가/실행·KR 실기는 이번 논의에 포함하지 않았다.
