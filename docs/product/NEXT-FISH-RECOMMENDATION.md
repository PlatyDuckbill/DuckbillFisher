# 지금 시작할 터주작 추천 — 조사와 구현 계획

2026-10-25. **목적은 ‘지금 터주작이나 해볼까?’에 답하는 여러 후보 제공**이다. 현재 도전 중인 목표·이미 확보한 생미끼·직감 진행도·실제 버프는 고려하지 않는다. 모든 후보를 지금부터 새로 준비한다고 가정한다. 사용자는 여러 요소를 함께 평가하는 방향과 복수 후보 제공에 동의했다. 아래 수치·기본값·화면 배치는 구현을 위한 제안이며 확정된 게임 사실/합의된 화면이 아니다. 이번 작업은 조사·계획 문서만 변경하며 기능은 미구현이다.

## 합의한 목적과 범위

- 출현 빈도, 생미끼/직감 준비, 지금 시작할 적절성, 이번 기회에 도전할 여유를 함께 평가한다. 시간순이나 희귀도 하나만으로 정렬하지 않는다.
- 같은 평가 방식으로 상위 후보 여러 개를 제공한다. 모두 비슷한 특성이어도 그대로 보여준다. ‘간단한 어종 하나/희귀한 어종 하나/직감 어종 하나’처럼 유형을 강제로 배분하지 않는다.
- 생미끼 단계가 깊거나 직감이 필요하다는 사실 자체를 감점하지 않는다. 그만큼 일찍 준비를 시작해야 한다는 정보로 사용한다. 출현이1시간 뒤여도 준비에40~60분이 필요하면 지금 추천할 수 있어야 한다.
- 준비 시간과 점수의 완벽한 정확도보다 선택에 필요한 이유·일정·준비 조건을 제공한다. 추천 점수는 어획 확률이나 정답이 아니다.
- 현재 목표 유지/전환, 준비 진행도 입력, 실제 직감/생미끼 관찰, 여러 어종의 순회 동선 최적화는 이번 추천 범위에 넣지 않는다. 기존 수량/입질 통계 보류도 유지한다.

첫 대상은 **일반 필드의 미수집 터주·터주왕**으로 제안한다. 수집 Unknown은 미수집으로 확정하지 않으며 ‘수집 상태 미확인 포함’으로 명시적으로 넓힐 수 있다. 준비용 일반 어종과 이미 수집한 선행 어종에는 목표 수집 필터를 적용하지 않는다. 먼바다·작살·우주개척 등 별도 규칙의 콘텐츠는 첫 범위에서 제외한다. 장비·레벨·전승록·미끼 소지 여부는 이번 점수에서 개인별로 추정하지 않고 필요한 조건을 안내한다.

## 조사로 확인한 설계 요건

| 특성 | 추천에서 반영할 내용 |
|---|---|
| 드물게 출현 / 짧게 출현 / 잘 안 물거나 놓침 | 서로 다른 개념이다. 시간표의 빈도와 총 출현 시간을 계산하며, 입질률·놓침률을 그 값에서 유추하지 않는다. |
| 생미끼 단계 | 단계 수는 준비 부담의 기본 자료다. 중간 어종이 시간/날씨 제한이나 터주 등급이면 별도로 고려한다. 첫 미끼 대안은 생미끼 단계 수를 늘리지 않는다. |
| 생미끼 반복·보관 | 홍룡 등은 반복 경로가 있으며 보관 기술도 전략에 영향을 준다. 내장 BaitSteps만으로 모든 반복/보관 전략을 복원할 수 없다. 새로 준비하는 기준의 어종별 보완만 허용한다. |
| 직감 수량 | 요구 마릿수는 시전 횟수가 아니다. 이중/삼중 낚아채기 효과와 수량이 어종별로 달라 ‘마릿수×고정 초’는 실제 준비 시간으로 사용할 수 없다. |
| 직감 발동 | 선행작과 마지막 발동 어획을 구분한다. 일반 선행 어종은 발동 직전까지 준비하는 전략이 가능하지만, 터주 선행 어종도 동일하게 확보할 수 있다고 가정하면 안 된다. |
| 시간 제한 선행작 | 선행 어종들이 동시에 출현할 필요는 없다. 서로 다른 시기에 잡아 누적하는 경우가 있으므로 모든 시간 구간의 단순 교집합은 잘못된 제외를 만들 수 있다. |
| 직감+생미끼 | 마지막 선행 어획이 생미끼 역할도 겸하는 경우가 있다. 확인한 중복 작업만 한 번 계산하며, 같은 ItemId라는 이유만으로 역할·수량을 무조건 합치지 않는다. |
| 출현 중 도전 시간 | 표시하는 출현 잔여는 대상 조건의 시간이다. 직감 어종이 그 시간 내내 낚시 가능하다는 뜻은 아니다. 직감 지속·재발동은 별도이며 누락값은 확정하지 않는다. |
| 기술/전략 차이 | 인내·월척 확보, GP 운용, 루어 등은 실제 효율에 영향을 주지만 첫 버전에서 최적 기술 순서를 시뮬레이션하지 않는다. 필수 루어 등 확인된 조건은 상세에 제공한다. |

공식 기술 설명에서 복수 어획의 어종별 차이와 보관 생미끼의 유지/사용 조건을 확인했다.[한국 공식 가이드](https://guide.ff14.co.kr/job/Fisher/31?type=L) 일반 직감과 터주 선행 직감의 준비를 구분하는 이유, 생미끼 반복의 존재는 [Fruity Snacks의 가이드](https://docs.google.com/document/d/1B7wjAtw5uCiARS9tXsozYAX8l6JZOzl2YtJSjejqchk/edit)를 참고했다. 해당 경험적 전략을 어종별 소요 시간의 실측 평균으로 전환하지 않는다.

2026-10-25에 `data/fishing.kr.v2.json`과 `data/fish-classifications.kr.v1.json`을 ItemId로 결합해 읽기 전용 집계했다. 캐릭터 수집 여부는 적용하지 않은 자료 전체의 수치다.

## 계산 흐름

### 1. 후보 회차를 만든다

- 기본 탐색 기간은 **앞으로3시간**, 선택은1·3·6·12·24시간으로 제안한다. 이는 ‘그 안에 출현하거나 도전할 후보’의 범위이며 사용자가 그만큼 계속 플레이한다는 뜻은 아니다. 알림의120분 상한 및 빈도 분석의30일과 독립이다.
- 대상 자체의 시간/날씨 구간과 선행 어종의 구간을 분리해 보관한다. 기존 `FishingForecast`의 직감 반영 결과는 참고하되 실제 준비 완료나 모든 어종의 완전한 준비 계획으로 간주하지 않는다.
- 단위는 내부적으로 `어종 × 지원 낚시터 × 출현 회차`다. 현재 자료의 연결된 낚시터를 기준으로 하며 검증되지 않은 다른 낚시터로 확대하지 않는다.
- 각 회차를 평가한 뒤 **어종당 가장 적절한 회차 하나**를 목록에 남긴다. 같은 어종의 여러 회차가 추천 목록을 채우지 않게 한다. 나머지 회차는 상세/일정표에서 확인한다.
- 항상 조건이 열려 있는 어종은 가짜 출현 시작을 만들지 않는다. 직감만 필요한 어종은 ‘선행작 후 도전’으로 표현한다.

### 2. 준비 시간은 범위로 추정한다

준비 시간은 성공 보장/평균/확률 구간이 아닌 **추천용 여유 시간**이다. 다음은 초기 튜닝을 위한 설계 상수이며 실제 어종 기록에서 얻은 숫자가 아니다. 구현 전 대표 사례를 대조하며 변경할 수 있다.

| 준비 특성 | 초기 추정 제안 |
|---|---|
| 직접 낚시, 직감 없음 | 낚시 준비0~2분 |
| 일반 생미끼1단계 | 2~5분 |
| 일반 생미끼2단계 이상 | 첫 단계2~5분 + 추가 단계마다2~5분 |
| 시간 제한 없는 일반 어종 직감 | 선행 준비 전체5~15분을 기본으로, 여러 종류/많은 수량이면 범위를 넓힘 |
| 터주를 요구하는 선행작 | 일반 직감 기본값으로 확정하지 않고 넓은 범위/어종별 보완 적용. 초기 검토 범위20~60분, 초과 가능 표시 |
| 시간/날씨 제한 선행작 | 위 작업 시간에 시간표상 대기를 별도로 반영. 일정상1시간 이상도 가능 |

- 위치를 추적해 실제 이동 시간을 예측하지 않는다. 공통 이동·정비 여유는 초기2분 가정으로 두고 계산 근거에 노출한다. 사용자가 바꾸는 설정은 화면 합의 시 결정한다.
- 일반 생미끼와 직감은 서로 다른 준비 작업이면 더한다. 검증한 같은 어획의 중복만 보완 규칙으로 제거한다. 복합 경로를 정확히 모델링하지 못하면 ‘준비 추정 폭 큼’을 표시한다.
- 첫 목표 어종을 노리는 준비와 매 실패 후 생미끼 재확보 비용은 다르다. 후자는 ‘시도마다 생미끼 필요/반복 전략 확인’으로 설명하며 최초 준비 시간만으로 예상 어획 횟수를 계산하지 않는다.
- 어종별 보완은 소수의 명시적 자료로 둔다: ItemId, 준비 범위, 시간 제한 선행 어종, 공유 어획/발동 주의, 근거 URL·revision/열람일, 검토 KR 자료 버전. 본문 공략/외부 통계를 복제하지 않는다.
- 자료가 없으면0분으로 넣지 않는다. 기본 추정이 가능한 경우는 ‘일반 규칙 추정’, 불가능한 복잡한 사례는 ‘준비 확인 필요’로 남긴다. 어종마다 근거 없는 정밀 숫자를 채우는 전수 수작업은 하지 않는다.

### 3. 지금 시작하기 적절한지 판단한다

단순한 경우, 대상 출현을 `[S,E)`, 이동 여유를 `M`, 준비 범위를 `[P짧음,P넉넉함]`으로 둔다.

```text
준비를 시작할 권장 범위 = [S - M - P넉넉함, S - M - P짧음]
지금 시작했을 때 도전 시작 추정 = max(S, 지금 + M + P)
조건 구간 안의 남은 여유 = max(0, E - 도전 시작 추정)
```

예: 출현까지60분, 준비40~60분, 이동 여유2분이면 준비 시작 범위는 지금2분 전~18분 후다. 이미 준비를 시작할 만한 때이므로 후보로 올린다. 준비가 끝나고 기다리는 시간이 긴 경우는 ‘지금 시작하기 적절성’을 낮춘다. 출현 중이라는 이유로 준비가 끝나기도 전에 닫히는 어종을 높게 올리지 않는다.

시간 제한 선행 어종에는 이 식만 적용하지 않는다.

1. 지금 이후부터 목표 회차 종료까지 각 필수 선행 어종/중간 생미끼의 출현 기회가 있는지 확인한다. 과거 어획은 없다고 가정한다. 이전에만 가능했고 다시 기회가 없는 조건은 이번 회차 제외 근거다.
2. 선행 기회가 목표보다 일찍 끝나면 그 구간 안에서 준비할 수 있도록 시작 권고를 앞당긴다. 기다리는 시간과 실제 준비할 시간을 구분한다. 선행 기회를 기다려야 하면 그 지연을 준비 완료 추정에도 넣는다.
3. 마지막 직감 발동은 대상 조건과 유효 시간이 겹치도록 다룬다. 선행 어종 모두를 미리 잡은 순간부터 직감이 무한 유지되는 식으로 계산하지 않는다. 생미끼를 출현까지 보관/유지할 수 있는지도 검증한 규칙만 적용한다.
4. 첫 버전은 ‘필수 기회 없음’ 판정과 단순 선행 일정 보정까지 구현한다. 여러 선행 작업의 순서·대기·발동을 신뢰할 수 없는 경우는 검토된 어종별 보완을 사용하고, 없으면 ‘준비 확인 필요’로 남긴다. 모든 작업을 조합하는 범용 최적화 엔진은 만들지 않는다.
5. 추정 시간상 빠듯한 것과 조건상 불가능한 것은 구분한다. 일반 추정 범위가 회차를 넘는다고 확정 불가로 삭제하지 않는다. 반대로 중요한 선행 조건을 계산하지 못했는데 도전 가능으로 확정하지 않는다.

현재 `FishingForecast.Constrain`은 직감 수량·소요 시간·생미끼 준비를 입력받지 않으며 특정 인접 기간/원본 선행 순서를 사용한다. 이를 새로 시작하는 모든 복합 어종의 불가 판정기로 재사용하지 않는다. 대상 자체 구간을 출발점으로 유지하고, 기존 직감 결과와 충돌하는 복합 사례는 제한을 명시한다. 이 작업에서 기존 알림/일정표의 예측 의미를 조용히 변경하지 않는다.

### 4. 희소성과 다음 기회를 계산한다

[Fish Tracker](https://ff14fish.carbuncleplushy.com/)는 출현 중/임박한 어종과 전체 희귀도를 결합한 정렬을 제공한다. 고정본 [fish.js](https://github.com/icykoneko/ff14-fish-tracker-app/blob/d0e1ab5bba62c2b57356e690a73676cd4751b64d/js/app/fish.js#L197)의 uptime은 보유한 회차들의 총 출현 시간 비율이다. 우리 추천에서는 사용자 요구에 맞춰 **출현 횟수와 총 출현 시간 비율을 분리**한다. 짧지만 매우 자주 열리는 어종을 매우 드물게 열리는 어종과 동일시하지 않기 위해서다.

- 같은 기준 시각부터30일의 내장 예측 구간을 사용한다. 연속/인접 구간은 합쳐 한 기회로 센다. 기간 경계에 걸친 회차는 집계 정책과 분석 시작/끝을 기록한다.
- `횟수/분석 일수`로 빈도, `기간 안의 출현 시간 합/분석 시간`으로 시간 비율을 만든다. 간격과 비율은 현 예측 모델에 따른 추정이다. 자료에 없는 입질률/놓침률은 점수에 넣지 않는다.
- 희소성 내부값은 빈도70% + 시간 비율30%로 제안한다. 양쪽 모두 로그 변환/상한을 사용해 극단값의 지배를 막는다. 상시 조건은 희소성0이며 ‘30일에1회’로 계산하지 않는다.
- 직감 어종의 빈도는 기존 선행 조건을 반영한 **예측 기회 빈도**다. 지금 준비를 시작한 개인의 성공 빈도와 다르다. 중간 생미끼 제한/복잡한 직감이 미반영이면 ‘준비 조건 일부 미반영’과 계산 근거를 함께 표시한다.
- 다음 기회는 선택 회차 다음의 기회를 별도로 찾는다. 30일 안에서 못 찾으면 ‘분석 범위 내 다음 기회 없음’이지 무한 희귀도/출현 불가가 아니다. 계산 실패·자료 누락과 구별한다.
- ‘다음까지 오래 기다림’은 희소성과 일부 겹치므로 작은 가중치만 준다. 다음 기회가 가까운 희귀 어종도 존재하므로 둘을 같은 값으로 대체하지 않는다.

희소성 정규화의 구현 초깃값 예시(`clamp`는0~1):

```text
f = 분석 기간 내 기회 수 / 분석 일수
u = 분석 기간 내 조건 출현 시간 비율
R빈도 = clamp(log10(1 + 1 / max(f, 1/30)) / log10(31))
R시간 = clamp(-log10(max(u, 0.0001)) / 4)
R = 0.7 × R빈도 + 0.3 × R시간
```

빈 구간/불완전 분석에 이 식을 적용해 최대 희소성을 만들지 않는다. 장기 분석이 아직 준비되지 않았으면 임시로0점을 넣어 전체 순위를 확정하지 않고 ‘빈도 계산 중’으로 둔다. 상시·Unknown·범위 내 없음·계산 취소는 별도 상태다.

### 5. 설명 가능한 점수를 만든다

초기 제안은 다음과 같다. 전부0~1인 내부값이며 가중치는 실제 대표 후보를 보고 조정할 설계 상수다.

```text
추천 점수 = 준비 적합도 V × (40 × T + 30 × R + 20 × Q + 10 × N)
T: 지금 준비를 시작하기 적절한 정도
R: 출현 기회의 희소성
Q: 준비 후 이번 조건 구간을 활용할 여유
N: 이번 회차 뒤 다음 기회까지의 간격
```

- `T`: 지금부터 권장 준비 시작까지의 불필요한 대기가0이면1,20분이면0.5가 되는 완만한 감소를 초깃값으로 한다(`1/(1+대기분/20)`). 이미 준비를 시작할 때가 된 경우1이며 늦은 정도는 V/Q가 반영한다. 제한된 선행작이 지금 필요하면 대상 출현이 멀어도 대기로 세지 않는다.
- `Q`: 짧은/넉넉한 준비 추정 각각에서 남은 대상 조건 시간의 비율을 구해 평균한다. 분모는 해당 회차 전체 길이며 값은0~1로 제한한다. 원래90초뿐인 어종도90초를 전부 활용하면1이므로 짧은 출현 자체를 불리하게 만들지 않는다. 이 값은 직감 중 실제 낚시 시간/어획 횟수는 아니다. 상시 조건은 준비 가능 시1로 처리한다. 끝 시각 미확인은 상시로 바꾸지 않고 Q의 근거 부족으로 구분한다.
- `N`: 이번 회차 종료에서 다음 기회 시작까지의 간격을 로그 변환해 증가시키고72시간에 상한1로 제안한다. 상시는0,30일 내 다음 기회가 없는 경우는 범위 정보와 함께 상한 적용, 계산 실패는 Unknown이다.
- `V`: 넉넉한 추정으로도 조건 구간이 남으면1, 짧은 추정에서만 남으면0.7, 양쪽 모두 늦으면0.25를 초깃값으로 한다. 이는 가능성의 **등급 보정**이며 성공 확률이 아니다. 시간표상 필수 기회가 없는 회차는 점수 이전에 제외한다.
- 준비의 핵심 조건이 미확인이라 V/T/Q를 만들 수 없으면 단일 총점을 확정하지 않는다. 접힌 ‘계산 보류 후보’에서 어종·시간표·사유를 볼 수 있게 제안한다. 일부 필드 누락만으로 항상 보류하지 않으며, 계산 가능한 부분과 가정은 유지한다.
- 생미끼 단계/직감 여부/터주왕 등급/낮다고 알려진 입질률 자체에 별도 가감점을 주지 않는다. 터주왕이 항상 터주보다 상위인 고정 규칙도 두지 않는다.
- 동점은 권장 준비 시각 → 출현 시각 → 안정적인 ItemId 순으로 결정한다. 매초 재정렬하지 않으며 선택한 행의 식별자는 ItemId로 보존한다.

이 가중치는 ‘희귀해도 지금 준비해 볼 수 있어야 상위’라는 성격을 가진다. 사용자가 선택하기 위한 정렬일 뿐 어획 기대값 최대화가 아니다. 처음부터 여러 모드/가중치 슬라이더를 노출하지 않고 대표 어종에서 이유와 순위가 납득되는지 먼저 검토한다.

## 정보 제공 방식 제안

첫 화면은 **기존 메인의 ‘추천’ 탭**, 상위5종과 ‘더 보기’를 우선 제안한다. 현재 `MainWindow`의 목록·수집·일정표 등 탐색 탭과 같은 수준에 두며, 별도 설정 메뉴 깊숙이 넣지 않는다. 목록 옆 진입 버튼으로 별도 화면을 여는 대안도 가능하지만 배치는 아직 합의하지 않았다. 기존 일정표/타이머를 전면 개편하지 않는다.

- 상단: 대상 범위(기본 미수집 터주·터주왕), 탐색 기간(기본3시간), 새로고침. 지역/확장팩·즐겨찾기 제한은 필요할 때 펼치는 필터로 제안한다. 기존 메인 필터가 몰래 추천을 제한하지 않게 현재 범위를 명시한다.
- 후보마다: 어종·낚시터, 출현 중/몇 분 후와 조건 종료, 준비 시간 범위/지금 시작 권고, 핵심 추천 이유1~2개, 다음 기회. 같은 특성의 어종이 여러 개여도 순서대로 보여준다.
- 준비 요약: ‘직접 낚시’, ‘생미끼2단계’, ‘직감: 선행2종·합계6마리’, ‘시간 제한 선행 어종 있음’ 등 확인된 구조를 간결하게 표시한다. 여러 구간에 걸친 대기는 별도로 표시한다.
- 펼치기/툴팁: 첫 미끼와 생미끼 경로, 직감 선행별 수량·시간표, 준비 시간의 추정 근거, 빈도 분석 기간/회차 수, 누락/가정, 점수 구성. 기본 목록에98.7점 같은 숫자를 크게 내세우지 않는다.
- 클릭: 기존 어종 상세, 지도, 일정표 확인으로 연결한다. 추천을 클릭했다고 게임 이동/미끼 변경/알림 등록을 실행하지 않는다. 알림 설정은 명시적인 별도 조작이다.
- 일반적인 출현 시각/남은 시간은 현지 시각·현실 분/초, 원래 조건은 ET임을 표시한다. ‘준비20~40분’과 ‘출현까지30분’, ‘직감 지속2분’을 서로 다른 필드로 둔다.

설명용 가상 표시(실제 어종·예측·실측값이 아님):

```text
어종 A · 낚시터
출현까지58분 · 조건 출현 시간6분
준비 약40~60분 · 지금부터 준비 권장
생미끼1단계 / 직감 선행2종 / 선행 어종 시간 제한
추천 이유: 드문 출현 · 선행 준비를 시작할 시점
이번 회차 다음 기회: 약3일 후        [상세] [지도] [일정표]
```

‘준비40~60분’은 완료 약속이 아니다. 전체 안내는 한 번, 어종별 추정의 근거/주의는 펼쳐 보는 방식으로 정보량을 조절한다. 상위5개는 출현 유형별 할당 없이 같은 순위에서 선택한다. 후보가 부족하면 기준 밖 어종으로 숫자를 억지로 채우지 않는다.

### 출현 알림과의 관계

알림0~120분/새 설정 기본0분은 이미 구현됐으며 [현재 낚시터 알림의 로컬 채팅 형식](TROPHY-FISHING-PROPOSALS.md#현재-낚시터-출현-알림-논의-2026-10-24)은 합의됐지만 신규 낚시터 알림은 미구현이다.

- 추천 순위 변화는 채팅으로 자동 발송하지 않는다. 추천은 사용자가 열어 보는 선택 화면이다.
- 합의한 로컬 채팅 형식은 `{어종 링크} 출현 시작 - {상세 보기 링크} - 남은 시간`이다. 현재 낚시터 인식/중복 방지는 별도 알림 구현 작업에서 다룬다.
- 대상 자체 시간/날씨 출현, 선행작 가능 시점, 개인 직감 발동은 서로 다른 사건이다. 직감형 출현 메시지는 개인 준비 완료를 뜻하지 않으며 ‘직감 필요’를 명시하는 방안을 제안한다. 순수 직감형에 공통 출현 시작 사건을 임의로 만들지 않는다.
- 준비 시작 알림은 이 추천의 첫 범위에 추가하지 않는다. 자동 추천과 기존 사전 알림 시간을 연결하면 기존0분 기본값/120분 상한의 뜻이 바뀌므로 별도 결정이 필요하다.

## 구현 계획과 기존 코드 연결

### 1단계: 순위 계산과 이유를 검토할 수 있는 Core

- `Core/Recommendations`에 기능 전용 입력/결과, 준비 추정, 빈도 지표, 점수 계산을 둔다. Dalamud/Lumina/ImGui 의존성과 게임 관찰은 추가하지 않는다. 범용 작업 계획 프레임워크를 만들지 않는다.
- 입력: UTC 평가 시각, 탐색 기간, 읽기 전용 조건/날씨 자료, 대상 ItemId/수집 판정, 버전 있는 준비 추정 상수/어종 보완. 현재 도전 상태·실제 버프·직감 누적·보관 생미끼를 받지 않는다.
- 결과: 어종/회차 식별자, 자체 조건 구간, 준비 시작/시간 범위, 선행 기회, 다음 기회, 빈도 기간/값, 점수 구성, 이유 코드, 추정 근거/누락 코드. 표시 문장 대신 안정적인 코드와 형식 인자를 반환한다.
- `FishingAvailability`의 시간/날씨 열거를 같은 Core 안에서 재사용해 대상/선행 구간을 확보한다. `FishingForecast`는 기존 직감 기회·빈도 계산을 참고하는 경로로 유지한다. 기존 소비자의 예측 계약은 변경하지 않는다.
- 일반 직접/생미끼/상시 선행 직감부터 계산하고, 시간 제한 선행13종과 제한 생미끼를 보완한다. 복합 사례가 미검토면 보류 이유를 반환한다. 보완 없는 상태를 ‘전335종 준비 정확 지원’으로 보고하지 않는다.

### 2단계: Plugin의 비동기 후보 계산

- `FishCatalogView`의 자료/Forecast와 수집 snapshot을 관리 값으로 복사해 사용한다. `SpawnSchedule`의 취소·session/revision 검사·오래된 결과 폐기 패턴을 참고한다.
- 30일 빈도는 자료 버전·날씨 자료·계산 모드·분석 기준일별 캐시로 둔다. 지역/수집 필터가 바뀌었다고 모든 장기 예측을 다시 돌리지 않는다. 분석 기간을 표시하며 UTC 날짜 경계에 백그라운드 갱신한다.
- 현재 후보는 최대30초 또는 대상/선행 출현 경계·수집/필터 변경 시 갱신한다. 카운트다운만 화면에서 갱신한다. Draw에서 파일 읽기/전체 검색/장기 예측을 하지 않는다.
- 계산 시각은 주입 가능한 TimeProvider와 UTC를 사용한다. 새로고침 주기는 단조 시계로 관리하며 시스템 시각 점프 시 재계산한다. 화면 종료/플러그인 종료/캐릭터 전환에서 취소하고 이전 세션 결과를 표시하지 않는다.
- 첫 버전은 물고기의 눈 OFF의 일반 조건으로 제안하며 화면에 명시한다. 기존 공통 Fish Eyes ON을 조용히 따라가거나 ON인데 일반 추천인 것처럼 혼용하지 않는다. 지원 어종/선행 조건을 함께 바꾸는 추천 모드는 후속으로 다룬다.

### 3단계: 합의한 화면 연결과 어종 보완

- 추천 진입 위치와 목록 구조를 합의한 뒤 실제 UI를 구현한다. 기존 상세·지도·일정표의 사용자 클릭 경로를 연결한다.
- 한영 TextKey/.resx 전체 문장, 번역과 독립인 ImGui ID를 사용한다. 캐시에 번역된 문장을 저장하지 않는다.
- 새로운 저장 설정을 도입할 경우 기존 값/백업 계약과 캐릭터 수집 분리를 함께 확인한다. 첫 작업에서 사용자별 학습이나 원격 통계 수집을 추가하지 않는다.
- 검증한 복잡한 어종 보완을 순차 적용한다. 원본 조건 ID/수량/시간을 준비 추정값으로 덮어쓰지 않는다. 외부 자료 도입은 URL·고정 revision/해시·라이선스·가공 내역을 먼저 기록한다.

### 검토할 대표 사례와 완료 기준

아래는 구현 때 대조할 가설이며 이번에 테스트를 작성/실행한 결과가 아니다.

| 사례 | 기대하는 판단 |
|---|---|
| 출현1시간 뒤, 준비40~60분 | 지금 준비할 만한 후보로 들어온다. |
| 출현10분 뒤 종료5분 후, 준비40분 이상 | 단순 임박 이유로 상위에 오르지 않는다. |
| 이미 출현 중, 종료 직전, 선행 기회가 이미 끝남 | 새로 준비하는 이번 회차는 제외하며 다음 회차를 검토한다. |
| 직접 낚시, 아주 짧고 드문 조건 | 구간 전체를 활용할 수 있으면 짧다는 이유만으로 Q를 낮추지 않는다. |
| 홍룡 / 쿠얼 | 중간 생미끼의 제한을 확인하며 반복 전략을 단순1단계 준비 완료 보장으로 표현하지 않는다. |
| 칠채천주 | 서로 다른 선행 시간대를 동시에 겹쳐야 하는 조건으로 만들지 않는다. 보완 없으면 확인 필요다. |
| 스테타칸투스 | 선행 터주와 발동/보류 전략을 일반 직감5~15분으로 처리하지 않는다. |
| 항상 자체 조건이 열린 직감 어종 | 개인 직감 발동을 가짜 공통 출현 시작으로 만들지 않는다. |
| 같은 어종의 여러 회차 / 비슷한 특성의 상위 어종들 | 어종당1행을 유지하고 특성별 할당 없이 여러 후보를 제공한다. |
| 미확인 지속 시간·계산 한계·다음 기회 미발견 | 가정/누락/검색 범위를 보이며0분·무한 희귀도·성공 확률로 바꾸지 않는다. |

구현 검사는 사용자 지침에 따라 직접 빌드·리소스 검사이며 테스트 추가/실행은 명시 요청 때만 한다. 대표 순위와 정보가 납득되는지는 고정 UTC·고정 입력의 검토와 게임 대표 확인을 구별해 보고한다. 실제 준비 시간을 기록/학습하는 기능은 이번 범위가 아니다.
