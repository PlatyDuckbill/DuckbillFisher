# 미끼 준비 확인과 미끼 찾기

기록: 2026-10-18. [터주작 후보 1](TROPHY-FISHING-PROPOSALS.md)의 구체화다. 사용자 요청으로 준비 목록·수량 표시·미끼 찾기와 이번 배포까지 진행한다. 수량과v3 진단 복사는 대표 확인,0.3.0.0의 명시적 찾기/테두리 후보는 인게임 확인 대기다. Item 연결을 확인할 수 없으면 강조하지 않는다. [구현/조사/실행/다음 단계](validation/BAIT-PREPARATION.md). Release 게시 완료가 아니다.

## 사용자와 합의한 방향

- 준비 대상은 기본 ‘즐겨찾기’, 선택하면 ‘어종 목록 필터 결과 전체’다. 후자는 검색·수집·지역 등 현재 메인 조건을 통과한 전체 결과를 뜻하며 보이는 행만으로 제한하지 않는다. 준비 대상을 바꿔도 기존 목록/알림 설정은 바꾸지 않는다.
- 생미끼 연쇄도 첫 실제 미끼를 기준으로 모은다. 중간 물고기가 가방에 없다는 이유로 부족 처리하지 않는다. 미끼별 관련 목표를 묶고 대체 미끼의 의미는 보존한다.
- 소지 수량 조회 불가와 실제0개를 구분한다. 첫 범위는 일반 소지품이며 다른 수납 공간은 확인 후 결정한다. 수량만으로 시도에 충분하거나 개인 준비가 끝났다고 판정하지 않는다.
- 사용자가 ‘미끼 찾기’를 선택하고 게임 미끼 선택 UI를 열면 선택한 미끼 하나를 강조한다. 실제 미끼 선택은 사용자가 게임 UI에서 한다. 기존 아이템 링크 동작은 유지한다.
- 이번 범위에 `ChangeBait` 호출·키 입력·게임 명령·자동 선택을 넣지 않는다. 직접 변경은 별도 범위 결정과 KR 계약 검증이 필요하다.

## 화면 위치

즐겨찾기 전용 영역에 넣는 안에는 사용자가 범위 불일치를 지적했다. 이후 제안한 메인 어종 목록의 필터 근처 ‘미끼 준비’ 버튼과 준비 목록으로 구현한다. 새 독립 화면을 추가하지 않고 버튼에서 목록을 열며 대상은 내부에서 전환한다. 큰 화면 구조 변경이 필요하면 별도로 협의한다.

상세의 찾기는 사용자 배치 피드백 후 ‘낚시 조건’ 제목 오른쪽 버튼 하나로 합의했다. 미끼 경로 중간에 반복 버튼을 두지 않으며 대체 첫 미끼가 여러 개면 버튼을 누른 뒤 대상을 고른다. 첫 미끼의 기존 아이템 링크는 유지한다.

## 강조 종료 규칙

| 조건 | 동작 |
|---|---|
| 다른 미끼의 ‘찾기’ 선택 | 이전 요청을 새 미끼로 교체. 한 번에 하나만 유지 |
| 찾기 취소 | 요청과 강조를 즉시 해제 |
| 한 번 열린 미끼 UI를 닫거나 재생성 | 해제. 다음에 열어도 예전 강조를 자동 복구하지 않음 |
| 로그아웃·캐릭터 전환·플러그인 언로드 | 즉시 폐기. 캐릭터나 재로드 사이에 요청을 저장하지 않음 |
| 요청 후 실제60초 경과 | 대기/강조 모두 해제하는 기본값 제안. 단조 시계를 사용하고 절전 복귀도 만료 처리 |
| 현재 미끼가 찾는 미끼와 일치함을 검증된 관찰로 확인 | 선택 완료로 해제. 클릭/시간 경과만으로 변경됐다고 추정하지 않음 |
| 대상 UI 항목을 식별할 수 없거나 호환성 확인 실패 | 강조를 중단하고 이 기능에만 사유 표시 |

UI를 아직 열지 않은 최초 대기는 ‘UI 닫힘’으로 즉시 취소하지 않는다. 스크롤로 대상이 가려진 경우 보이지 않는 위치에 테두리를 그리지 않고, 대상 식별과 표시 범위가 확인될 때만 그린다. 어종 선택/마우스 오버만으로 강조 대상을 자동 교체하지 않는다.

‘미끼 찾기’ 버튼의 비활성 조건은 강조 종료와 별개다. 미끼 ID/근거 없음, 미로그인, 보유0개, 수량 조회 불가, 미지원 강조 환경에서는 비활성/사유 안내를 제안한다. 선택된 목표 하나가 미확인이어도 다른 목표의 준비 목록과 기존 기능을 막지 않는다.

## 다른 PC 호환성 경계

- 과거 동일15.0.3.7이라도 wasdcxz/dal4kr DLL 조합이 달라 차단됐던 원인은 [기존 조사](validation/NATIVE-RUNTIME-DAL4KR.md)를 따른다. 이미 등록된 세 프로필의 경계를 유지하며 본인 PC 파일만 기준으로 추가 제한하지 않는다.
- 소지 수량은 공개 `IGameInventory.GetInventoryItems`를 우선한다. 현재/최저 지원/친구 DLL의 공개 메서드 형태·GameInventoryItem 크기72·일반 가방 enum4개 존재를 디스크 메타데이터로 확인했다(`.cache/preparation-api.json`). 이것은 전체 구현/실기 호환성 확인이 아니다.
- 미끼 UI의 위치·행과 실제 Item ID의 연결은 별도 KR 조사가 필요하다. 화면 문자열·고정 행 번호·추측한 오프셋으로 대상을 정하지 않는다. 현재 `ChangeBait` 함수 이름 존재만으로 호출 가능을 확정하지 않는다.
- 강조는 플러그인이 테두리를 덧그리는 방식을 우선 조사한다. 게임 UI 노드 색/상태 쓰기와 미끼 변경 함수 호출을 추가하지 않는다. UI 수명 종료 때 참조를 폐기하며 게임 객체 주소를 요청에 보관하지 않는다.
- 새 강조의 UI 계약을 확인하지 못하면 해당 기능만 비활성화한다. 그 실패를 기존 NativeRuntimeCompatibility 판정에 덧붙여 도감/타이머까지 막지 않는다. 기존 지원 프로필 자체가 미지원인 경우에는 기존 가드를 계속 따른다.
- 지원 중인 세 참조 조합의 컴파일·관련 메타데이터 대조와 실제 PC 확인을 구분한다. 버전 숫자만 같다는 이유로 안전성을 보장하지 않으며, 테스트/인게임 확인을 하지 않고 완료했다고 기록하지 않는다.

## 남은 실제 확인

1. 준비 목록의 즐겨찾기/현재 필터 전체 전환과 첫 미끼/대체 후보를 대표 확인한다. 일반 소지품 수량은 사용자 일치 확인을 받았으며 모든 가방 이동/캐릭터 조합의 확인으로 확대하지 않는다.
2. KR 미끼 UI의 정확한 Item 연결·표시 범위·수명과 현재 미끼 선택 완료 후 해제를 실제 확인한다. 관찰v3의 UI 이름/그리드 확인과 Item 연결 확인은 구분한다.
3. 강조를 지원하지 못해도 준비 목록은 독립적으로 제공한다. 후보 인게임 확인 뒤 최저 지원 참조 Release ZIP을 따로 확인받고 게시한다.

직감용 선행 어종의 미끼까지 재귀적으로 합산하는 범위, 집사/초코보 가방, 충분 수량 임계값은 후속 결정이다. 기존 수집·필터 저장·프리셋·알림 정책은 유지한다.
