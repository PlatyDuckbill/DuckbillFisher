# UI/UX 전면 개편 요구사항과 재개 범위

갱신: 2026-10-16 · 조사/일부 구현 후 사용자 요청으로 일시 중단 · 화면 구조 협의 대기

## 출발점

- 정규 DLL 0.1.26.0의 필터·정렬 저장/기본값 복원/자동 해제 기본값/도감 안내는 사용자 `다 잘됨`으로 대표 확인을 받았다. 모든 경계/다른 캐릭터까지 검증한 것으로 확대하지 않는다.
- 다음 작업은 기존 화면과 사용 흐름 전반을 조사하고 아래 요구를 반영하는 UI/UX 개편이다. 사용자는 나열한 부분 외에도 에이전트 판단으로 상세 분석과 개선을 원한다.
- 현재 코드와 UX 자료를 조사하고 설정/탭 구조를 일부 수정했으나 사용자가 작업을 일시 중단했다. 구현은 미완성이며 빌드/리소스 검사/정규 DLL 교체는 실행하지 않았다. 정규 DLL은 0.1.26.0이다.

## 중단 시점과 재개 조건

- 대대적인 디자인 변경은 화면 구조와 주요 동선의 선택지·차이를 먼저 질문하고 사용자 답변을 받은 뒤 구현한다. 앞서 제안한 단일 창의 목록/즐겨찾기/설정 구성은 아직 승인된 설계가 아니다.
- 설계 후보: 현재 출현 중/출현 임박 어종을 보는 간략 뷰, 목록 클릭으로 별도 어종 상세 창 열기, 기존 창 안의 목록/상세 분할 유지. 사용자 예시이며 특정 방식을 구현하라는 확정 요청은 아니다.
- 재개 첫 단계는 위 후보를 포함한 구조 협의다. 단순한 ‘진행’ 요청만으로 미합의 구조를 확정하지 말고, 질문에 대한 답변을 받은 뒤 계속한다.
- 작업 트리에 FishPreferences.cs, Localization/UiText.cs, MainWindow.cs, Plugin.cs의 미완성 변경을 보존했다. 설정 언어/개발자 모드 저장 및 탭 구조 초안이며 아직 없는 UiWidgets/리소스/패널 메서드를 참조한다. 현재 소스는 빌드 가능한 완료본이 아니며 승인된 설계에 맞춰 조정해야 한다.
- 사용자는 이번 작업의 언로드 완료와 정규 DLL 교체를 이미 승인했다. 일시 중단은 구현 진행에 대한 것이며, 재개 시 기존 승인과 실제 로드 상태에 관한 새 안내를 함께 따른다.

## 조회한 UX 근거와 적용 후보

- [NN/g 사용성 원칙](https://www.nngroup.com/articles/ten-usability-heuristics/): 상태 가시성, 일관성, 불필요한 정보 축소를 확인했다. 도감 안내 강조/중복 문구 축소/공통 행 표현의 근거로 사용한다.
- [Microsoft Fluent 툴팁](https://fluent2.microsoft.design/components/web/react/core/tooltip/usage): 툴팁은 보조 정보에 사용하며 시스템 피드백을 숨기지 않는다. 아이콘 이름과 조건 설명은 툴팁, 필수 상태와 오류는 화면에 남기는 방향이다.
- [W3C 색상 사용](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): 상태를 색상만으로 전달하지 않는다. 열린 창/도감 안내에 짧은 상태 표현과 아이콘을 함께 제공하는 근거다. ImGui 접근성 인증을 의미하지 않는다.
- [FFXIV Fish Tracker](https://ff14fish.carbuncleplushy.com/): 실제 페이지의 상시 어종 숨김, 출현 정렬, 미끼와 낚아채기 표시, 위치 지도 접근에 관한 안내를 확인했다. 빠른 목록 탐색의 비교 사례이며 해당 사이트의 동작/코드를 복제하거나 예측 조사에 사용하지 않는다.
- 위 자료는 2026-10-16 조회했다. 외부 코드/에셋 도입은 없으며 구체적인 화면 구조는 사용자 협의 후 확정한다.

## 사용자 요구

1. 불필요한 안내/중복 제목을 줄인다. 예를 들어 미끼 경로에서 `미끼 → 생미끼`라는 설명 제목을 반복하지 않는다.
2. 목록의 미끼/날씨 등은 검증된 게임 아이콘을 우선하고 마우스를 올리면 이름과 조건을 안내한다. 아이콘만으로 상태를 알 수 없는 경우와 데이터 없음/로딩 실패는 대체 표시를 설계한다.
3. 도감 연동 권장 안내는 현재처럼 묻히지 않도록 주목도를 높인다. 현재 세션의 전체 도감 대조가 필요하다는 사실을 쉽게 인지하고 실제 게임에서 해야 할 동작을 알 수 있어야 한다.
4. 어종 목록과 즐겨찾기 관리를 주 화면으로 만든다. 개발자 진단 탭이 주요 동선과 경쟁하지 않게 한다.
5. 필터·정렬 기본값 복원은 정렬이 보이는 상단에서 바로 접근 가능하게 한다. 복원을 접힌 영역 안에 둘 경우 해당 정렬도 같은 영역에 속해야 한다.
6. 상세 진단/수첩 연동 확인/관찰 로그 등은 개발자 옵션을 켰을 때 노출한다. 일반 사용자에게 개발 과정의 UI를 기본으로 보여주지 않는다.
7. 별도 설정 탭을 두어 공통 설정의 위치와 책임을 정리한다.
8. 수집으로 지정/미수집으로 지정을 하나의 컨트롤로 통합하고 수동 지정 해제도 간결하게 처리한다. 자동이 기본이므로 자동 표시는 반복하지 않고 수동으로 바꾼 경우만 표시한다. 구체적인 토글/복귀 상호작용은 Unknown 구분과 오조작 가능성을 검토하여 정한다.
9. 즐겨찾기는 별, 시간은 시계 등 텍스트를 줄일 수 있는 아이콘을 활용한다. 시작까지/종료까지의 의미는 툴팁과 상태 구분으로 유지한다.
10. 어종 상세의 산만한 버튼 배치를 정리한다. 제목/상태/주요 동작과 낚시터/예측/미끼/추가 조건을 일관된 정렬과 간격으로 묶는다.
11. 권위 있는 UI/UX 원칙과 다른 실제 사례를 조사하고, 출처와 적용 이유를 기록하여 이 목록 밖의 문제도 개선한다.

## 조사와 설계에서 다룰 항목

- 현재 MainWindow/목록/공통 행/즐겨찾기/상세/설정 흐름과 고정 높이·스크롤·창 최소 크기·번역 길이의 제약부터 확인한다. 이미 공유한 row renderer와 캐시 경계를 활용한다.
- 조사한 자료와 적용 후보는 위 근거 구역을 따른다. 추가 조사와 게임 화면 확인은 필요에 따라 진행하며 웹 자료 조회를 인게임 UI 검증으로 표현하지 않는다.
- 예쁜 화면뿐 아니라 중요한 상태의 발견, 빠른 탐색, 일관된 행동, 오조작 복구, 정보 밀도, 툴팁 없이도 필요한 핵심 정보가 전달되는지를 평가한다. 웹 접근성 원칙은 ImGui/게임 환경에 맞게 적용하며 인증이나 완전한 준수를 주장하지 않는다.
- 먼저 문제/개선 근거/화면 구조/주요 상호작용/작업 순서를 정리하고 사용자에게 선택지를 질문한다. 답변 후 코드/API 제약과 조사 결과를 반영하여 구현한다.
- 예상 기본 구조는 어종 목록/즐겨찾기 관리/설정과 개발자 옵션으로 노출하는 진단이다. 구체적인 탭/패널 구성은 아직 최종 확정이 아니다.
- 도감 미확인 안내는 작은 색상 차이만 사용하지 않고 아이콘과 짧은 동작 안내를 함께 검토한다. 완료 후에는 목록 공간을 불필요하게 점유하지 않게 한다.
- 아이콘을 쓰더라도 직전/현재 날씨, AND/OR, 미끼 단계/수량, 시작/종료 시간과 Unknown의 의미를 잃지 않는다. 이름/기능은 툴팁으로 제공하고 실제 아이템 링크/지도 동작을 유지한다.
- 수동 수집 UI는 자동 관찰 Caught/Uncaught/Unknown과 수동 override를 합쳐 없애지 않는다. Unknown을 단순 체크 해제로 미수집 판정하는 오류를 피하고 자동 상태로 복귀하는 동작을 명확하게 한다.
- 개발자 옵션은 진단 UI 노출을 제어하며 정상 자동 수집/예측/알림의 동작 조건으로 만들지 않는다. 개발자 옵션 기본은 꺼짐을 검토한다.

## 계속 지킬 구현 경계

- 수집 판정/수동 우선순위/세션 격리/등록 이벤트 계약과 자동 즐겨찾기 해제 정책, 기존 예측/알림 예약·중복 방지를 유지한다. 자동 어획/시전/이동/명령·서버 채팅 전송은 구현하지 않는다.
- Toast는 사용자 요청으로 제거한 기능이므로 재도입하거나 재현 조사를 하지 않는다. Teamcraft/바다구렁이 불일치와 입질 초 수 통계는 계속 보류한다.
- UI 언어는 한영 리소스/고정 ID, 게임 이름·아이콘은 확인된 클라이언트 데이터를 따른다. 게임 접근은 기존 Plugin 어댑터 경계를 지킨다. 런타임 HTTP를 추가하지 않는다.
- 테스트는 명시 요청이 없으므로 추가/실행하지 않는다. 빌드와 리소스 검사, 문서 갱신/논리적 커밋을 수행하고 정규 DLL 교체 전 새 언로드 확인을 받는다.
- 사용자 `tmp_note.md`는 읽기/수정/스테이징하지 않는다. 외부 예제 코드를 도입하면 원본 revision/라이선스/변경 내역을 기록한다.

## 개편 후 대표 확인 항목

- 기본 동선에서 목록/즐겨찾기/설정을 쉽게 찾고 개발자 옵션을 껐을 때 진단 UI가 숨겨지는지 확인한다.
- 도감 조회 전 강조 안내와 완료 후 해제, 저장된 필터 복원과 상단 기본값 복원, 선택/스크롤/언어 변경 상태 유지를 확인한다.
- 아이콘 툴팁/아이템·지도 링크, 상세 정렬, 자동 기본 표시와 수동 전환/해제를 확인한다. 작은 창/큰 창/한영 문자열/아이콘 미확인 상태도 확인 범위를 구분한다.
- 실제 게임 결과를 받기 전에는 시각적 개선이나 기능 경계 검증이 끝난 것으로 기록하지 않는다.
