# 범용 실행 계약 재설계안

작성: 2026-11-04 · 상태: **제안(미승인)**. [글로벌·공식 저장소 계획](../product/GLOBAL-AND-OFFICIAL-REPO.md)의 P1 설계다. 근거는 [호환성 조사](../verification/native/GLOBAL-COMPAT.md)를 따른다. 승인 전에는 코드, [ARCHITECTURE](ARCHITECTURE.md), AGENTS.md를 바꾸지 않는다. 구현이 끝나면 확정된 내용은 ARCHITECTURE로 옮기고, 이 문서는 설계 결정 기록으로 남긴다.

## 목표와 비목표

- **목표**
  - KR(wasdcxz·dal4kr)과 글로벌 Dalamud에서 같은 빌드가 동작한다.
  - Dalamud 재빌드·재배포에 플러그인 수정이 필요 없다.
  - 게임 패치나 구조 변화가 생기면 해당 기능만 Unknown으로 끄고 다른 기능과 수동 상태는 유지한다.
- **비목표**
  - 자동 조작, 서버 송신, 런타임 HTTP, 원격 허용 목록 갱신은 도입하지 않는다(기존 경계 유지).
  - 무효 포인터를 try/catch로 안전하게 만든다고 가정하지 않는다(기존 원칙 유지).
  - 새 기능 추가나 UI 구조 변경은 하지 않는다.

## 현재 구조와 문제

- `NativeRuntimeCompatibility.Inspect()`는 프로세스 이름, 게임 빌드(`2026.10.06`) 일치, Dalamud 버전 일치, 세 DLL의 MVID·SHA256 조합 일치를 **한 번에** 판정한다. 결과 `IsCompatible` 하나가 다음 기능을 모두 켜고 끈다.
  - 수집 비트, 도감 스냅샷, 도감 열기
  - 낚시 상태, 타이머, 기록
  - 미끼 화면, 미끼 수량, 버프 표시
  - 선택 효과음
- 그 결과 생기는 문제는 세 가지다.
  - 재빌드마다 KR·글로벌 모두 전체 기능이 멈춘다. 지금까지 차단은 4회였고, 사용하는 구조가 실제로 바뀐 적은 없었다.
  - 공개 API만 쓰는 미끼 수량과 버프까지 함께 멈춘다.
  - 실패 사유가 "DLL 불일치" 하나로 뭉쳐서, 어느 기능의 무엇이 문제인지 알 수 없다.
- 지역 전용 가정 네 가지가 따로 있다.
  - `FishingLogContracts`의 KR 문장 지문(글로벌 0/28 일치)
  - 미끼 화면의 하드코딩 오프셋 `0xD2690`
  - 수집 비트 상한 상수 `1522`
  - KR 전용 안내 문구

## 새 구조

### 1. 전역 가드 제거, 환경은 보고 전용

- `NativeRuntimeProfiles`(해시 목록)와 게임 빌드·Dalamud 버전 일치 검사를 삭제한다.
- 로드 가능 여부는 Dalamud의 API 레벨 판정에 맡긴다. 게임 버전과 배포판 정합성은 런처·Dalamud(`SupportedGameVer`)가 담당한다. 이는 다른 공식 플러그인과 같은 신뢰 수준이다.
- 새 `NativeEnvironment`는 다음 값을 **진단 보고에만** 기록하고, 어떤 기능도 막지 않는다.
  - 게임 빌드, 클라이언트 언어
  - Dalamud·ClientStructs 버전과 MVID
- 판정에 쓰지 않으므로 DLL 해시 계산도 하지 않는다.

### 2. 기능별 실행 계약

기능마다 독립된 상태(`Available` / `Unavailable(사유 코드)`)를 둔다. 각 검사는 기존 스레드·수명·캐릭터 일치 검사 뒤에 수행하며, 하나가 실패해도 다른 기능은 영향을 받지 않는다.

| 기능 | 계약 검사 (실행 중) | 변경 |
|---|---|---|
| 수집 비트 | `PlayerState` 정적 주소 확인, IsLoaded·ContentId 일치, **비트 수를 로드된 ClientStructs에서 읽음** | 상한 `1522` 상수 제거 |
| 도감 스냅샷 | 기존 Mode·Entries 정렬·IsCaught와 비트 교차 일치(`BitMismatch`) | 유지. 교차 검증이 의미 검사 역할을 함 |
| 도감 열기 | `AgentFishGuide.OpenForItemId` 함수 포인터 해석 여부 | 전역 가드만 제거 |
| 낚시 상태 | `EventFramework`·`FishingEventHandler` 주소, Phase 0~12, 보관 생미끼 선택 −1~2 | 유지 |
| 낚시 로그 | **매개변수-시트 결합 계약**(아래 3절) | KR 문장 지문 대체 |
| 미끼 화면 | **`AtkStage.Instance()`**, 기존 노드 수·AtkValues·툴팁 범위 형태 검사 | 오프셋 `0xD2690` 제거 |
| 선택 효과음 | `UIGlobals.PlaySoundEffect` 함수 포인터 해석 여부 | 전역 가드만 제거 |
| 미끼 수량·버프 | 공개 API(`IGameInventory`·`StatusList`) 결과 검증 | 전역 가드 연결 제거 |

- **안전 근거**
  - 주소와 함수는 ClientStructs 시그니처를 Dalamud가 실행 중인 게임에서 해석한 결과만 쓴다. 해석에 실패하면 null이 되고, null은 사용 전에 거부한다.
  - 구조 배치는 실행 중인 배포판이 제공한 ClientStructs를 따른다. 그 위에 값 범위, 형태, 교차 일치 검사를 더한다.
- **남는 위험**
  - 배포판이 게임과 맞지 않는 ClientStructs를 공급하면 잘못된 값을 읽을 수 있다. 같은 배포판의 모든 플러그인이 함께 겪는 위험이며, 범위·형태 검사로 대부분 Unknown이 된다.
  - 그래도 오작동 가능성을 0으로 만들 수는 없다. 이 위험은 결정 사항으로 받는다.

### 3. 낚시 로그: 매개변수-시트 결합 계약

- ID별로 **기대 결합 집합**을 둔다. 예: 1110 `{PlaceName:lnum1}`, 3512 `{Item:lnum1}`(수치 lnum2·lnum3), 5557 `{Item:lnum1, Item:lnum2}`. 값은 KR과 글로벌 5개 언어 대조에서 확인한 것만 사용한다.
- 실행 중 현재 클라이언트 언어의 LogMessage 행을 읽어 `sheet`와 언어별 명사 매크로(`ennoun`/`denoun`/`frnoun` 등)의 `(시트, …, lnumN)` 결합을 추출한다. 대조에서 확인되지 않은 매크로 이름은 결합으로 취급하지 않는다.
- 판정 규칙
  - 허용: 행이 존재하고, 발견한 결합이 기대 집합의 부분집합이며, 같은 `lnumN`이 다른 시트에 결합되지 않을 때.
  - 거부: 행이 없거나 결합이 충돌하면 그 ID만 거부한다. 기존처럼 거부된 ID는 무시하고, 판정을 추측하지 않는다.
- 문장 수정이나 언어 차이로는 차단되지 않는다.
- 결합이 없는 13개 ID(1111·1112·1113·1116·1117·1119·1120·1127·1129·3511·3527·5559·5584)는 행 존재만 확인한다. 문장으로 의미 변경을 감지할 수 없다. 이 ID들의 기존 판정 순서(본인 여부, 시전 상태, 같은 시전 안의 상관)는 바꾸지 않는다.
- 진단은 `Contracts=유효/전체`를 유지하고, 거부 ID와 사유(`Missing`/`Conflict`)를 추가한다.

### 4. 지역 중립 안내

- 전역 차단 문구 `NativeFeaturesBlocked`, `NativeDllMismatch`, `NativeGameMismatch`, `NativeRuntimeUnsupported`를 없앤다.
- 대신 해당 기능 위치에 "이 기능을 현재 게임 상태에서 읽을 수 없음 (사유 코드)"을 표시한다. 문구는 기존 TextKey·한영 리소스 규칙을 따른다.
- 화면 구조는 바꾸지 않는다. 기존 경고 표시 자리의 문구와 조건만 바꾼다.

### 5. 진단 형식

- 다음 행을 제거한다.
  - `NativeRuntime=…; NativeProfile=…; NativeStatus=…; MismatchedModules=…`
  - `Game build: … native compatibility: …`
- 대신 `NativeEnvironment` 행(빌드·언어·버전)과 기능별 상태 행을 둔다.
- 해당 보고서의 형식 버전을 올리고 변경 근거를 검증 기록에 남긴다.

### 6. 빌드와 개발 검사

- KR 참조와 글로벌 참조 **양쪽 빌드 통과**를 일반 검사로 둔다. 공식 CI는 글로벌 최신 참조로 빌드한다. 한쪽에만 있는 멤버를 쓰면 다른 쪽에서 실패하므로 이를 미리 잡는다.
- `compare-native-runtime.ps1`은 허용 판단 도구가 아니라 **사용 멤버 존재·시그니처 대조 도구**로 바꾼다. 쓰지 않는 메서드의 IL 차이는 경고로만 보고한다.
- 로그 결합 대조 도구(임시 `.cache/global-compat-2026-11-04/logaudit/`)는 `tools/`의 정식 개발 도구로 옮길지 구현 단계에서 정한다.

## 구현 순서 (승인 후, 커밋 단위)

1. 로그 결합 계약으로 교체한다. KR 동작은 같아야 한다.
2. `AtkStage.Instance()`로 바꾸고, 수집 비트 수를 실행 중 값으로 읽는다.
3. 전역 가드를 제거하고 기능별 상태, 안내 문구, 진단 형식을 바꾼다.
4. 방침 문서를 갱신한다: AGENTS.md, ARCHITECTURE, 스킬, 계획 진행도.

각 단계에서 KR·글로벌 참조 빌드와 리소스 검사를 한다. 테스트 추가와 실행은 별도 요청이 있을 때만 한다. 인게임 확인은 사용자가 KR·글로벌에서 한다(계획 P5).
