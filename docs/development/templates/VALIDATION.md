# 검증 기록 템플릿

기존 주제 기록에 짧게 추가하는 것을 우선한다. 새 KR 계약·독립 기능·배포처럼 별도 참조할 근거가 있을 때만 새 파일을 만들고 [색인](../../verification/README.md)에 연결한다. 해당하지 않는 항목은 생략한다.

## 범위와 근거

- 작업/날짜/버전/소스 커밋:
- 변경한 동작과 유지한 계약:
- 근거: 소스 URL/revision·실제 KR 빌드·배포판/DLL 식별·자료 revision 중 관련 항목.
- 판단하지 못한 것과 실패 동작:

## 실행과 확인

| 구분 | 실제 수행한 내용 | 결과/한계 |
|---|---|---|
| 빌드/자료/문서 검사 | 명령·대상·종료 결과 | 경고/오류 또는 검사 범위 |
| 테스트 | 명시 요청이 있을 때만 기록 | 미실행이면 미실행 |
| 인게임 | 재현·기대·사용자의 실제 결과 | 대표 표본/미확인 조합 구분 |
| 배포 | 요청 범위·ZIP SHA256·태그/Release/index·익명 URL | 설치/업데이트 실기와 구분 |

실제 로그의 필요한 구역만 익명화하여 남긴다. 캐릭터 식별자·주소·자격 증명·원문 전체를 복제하지 않는다. 빌드 성공을 인게임 통과로 바꾸지 않는다.

## 남은 확인

현재 판정과 필요한 다음 확인만 쓴다. 사용자 대표 확인을 받으면 범위/날짜를 추가하고, 현재 전체 상태는 STATUS에 링크한다. 후속 작업으로 이 문서를 읽을 때 과거의 ‘다음 확인’을 새 실행 지시로 해석하지 않는다.
